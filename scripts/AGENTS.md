# 目录用途

`scripts/` 存放仓库级开发、构建、生成、调试和轻量测试入口脚本。

按职责分组：`launch/` 存放开发和目标生命周期入口，`install/` 存放安装后处理入口，`release/` 存放发布打包入口；协议、fixture、诊断和轻量测试脚本保留在根目录或对应的专用目录。

```text
scripts/
├── git/                     Git worktree与索引隔离检查
│   └── assert_isolated_index_commit.mjs
├── launch/                  开发服务和目标生命周期
│   ├── dev.mjs              开发栈入口，负责安装调试模板
│   └── debug-fixtures/      仅供开发启动器使用的只读调试模板
├── install/                 安装后处理
├── release/                 发布打包
└── generate_*.{py,mjs}      协议、类型和测试数据生成入口
```

目录先按职责归属，再按该职责内的用途展开。仅被一个入口使用的模板放在该入口所属目录下；多个入口真正共用时才提升到共同上层，并迁移全部调用方。不要为了便于查找在不同层级保留同一模板的副本；生成结果写入各自的输出目录。

# 可修改内容

- 可以新增或维护由 `package.json`、测试命令或开发流程调用的脚本。
- 可以放置 ESM `.mjs` 脚本，用于编排已有工具、生成类型或执行无 DOM 的状态测试。

# 不可修改内容

- 不在这里实现后端业务逻辑、前端运行时代码或持久化核心规则。
- 不放需要长期维护的大型测试数据、构建产物或运行时缓存。
- 不直接引用仅在源码仓库存在的资源作为最终安装后的运行时路径。

# 规范

- JavaScript 脚本使用 ESM，通过 `import`/`export` 或顶层脚本逻辑组织，不使用 CommonJS。
- 脚本应从仓库根目录或显式传入路径解析文件，不通过脚本文件位置向上猜测项目根目录。
- 长命令优先收敛到脚本中，脚本失败时直接抛出明确错误。
- 开发启动和安装脚本统一尊重 `BOXTEAM_HOME`；用户配置通过 `python -m configs.boxteam` 生成到 `${BOXTEAM_HOME:-~/.boxteams}/config/`。
- 默认工作区与开发专用资源的安装属于安装器或开发启动脚本职责，不得转嫁给工作区后端初始化。
- 触发全局存储迁移前必须先停止可能写入旧目录的相关进程，避免迁移期间产生分叉状态。
- 保留“模板示例；在整理 `AGENTS.md` 时请保留此行。”这一行。
