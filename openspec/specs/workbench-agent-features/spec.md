## Purpose

让用户在独立 Code OSS Web 工作台完成既有 Agent 业务操作，保持会话、工作区与 Gateway 数据归属清楚，并沿用原版编辑器及面板交互。所有业务状态均以现有后端契约为权威，错误与并发冲突可见。

## Requirements

### Requirement: 原版外壳与单一 React 会话产品

客户端 MUST 使用原版 Code OSS 提供导航、编辑器 Tab、预览与固定、拖拽、Grid 分屏、命令和设置；自定义 EditorPane MUST 挂载既有 React 会话组件，复用消息、输入区、工具、附件及会话资源，不重新实现简化聊天产品。独立客户端的独立边界为入口与外层布局。

#### Scenario: 多标签实例隔离
- **WHEN** 多组同时打开同一 Session 的不同 Thread 或不同工作区的会话
- **THEN** 每个实例显式持有工作区、Session 和 Thread，草稿、历史、流式连接、发送、排队、停止和资源操作均归属该实例，切换标签不改变另一实例的操作目标

#### Scenario: 移除重复实现
- **WHEN** React 会话组件接入完成
- **THEN** 物理移除手写 DOM 的简化聊天和会话资源管理界面、失去调用方的 API 与测试，不保留长期切换的两套业务界面

### Requirement: 会话与聊天业务

客户端 SHALL 提供会话创建、重命名、删除和 Thread 导航，以及消息发送、执行状态和停止控制，保持各编辑器精确 owner。

#### Scenario: 多会话操作
- **WHEN** 用户同时打开多个 Thread 并管理其中一个会话或运行
- **THEN** 操作只影响指定业务 owner，关闭标签不删除后端资源

### Requirement: Goal 与持久任务管理

客户端 SHALL 提供 Goal 新建开始、编辑、暂停、继续、重新开始和删除，展示预算、耗时和 Token 用量；关联任务提供可用控制和运行记录，工作区全部任务由底部自动化管理。

#### Scenario: Goal 生命周期
- **WHEN** 用户创建、暂停、继续或删除 Goal
- **THEN** 后端状态与完整 UI 镜像一致，说明其属于会话主线程，暂停或删除不会伪装成中断当前轮次

#### Scenario: 操作失败
- **WHEN** Goal 或任务操作失败或并发冲突
- **THEN** 显示详细错误并重读权威状态，保留尚未成功保存的输入

### Requirement: 原生文件编辑及更改

客户端 SHALL 用原生编辑器提供后端工作区文件读取、编辑保存及更改审阅，并保留 revision 并发保护。

#### Scenario: 保存冲突
- **WHEN** 另一个 owner 修改了已打开文件，用户保存旧版本
- **THEN** 拒绝静默覆盖，保留本地未保存文本，明确呈现冲突和重新读取入口

### Requirement: 工作区与运行面板

客户端 SHALL 提供工作区终端、输出、端口、自动化与 MCP 控制，并将精确 Thread 关联资源展示于对应编辑器内；Gateway 控制面独立于会话。

#### Scenario: 切换工作区
- **WHEN** 用户切换工作区或打开不同工作区的 Thread
- **THEN** 操作发往明确工作区，工作区面板及会话资源不发生归属串用

### Requirement: 验收及原版行为

客户端 MUST 保留原版标签、分屏、命令、设置和恢复行为，逐链路完成真实 Gateway 浏览器验收及类型检查和构建。

#### Scenario: 业务迁移完整性
- **WHEN** 声明功能迁移完成
- **THEN** 既有核心入口均有对应操作和真实后端验收证据，摘要、TODO 或局部绿测不能代替完整迁移

#### Scenario: 正式回归与唯一入口
- **WHEN** 完成旧工作台迁移
- **THEN** 正式完整页面测试、开发和发布入口均使用同一 Workbench，覆盖聊天、工具循环、多 Thread 分屏隔离、文件、任务和工作区行为，并物理删除失去调用方的旧外壳；使用模型回放的测试仍标识为 Integration
