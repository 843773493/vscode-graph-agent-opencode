# harness-agent-configuration-ui Specification

## Purpose

让用户无需依赖会话输入框或手工记忆配置结构，即可管理模型 Provider、Agent、工具、Skill 和指令来源；所有更改继续进入所属目标的正式配置或业务 owner，清楚展示继承、生效与错误，保护既有执行和秘密输入边界。

## Requirements

### Requirement: 业务设置必须共用正式配置来源与保存语义

管理界面 SHALL 复用所属目标正式来源、schema、预检、并发基线、保存及生效状态。表单与 JSONC 表达同一草稿，展示选定节点本地定义、实际唯一父链和有效结果；恢复继承只删除该节点定义。保存失败／冲突保留输入并重读原 owner，成功不等于运行已生效。未接入实际运行链的字段 MUST 明确标未支持，不提供伪生效普通控件。

Provider／Model／Agent 表单 SHALL 直接编辑原 `(gateway_id, workspace_id 或 Gateway 范围, source_key)` JSONC 文本模型，以稳定实体键和节点位置定位。更改 config_ref、extends 和字段共用此草稿及撤销，不建独立持久草稿、保存队列或自动重基。共享来源从不同工作区打开保持各自上下文、基线和回执，不按文件路径合并草稿。定义读取不要求凭据展开、登录或模型客户端创建成功，定义可读和运行可用分别展示。

业务来源 URI SHALL 沿原机制禁用自动保存，仅显式预检／确认／CAS 后写入；客户端原生 Settings 按原版行为，不全局改变 auto-save。已有即时业务开关沿实际 owner 提交，不冒充来源草稿。全局管理首次默认本地，已有对象入口绑定原精确 owner，不随焦点／导航改投。

#### Scenario: 保存成功但需要重启
- **WHEN** 候选文件已保存，owner 报 pending 或应用失败
- **THEN** 分别展示已保存来源、当前 active 和待应用原因，只提供原 owner 支持动作，不伪报即时生效

#### Scenario: 表单切换 JSONC 与恢复继承
- **WHEN** 表单编辑后切 JSONC，随后删除该节点某个覆盖
- **THEN** 保留同一草稿和撤销，提交后显示真实父值，不写回整个 effective 对象

#### Scenario: 原生设置与业务来源保存并存
- **WHEN** 修改原生 Settings，再修改未保存的业务节点
- **THEN** 原生设置保持原行为，业务草稿不发写请求，显式保存才进入所属 writer 的 CAS

#### Scenario: 共享文件的两个工作区草稿
- **WHEN** A、B 打开相同来源，A 保存而 B 持有旧基线
- **THEN** B 保留草稿并收到原 CAS 冲突，不套 A 回执或自动覆盖

#### Scenario: 稳定键对象的局部覆盖与移除
- **WHEN** 新建稳定键模型、选择本地覆盖节点或移除本地目录定义
- **THEN** 不遮蔽其他稳定键；移除说明祖先同 ID 可能重新可见，彻底移除时定位真实定义来源，不加 tombstone 或级联修改其他层

#### Scenario: 普通模型编辑与共享定义编辑
- **WHEN** 两个模型指向同一 profile，用户在其中一个的普通详情修改参数
- **THEN** 在同一 JSONC 草稿创建该对象私有子节点并改 config_ref，一次 CAS 保存；只有明确选择编辑共享定义才改原节点，并展示已知影响范围

### Requirement: Provider 管理必须独立于会话并保护引用关系

产品 SHALL 在原生 Settings 的模型管理入口提供 Provider 分组、旗下模型列表、详情、新建、编辑、复制和移除本层定义。Provider 与 Model 的对象键为稳定身份，创建后不提供 ID 重命名；可选显示名称可编辑，服务端模型名称单独展示。共享连接、协议、凭据及请求参数在 Provider 默认配置中管理，Model 显示继承来源并只写明确覆盖，不复制整组列表。

默认配置 SHALL 仅要求现有协议必需参数，不自动推导输出限制、采样或 reasoning。创建时 SHALL 提供当前支持协议的最小模板，生成合法稳定键并允许首次提交前修改，显示名可选；高级请求头／代理／参数按需展开。列表显示本地配置、active／pending 与尚未验证状态；连接编辑可按本规范自动获取目录，但新增／编辑不自动发推理请求，真实调用须显式测试。

删除校验 SHALL 沿原 owner 限定在完整 candidate 的当前 Agent primary／fallback ModelReference 及该工作区的既有 SessionDefaults。共享来源的影响只报告已观察消费者，不承诺全部未知工作区无引用。MUST NOT 扫描全部 Session／Thread、Job、Trace 或检查点、另建引用索引或跨 owner 事务。历史引用保留，后续访问已删除定义时明确报不可用并要求选择，不静默改绑、级联修改或回退另一模型；运行中快照保持原合同。

模型密钥引用 SHALL 按稳定 Provider／Model 键与正式引用保持，不按数组索引或同名对象恢复；移除或重排展示项不能借用另一对象的凭据。原只为 Provider 数组中字面密钥占位服务的恢复特例 SHALL 随全部调用方迁移后删除，其他实体既有秘密合同保持。

#### Scenario: 创建最小模型服务并添加模型
- **WHEN** 用户尚无会话，从本地设置填写服务连接、凭据来源及协议，添加两个模型并保存
- **THEN** 两个模型共享默认配置并有不同稳定键，不要求先创建会话或自行添加 max_tokens／max_output_tokens；连接字段完成编辑时可获取一次目录，保存本身不触发发现或推理

#### Scenario: 删除被引用模型
- **WHEN** 用户删除仍被 Agent primary 或 fallback 使用的模型，或包含该模型的 Provider
- **THEN** 显示原 owner 提供的具体引用冲突，保留有效配置，不自动选择替代项或改写运行 Job

#### Scenario: 默认值引用与历史引用分别处理
- **WHEN** 模型被当前工作区会话默认值引用，或仅被某个历史会话引用
- **THEN** 前者由原 owner 拒绝删除；仅历史引用不要求扫描或重写历史，具体访问不存在定义时要求显式选择

#### Scenario: 显示顺序和名称改变不改凭据
- **WHEN** 用户改变列表排序、修改显示名，或移除另一未引用模型
- **THEN** 剩余模型的稳定键、凭据引用及参数保持，不按位置替换密钥或要求全部重新输入

### Requirement: 秘密与登录必须归属目标且不进入普通展示存储

模型 API Key SHALL 统一由所属 Gateway 的现有密钥库持有；Provider／Model 只保存正式引用，或者已有目标 Workspace 环境变量引用。普通 Workspace 配置 writer MUST NOT 再保存模型密钥字面量。插件、MCP、连接凭据及 OAuth 仍沿各自原 owner 的秘密输入／引用／登录合同处理，不能因共用 UI 就互换格式或移交归属。

界面 SHALL 显示是否配置、来源、所属目标及真实错误，不回显已存值；秘密不得进入浏览器持久草稿、普通日志、诊断导出或跨目标复制。Provider／Model 的凭据选择 SHALL 提供已有密钥、新建密钥和环境引用；Model 可恢复继承 Provider 引用。新建与更新只在短暂密码控件中输入，值通过原受保护写入口提交 vault，随后通过原来源预检／CAS 保存非秘密引用，不将密码写入普通文本模型。

草稿发现／测试 SHALL 允许在保存前使用密码控件中的新 Key，通过独立短暂请求输入传输，不先创建 vault 条目；只有用户明确保存时才进入密钥创建和引用绑定。测试结果不得回显 Key、宣称密钥已保存或把它作为普通 JSONC 字段写入草稿。

密钥创建／更新和来源引用保存 SHALL 分别反馈结果；取消或绑定失败不能假报密钥未创建、自动删除可能被复用的密钥或重发结果未知的写入。原配置提交继续沿 submission key／回执查询，明确原结果前不得换键重投或转投本地；vault 不共用这套回执。创建密钥前生成并保留原目标与稳定 secret ID，响应丢失只读原目标元数据按 ID 恢复，不能按名称匹配；更新／删除未知时显示原结果未知与当前状态，不凭 revision 或缺失推断成功，后续操作由用户明确基于新状态发起。更新共享密钥和改用其他密钥 SHALL 区别说明；移除 Provider／Model 不删除共享密钥。未完成的其他实体秘密能力保持准确支持边界，不宣称新增系统密钥链。

#### Scenario: 远端秘密输入与取消
- **WHEN** 用户从 B 的模型设置新建密钥并确认，或在创建请求发出前取消
- **THEN** 确认只写 B Gateway 密钥库，保存前取消零提交；普通页面、缓存及诊断不含正文，A 的环境变量不作为 B 的值

#### Scenario: 密钥已创建而引用尚未保存
- **WHEN** B 密钥创建成功后，用户取消引用绑定或来源 CAS 冲突
- **THEN** 分别显示密钥已创建和引用未保存，保留可复用元数据，不自动删除密钥或虚报全部操作已取消

#### Scenario: 引用保存响应丢失
- **WHEN** B 已保存配置引用，而客户端未收到回执
- **THEN** 沿原 submission key 查询，只依据原提交事实报告结果，不比较明文、不重发 PUT，也不将操作转投 A

#### Scenario: 密钥创建响应丢失与来源保存分开恢复
- **WHEN** B 创建密钥的响应丢失，之后用户重开设置
- **THEN** 按预定 secret ID 只读 B 元数据，存在时显示资源已创建及当前 revision；来源引用尚未保存仍单独显示，没有第二次创建或虚构 vault submission key 查询

#### Scenario: 修改非秘密参数或共享凭据
- **WHEN** 用户只修改模型参数，或明确更新当前共享密钥的值
- **THEN** 前者仅写配置并保留引用，后者沿 Gateway 原 revision CAS 更新并说明后续引用影响；两者均不回读或复制正文

### Requirement: Agent 管理必须保持定义与运行选择分离

产品 SHALL 提供 Agent 列表、详情、定义编辑、创建和移除本层定义，管理提示词、结构化模型 primary／fallback 引用和现有工具配置，并显示默认值的来源与影响范围；稳定 ID 创建后不提供重命名，显示名可编辑。模型选择 SHALL 同时确定 Provider 和 Model，不以单独 Provider ID、名称或列表首项代替。

配置定义及 `default_agent` SHALL 沿原 source writer；工作区会话默认 Agent／Model SHALL 沿原 SessionDefaults API／存储；当前 Session 选择 SHALL 沿原 Session owner，与 Composer 共用对应操作，不迁入同一 JSONC、双写或新增默认值协调器。定义变更遵守原后续 Job 生效规则，不能重建当前执行或批量重写会话。可删除性沿完整 candidate 当前引用及当前工作区默认值检查，继承恢复与历史引用遵守同一边界，不维护第二引用索引或全历史扫描。

#### Scenario: 修改默认值与既有执行并存
- **WHEN** A 中已有会话运行，用户修改工作区默认 Agent 或某 Agent 的模型配置
- **THEN** 原合同规定的新会话／后续 Job 使用更新，既有绑定和在途执行保持，不把当前 Composer 选择伪装成全局默认

#### Scenario: Agent 主模型与备用模型属于同一服务
- **WHEN** 用户选择同一 Provider 的两个不同 Model 作为 primary 和 fallback
- **THEN** 原来源保存完整的两个 ModelReference 及顺序，详情、Composer 和后续执行一致，不按 Provider ID 合并成一个选择

### Requirement: 工具管理必须复用真实目录与既有策略

工具管理 SHALL 展示所属 Agent／工作区、来源插件或内置组、只读工具说明与参数 schema、可见性、执行状态及已有策略，复用现有选择与测试 owner。定义策略走原配置来源；两个运行时开关走工作区 ToolSelectionStore，按 `agent_id` 保存，影响该工作区使用同一 Agent 的会话，不能标为当前 Session 私有、迁入来源 JSONC 或当作插件启停。静态策略锁定、插件实例／MCP可用性分别展示，开工具不自动启动插件。

selection PATCH 的回执只含 changed 项，SHALL 按稳定 `tool_id` 完整替换对应实体，其余目录保持；失败沿原 owner 重读，不将部分回执当完整目录，不为成功更新强制追加全目录读取。默认没有确认要求时 MUST NOT 新增审批中心、轮询审批或每会话后台检查；显式配置的既有确认语义不因页面整理被移除或启用。

模型工具测试 SHALL 由用户明确选择非空 ModelReference 范围及已有重复次数，显示实际目标和可能产生的模型调用／费用后显式启动；不在浏览列表时调用工具或模型。范围字段统一为 `model_refs`，后端原空范围表示全部的语义保持，但新 UI MUST NOT 用空数组表示当前模型。进度沿发起工作区与 run_id 查询；关闭页面仅结束本页观察，不宣称已取消后端测试、不自动重发启动。

#### Scenario: 打开多个 Thread 的工具页面
- **WHEN** 用户打开六个 Thread 并查看其中一个工具目录
- **THEN** 只按所查看范围读取真实目录，不产生六套审批轮询或模型探测，关闭页面后不继续执行工具探测

#### Scenario: 同一工作区 Agent 的工具开关
- **WHEN** 同一工作区两个会话使用相同 Agent，用户从其中一个入口关闭工具
- **THEN** 说明这是该工作区 Agent 的运行时覆盖，按原策略生效；只返回该工具时其余行保持，不改插件 enabled 或伪造 Session 私有配置

#### Scenario: 显式执行模型工具测试
- **WHEN** 用户选定 B 工作区 Agent 在同一 Provider 下的一个 Model 并启动测试，随后切到 A 或关闭页面
- **THEN** 只提交原 B 的非空完整模型引用和原重复次数，查询原 run_id，不扩大到其他模型、不重发或假报取消

### Requirement: Skill 与指令管理必须区分来源权限和实际使用版本

产品 SHALL 提供工作区及 Gateway 已支持的 Skill 来源列表、详情、来源配置、已有显式刷新和来源错误，并用正式 URI 打开实际 Skill／AGENTS 资源。来源配置沿各自 source writer；本机 Gateway refresh 与 Workspace 来源 refresh 分别沿原 owner。远端 Gateway 来源的联邦投影目前只读，不能将查看权限当作刷新权限或新增联邦刷新 RPC。刷新来源、插件开关及 Thread 跟踪是独立操作，不新增来源启用账本。

插件包 Skill SHALL 沿安装版本贡献只读打开；已有可写 Skill／AGENTS 仅按实际资源 owner 的写能力编辑。无写能力时明确说明，不提供虚假的副本按钮；本变更不新增包 Skill 复制／物化流程或副本 owner。来源发布、Thread 跟踪与当前请求使用的封存版本分别展示，不将刷新成功宣称为运行中上下文已替换；不恢复 Agent memory。

#### Scenario: 查看只读插件 Skill
- **WHEN** 用户打开安装包内 Skill 并希望编辑
- **THEN** 只读并显示包版本及所属插件，不自动复制或生成可编辑副本；已有可写资源按原 URI 能力另行打开，不改包贡献或注入 Thread

#### Scenario: 查看远端 Gateway Skill 来源
- **WHEN** 用户从远端工作区查看其 Gateway Skill 来源的只读联邦投影
- **THEN** 展示原允许的状态及资源，不发送 Gateway refresh、不回退到本地 Gateway 刷新；Workspace 自有来源的显式刷新仍由原 Workspace owner 执行

#### Scenario: 刷新来源期间存在执行
- **WHEN** 用户刷新工作区 Skill 来源，当前 Turn 已封存上下文
- **THEN** 显示新来源及刷新结果，当前执行保持其封存来源，后续允许边界才采用更新

### Requirement: 模型详情与快捷配置必须复用原生设置习惯

模型设置 SHALL 从原管理菜单、Settings 分类与模型选择器上下文动作到达同一对象。详情展示最终值、字段来源、实际父链、覆盖和不发送状态，参数按真实 schema 提供类型／枚举／只读状态；前端不得自己计算有效配置。行内操作与次要菜单复用原生 Workbench 控件，窄宽度保持可用，不因换模型或展开参数移动整个工作台。

协议切换 SHALL 在同一 JSONC 草稿编辑目标协议的完整 supports_reasoning 块，按统一 schema 原子替换，不拼接两种协议字段或猜能力。恢复继承删除整个本地块，显式空块保持独立语义，错误定位真实来源。快捷菜单修改持久配置只编辑同一来源节点，不另写原生模型 profile 参数或独立配置文件。

相同服务端模型的不同参数预设 SHALL 通过复制模型配置并取得不同稳定键实现；config_ref 是其配置定义关系，不增加一层 Variants 选择。收藏、隐藏、折叠仍是展示偏好，不等于删配置或切 Session。

#### Scenario: 从远端 Thread 打开同一模型配置
- **WHEN** 从 B Thread 进入模型详情，随后导航或焦点切到 A
- **THEN** 详情与快捷参数仍绑定 B 原模型，Settings／JSONC 指向同一文本模型，不弹重复范围选择或改写 A

#### Scenario: 窄宽度下查看参数来源
- **WHEN** 缩窄编辑器并切换模型、展开参数或来源链
- **THEN** 原生截断、滚动和菜单保持选择与操作可达，来源可检查，外层布局不随内容跳动

### Requirement: 配置继承必须用同一链或唯一父节点树展示

Settings SHALL 提供紧凑继承链及按需展开的同 owner 树，采用服务端返回的 node_id、parent_id 和来源。文件、Provider、Model 与原 runtime override 使用同一表示；上下文引用显示实际绑定对象，不混入文件优先级图或另一套代理链。只读／根节点不提供无效恢复继承，字段没有本地定义时也不显示可执行恢复动作。来源跳转沿原 config URI 和原文位置。

#### Scenario: 查看模型的完整生效路径
- **WHEN** 用户选中模型配置
- **THEN** 能看到从实际入口祖先到 Provider／Model 的真实单父链及字段定义节点，改变自定义父后显示新链而非固定示意图

#### Scenario: 根配置与子配置
- **WHEN** 用户查看无父根或未定义某字段的子节点
- **THEN** 不出现无效恢复继承；明确设值后才可删除该本地定义，值相同也仍标为本地覆盖

### Requirement: 代理设置必须说明继承语义和实际覆盖范围

已支持消费者的代理控件 SHALL 提供使用父配置、环境代理、直连、指定代理。使用父配置只删除本地 proxy 块，其他模式写合法完整互斥块。展示执行目标、捕获环境或脱敏代理地址及真实生效状态，不以当前浏览器机器解释 localhost。尚未接入的浏览器页面、SSH 和插件自有网络不显示伪生效控件；密钥只引用原密钥管理入口。

#### Scenario: 指定代理切换到继承
- **WHEN** 用户由 explicit 选择使用父配置并保存
- **THEN** 原 JSONC 的本地 proxy 块移除，显示父的真实策略及来源，不把父块复制为本地值

#### Scenario: 工作区和 Gateway 的出网不同
- **WHEN** 用户查看 Backend 模型和 Gateway 外部 MCP／下载请求的网络设置
- **THEN** 界面分别显示实际 owner 的继承链和执行机器，不能把工作区代理说成覆盖 Gateway 及所有插件流量

#### Scenario: 插件范围与终端环境不同
- **WHEN** 查看工作区插件的代理来源以及终端环境说明
- **THEN** 显示插件实际 Workspace 父链和已接入范围；明确用户命令继承启动环境，不把 JSONC 的代理保存显示成已有 Shell 已改变

### Requirement: 连接编辑完成后自动发现且由用户选择导入

添加模型 SHALL 始终支持手工填写。当前连接首次满足发现必需字段、或相关连接信息改变并结束编辑后 SHALL 默认自动获取一次当前 Provider 目录；提供关闭自动获取、手动刷新及取消，不随每次按键、模型参数改变或普通页面打开发请求。更换连接取消旧请求并废弃迟到结果；旧列表可见但须标为过期。

发现界面 SHALL 提供搜索、多选、选择全部匹配项、已配置／新增／本次未返回的差异和已选数量；不完整目录须明显说明，不能把未出现项当已下线。用户选入才写原来源草稿，保留已有模型身份、能力和参数。目录缺字段、空列表、不支持或失败须就地显示真实情况，不清空配置或阻止手填；最终目录／调用地址按同一请求规则展示，密钥保持脱敏。

普通浏览与保存 SHALL 不触发 Provider 发现或真实推理，既有公共元数据刷新保持其独立边界。系统 SHALL 分开呈现配置有效、凭据状态、目录返回和真实测试结果，不把获取到模型名称显示为“模型已验证可用”。

#### Scenario: 目录失败后手工添加
- **WHEN** 自动或显式发现返回不支持或网络错误，用户改为手工添加模型
- **THEN** 显示发现错误但保留现有模型和草稿，用户仍可填写合法模型信息并沿原保存链提交

#### Scenario: 快速输入与换连接不产生重复或错配目录
- **WHEN** 用户连续输入 Base URL 和新 Key，完成编辑后立即改用另一连接
- **THEN** 不逐字符请求，首次编辑完成只启动一次当前连接发现；旧请求取消，迟到响应不替换新连接结果，列表选择不被旧结果改写

#### Scenario: 打开已有设置和六个 Thread
- **WHEN** 用户打开已保存模型设置、恢复六个 Thread，或仅修改显示名／模型参数并保存
- **THEN** 不触发上游目录与推理；只有当前连接编辑完成或显式刷新才获取目录，自动获取关闭时仅显式刷新联网

### Requirement: 快速测试必须可直接测试草稿并给出分项反馈

模型详情 SHALL 提供快速测试，存在相关未保存修改时默认使用当前草稿，否则使用 active，并明确展示目标／工作区、模型、协议、模式和采用版本；用户能明确选择草稿或 active，pending 不冒充 active。测试为显式动作，不要求先保存或先创建会话，保存和 active 状态不能由测试成功替代。

采用版本 SHALL 区分本页编辑计数、实际来源基线或 active revision 及本次使用的非秘密凭据 revision。draft 明确以当前已保存来源（可含 pending）为基底替换所选来源；提交沿原 source document 携对应基线，其他来源已变化时显示配置冲突与重读入口，不自动重基、重发测试或覆盖脏草稿。临时 Key 改变同样废弃旧编辑版本的回执，不保存其正文或摘要作为版本。

测试 SHALL 支持当前配置模式、流式、非流式及明确选择两种，逐项展示状态和短输出，流式内容实时可见。模型 `api_mode.streaming` SHALL 在 Provider／Model 详情按继承／覆盖呈现；测试选择其他模式本身不改配置，用户明确应用时才编辑原草稿。默认单模型，批量仅使用用户明确选中的非空范围并可停止；已有工具准确率测试作为独立深入入口，不自动运行，也不展示尚未实现的能力测试控件。

短暂 Key SHALL 显示其绑定的是 Provider 默认还是指定 Model 覆盖，按该位置参与同一继承。被 Model 覆盖而不生效或对象不匹配时显示对应字段错误并零上游请求；旧引用失效不能阻止当前字段明确替换后的 draft 测试。结果不得把临时输入、原凭据或其他 Model 的成功混为一项。

测试观察 SHALL 消费同一 POST 返回的 start／delta／result SSE，start 只表示已进入测试，心跳、HTTP 200 与无 result 的 EOF 均不能显示通过；前者等待真实终态，后者非主动取消时显示失败。慢首内容可在测试总期限内等待，不受普通 JSON 15秒默认值截断；不自动重连或重放推理请求。取消须传播到真实请求，断开后只显示本地取消事实，不宣称撤销上游计费。

结果 SHALL 显示首个有效内容与完整耗时、取消／超时／本次失败及真实错误、实际观察版本与时刻；通过仅说明该版本当时的一次请求。相关输入、原配置通知、密钥管理回执或显式重读表明版本变化后标为过期，不能因本页编辑计数没变而继续表示新配置已通过。没有通知的其他窗口／进程变化不假报已实时检测；提供原范围版本刷新，零自动重测或后台轮询。短错误和可展开脱敏详情分开，能定位相关表单字段或同一 JSONC，保留原 request_id；无法确定原因时显示原错误而不猜测。自动发现状态就地展示，窄宽度采用原生滚动、截断和菜单，不因状态切换或不同测试按钮移动整个工作台。

#### Scenario: 未保存参数立即测试
- **WHEN** 用户修改参数后直接点击快速测试
- **THEN** 明确采用当前草稿及对应有效参数，显示逐项结果且零配置写入；用户切回 active 测试时实际采用已生效版本，不混用两者

#### Scenario: 另一窗口修改继承来源或凭据
- **WHEN** 本页草稿未变，另一窗口保存其继承来源或轮换所用密钥，本页随后测试或刷新版本
- **THEN** 旧来源基线在上游调用前报告冲突，既有测试按实际观察 revision 与时刻显示，已知新版本使旧结果过期；不自动重基脏草稿或再次发推理请求

#### Scenario: 仅非流式测试通过后应用模式
- **WHEN** 一个模型流式失败、非流式通过，用户选择将其设置为非流式
- **THEN** 保留两项真实测试结果，只有该显式操作修改模型草稿的 streaming 覆盖；仍需原保存链提交，其他模型与运行 Job 不改变

#### Scenario: 出错后直接修正字段
- **WHEN** 上游明确报告鉴权失败或模型不存在，或发生无法分类的错误
- **THEN** 前两者提供凭据／服务端模型名的定位动作，后者保留脱敏原错误；原草稿和已知结果保持，用户修正后可显式重测，没有自动重试或全局错误弹窗循环

#### Scenario: 模型覆盖导致临时 Key 未被使用
- **WHEN** 用户在 Provider 输入新 Key 后测试一个已有独立凭据覆盖的 Model
- **THEN** 明确显示该 Model 的凭据覆盖位置并拒绝本次未生效临时输入，不发送请求或显示新 Key 已验证；用户可明确在 Model 字段替换后重新测试

### Requirement: 日常模型选择必须提供搜索与独立展示偏好

聊天模型选择器 SHALL 自动聚焦搜索，支持显示名、稳定 ID 与服务端模型名匹配，按 Provider 分组并显示当前选择、最近使用、收藏及必要归属。模型提示 SHALL 区分已声明能力、参考目录信息和未知，不因未测试而假报不可用；可从行上下文到达同一原生 Settings 对象。

Settings SHALL 管理当前工作区全部模型，Composer 的可选结果 SHALL 仅来自当前 Agent primary／fallback 的完整 ModelReference 集合。收藏和最近展示与该集合取交集；同 Provider 的其他 Model 不自动纳入。切换 Agent 后沿原 Session owner 更新允许选择，旧会话绑定已不允许时保留其身份与原因并要求明确选择，不先在前端伪造成功或偷偷修改 Agent 定义。Settings 的无会话快速测试仍可显式测试其他已配置模型，不混同于会话执行准入。

收藏、最近、隐藏和折叠 SHALL 使用原 Workbench 展示存储，按 Gateway／Workspace／ModelReference 隔离，不作为业务默认值或第二模型目录。隐藏当前选中项不能改变 Session；当前模型仍可辨认并可进入设置。无法解析的旧偏好不恢复已删配置、不改绑同名模型、不触发网络探测。切换模型仍沿原 Session owner 提交真实选择。

#### Scenario: 隐藏当前模型和恢复偏好
- **WHEN** 用户隐藏当前选中的模型，然后关闭并重新打开选择器
- **THEN** 会话选择保持且当前项仍可辨认，普通结果按隐藏偏好筛选，恢复显示不重建模型配置或调用上游

#### Scenario: 不同工作区同名模型的最近使用
- **WHEN** 用户在 A 使用一个模型后进入 B 的选择器，两处有同名服务及模型
- **THEN** A 的偏好不冒充 B 的当前或最近模型，选择 B 的项仍提交完整 B 归属，不按显示名路由

#### Scenario: 收藏模型不扩大 Agent 的候选范围
- **WHEN** 一个 Model 在工作区已配置并被收藏，但当前 Agent 只允许同 Provider 下另一个 Model
- **THEN** Settings 可查看和测试前者，Composer 的搜索、最近与收藏不提供它作为执行选择；管理 Agent 允许集合是独立显式配置动作，切换 Agent 后重新筛选
