# resource-file-operations Specification

## Purpose

为目录导航、普通文本文件访问和目标端文件执行提供统一消费合同。工具通过资源 URI 固定目标、返回可继续访问的引用，并诚实报告冲突、部分写入与执行未知结果，保持普通文件操作与上下文激活及业务资源生命周期分离。
## Requirements
### Requirement: 文件工具必须共用唯一寻址与文件 owner

系统 MUST 使 `ls/read_file/glob/grep/write_file/edit_file/apply_patch` 消费 `add-unified-virtual-resource-addressing` 的 URI 语法、导航形态、操作能力和错误登记，并遵守其「普通文件入口必须保留原生路径输入并统一目标解析」。普通文件/根目标 MUST 接受相对路径、绝对路径和资源 URI；目标与 glob/grep 查询条件 MUST 为独立字段，查询文本不得参与 authority、工作区或根解析。每个调用在执行前固定目标 Gateway/机器、目标工作区或选定目录及规范子路径，三种输入通过同一目标解析边界交同一文件 owner，不保留独立旧解析器或执行链。

原生路径按公共 owner 的字段职责合同用于明确目标机器的参数、展示、正文、诊断及必要原生配置；资源目标与持久引用继续使用 URI，不建立第二权威定位关系。外部绝对路径按既有能力和授权处理，不得通过去除根/盘符改投工作区，也不得以 URI 化取消既有外部文件能力或要求先注册工作区。用户原生路径和 DeepAgents 内部虚拟路径 MUST 以明确入口或类型区分，迁齐调用方后移除歧义回退。终端/shell 仍按目标操作系统解释路径，Gateway 原生目录选择/注册的管理入口不限制普通文件绝对路径输入。

文件树 MUST 保留未注册目录浏览和文件编辑，以及快捷目录保存/重开能力，引用统一寻址 owner 的相同合同及规范地址；MUST NOT 要求先注册、暗中注册或伪造 workspace_id。公共 owner 尚未补齐模板时应先完成该依赖，不得以删除功能、收窄为只读或返回工作区同名文件替代迁移。

#### Scenario: 三种输入经真实入口访问同一对象

- **WHEN** 对同一目标工作区文件，分别使用相对路径、目标原生绝对路径和资源 URI 读取或授权写入
- **THEN** 三者访问同一实际文件，产生相同规范资源引用并遵守相同能力/冲突规则，不产生副本或另一条操作链

#### Scenario: 外部绝对路径不误读误写工作区文件

- **WHEN** 目标工作区内存在 `etc/hosts` 对照文件，而普通文件入口收到目标机器的 `/etc/hosts`
- **THEN** 在隔离验收目标上读取/授权写入真正的外部文件，或明确拒绝且零写入；工作区对照文件始终不被读取为替代结果或被修改

#### Scenario: 远端原生路径只在目标机器解释

- **WHEN** source/relay 与目标采用不同当前目录或操作系统，普通文件入口收到已明确目标的相对路径或 Windows 等原生绝对路径
- **THEN** 目标机器按其原生语义和选定目录执行，实际目标内容/修改可核实，source/relay 同名文件不变，不在中继重绑定或本地 fallback

#### Scenario: 搜索条件不改变目标

- **WHEN** 在某资源根搜索含斜杠、中文或 URI 字样的 pattern
- **THEN** 查询仍只在已固定根内执行，pattern 不成为目标路径或联邦路由参数

#### Scenario: 激活工作区切换

- **WHEN** 文件调用已固定目标后，用户切换当前激活工作区
- **THEN** 本调用及其分页/写入仍指向原 Gateway、工作区和根，不重新用当前激活态解释

#### Scenario: 同一后端由多个 Gateway 注册

- **WHEN** 固定 Workspace 导航存在多个 backend ID 相同的注册目标
- **THEN** URI 的显式 Gateway 归属只匹配对应注册 owner，Gateway scope 的缺省 authority 仅指本机；没有明确归属或同 owner 仍有多个候选时明确拒绝歧义，不借请求头或激活工作区代选

#### Scenario: 连接更换与目标重开

- **WHEN** 已固定导航目标的联邦 channel 更换，或目标 backend 退出后重开
- **THEN** 相同 URI 和合法 cursor 仍访问原 Gateway、Workspace 和根；目标不可达期间明确失败，不能改读当前激活工作区或 source 同名文件

### Requirement: 导航与搜索结果必须有界且可继续访问

目录和搜索结果 MUST 带规范资源 URI 和节点类型；搜索匹配同时带文件引用、位置和有界片段。操作 MUST 设置 entry/match、单文件读取、总响应字节及总 deadline 上限，明确返回截断原因和 continuation 能力；分页 cursor MUST 绑定目标根、操作及查询参数，不含真实路径或凭据。普通可变目录分页不得伪称历史快照；检测到影响分页的变化时明确披露或拒绝旧 cursor。不得为了分页为所有文件建立持久快照。

#### Scenario: 技能包多层访问

- **WHEN** 列出技能包根后访问 references 下中文带空格文件或 scripts 下文件
- **THEN** 使用返回 URI 可访问同一目标，分段编码由统一 owner 处理，读取不产生 activation/tracking 记录

#### Scenario: 大量搜索仍保持轻量

- **WHEN** 对大量未登记文件执行 glob/grep
- **THEN** 返回受限匹配及明确截断/分页信息，来源身份、历史快照与 activation 数量保持不变

#### Scenario: cursor 与另一个根或查询混用

- **WHEN** 将搜索 cursor 用于不同根、操作或查询
- **THEN** 显式拒绝，不跳到新目标继续读取

#### Scenario: 路由预算扣减与续页查询分别保持

- **WHEN** 输入解析、Gateway 路由及目标执行消费同一次导航预算，或相同查询的续页获得不同的剩余执行时间
- **THEN** 后续节点不得重新获得完整查询预算；原 `timeout_ms` 及 cursor 绑定保持不变，执行期限只能缩短，响应正文分块不能重启总计时，已过期调用不得继续读取或回报成功

#### Scenario: 模型目录导航复用同一文件执行

- **WHEN** 模型经同步或异步 ls 列出工作区或已公布 Skill 目录，或使用相同目标和限制续页
- **THEN** 两个入口使用同一文件 owner 与 URI 导航结果合同；原 DeepAgents ls 执行不再被调用，普通导航不建立来源观察或上下文激活，已有事件循环中也能使用同步入口

#### Scenario: 普通工具执行期间存在后续模型装配

- **WHEN** ls 结果驱动同一轮的后续模型请求，运行时保存新的 assembly binding
- **THEN** 新装配仍引用原有 activation snapshot、bindings hash 与 provenance，普通导航不新增来源控制、来源快照或 activation；不能把正常模型装配回执误认成文件来源激活

#### Scenario: 内容搜索在同一文件内续页

- **WHEN** 单文件或目录内容搜索产生超过本页限制的匹配行
- **THEN** 返回规范文件 URI、一索引行列及有界 UTF-8 片段，以绑定目标、查询和限制的 cursor 继续；前缀变化明确拒绝，count 仅表示本页匹配行，不能把局部计数伪称全量

#### Scenario: 搜索超限和编码失败

- **WHEN** 内容搜索遇到超过文件字节预算的文本或未知非 UTF-8 文本，或最终工具回执超响应预算
- **THEN** 返回明确文件执行错误，不伪报无匹配；已知媒体及含 NUL 二进制按原 grep 规则跳过，普通文件搜索不返回被工具读取规则拒绝的文件匹配

### Requirement: 普通文本读写必须遵守能力与修订边界

普通文本读取与首批写入 MUST 使用严格 UTF-8 文本和原始字节内容 hash，不隐式改写换行、BOM 或 Unicode。读取可有明确范围/截断标志，不完整内容不得标作完整；普通文件 hash 按需计算。既有 `read_file` 支持的图片等媒体读取 MUST 保留其工具结果合同，不能因文本编码限制而失效；媒体类型与读取能力由实际资源 owner 公布，不将任意非 UTF-8 文件猜成媒体。文件写入 MUST 校验 owner 公布的写能力，绑定预期当前内容 hash 或 owner 的等价 revision；创建 MUST 使用明确的预期不存在条件。只读根、固定历史 revision、领域对象以及由附件/工具结果 owner 管理的产物不得被通用文件工具覆盖。文件工具不得写入上下文来源控制或伪造来源 revision。

#### Scenario: 并发修改返回冲突

- **WHEN** 文件读取后在写入前内容已改变，或预期不存在的文件已出现
- **THEN** owner 返回明确冲突并保留实际新内容，不自动覆盖或以旧内容重试

#### Scenario: 只读根和历史引用拒绝写入

- **WHEN** 对 inline 技能、只读资源或固定历史 revision 提交 edit/write/patch
- **THEN** 按 owner 能力明确拒绝，不转为操作当前可写文件

#### Scenario: 非 UTF-8 文件被文本工具读取

- **WHEN** 通过文本读取能力读取不符合严格 UTF-8 的字节
- **THEN** 返回明确编码失败，不用替换字符伪造文本；既有媒体读取能力不受该文本限制，附件二进制读取仍归附件 owner

#### Scenario: 行范围和媒体读取共用同一执行 owner

- **WHEN** 同步或异步 read_file 使用已公布文件 URI，选择文本行范围或读取既有受支持媒体
- **THEN** 复用同一文件 owner，文本保留原 UTF-8 字节语义和一索引行号，媒体保留原有 block 与 Provider 投影；显式预算包含跳过的行、完整媒体及最终工具回执，超限不得伪报完整内容或返回残缺媒体

### Requirement: 补丁必须固定一个根并披露实际发布结果

一次 apply_patch MUST 固定一个目标根；补丁内文件名只按该根的未编码相对文件路径解释，经同一 owner 校验，不允许嵌入另一 authority、绝对路径或越界段。首批 MUST 保留既有文本新增、修改、`Delete File` 和 `Move to` 能力；通用目录/二进制节点 mutation 留后续切片。删除 MUST 校验原文件的预期当前版本；同根文本移动 MUST 分别校验源文件版本和目的路径的预期不存在或明确预期当前版本，不允许无条件覆盖目的文件。owner MUST 在首次发布前检查全部受影响路径（含移动的两个端点）的能力、预期版本与补丁有效性；单文件 MUST 原子发布完整内容，删除的不存在结果也必须核实。多文件修改以及移动的目的发布/源删除不承诺跨路径事务：发布过程中失败时 MUST 停止后续写入，返回已发布、确定未发布/未尝试及结果未知的逐路径列表、存在状态和可核实的新 hash，不伪报整批回滚；不得通过盲目恢复旧内容覆盖外部并发更新。

#### Scenario: 补丁 preflight 失败

- **WHEN** 多文件补丁有一个文件版本冲突或属于另一根
- **THEN** 全部文件在发布前保持未修改，失败指出相关逻辑引用

#### Scenario: 中途发布失败

- **WHEN** 首个文件已原子发布而后续文件发布失败
- **THEN** 响应明确为部分失败，列出实际已发布、未发布及未知文件，不宣称整体未执行或已回滚

#### Scenario: 既有文本删除和移动继续可用

- **WHEN** 在同一目标根提交包含 Delete File 或带内容修改和定位提示的 Move to 补丁，所有预期版本有效
- **THEN** owner 保留原补丁内容与变更结果，核实删除后路径不存在、移动后源不存在且目的内容正确，不要求模型改用终端或另一套文件工具

#### Scenario: 移动目的出现并发修改

- **WHEN** 移动目的不满足 expected_absent 或其预期内容版本
- **THEN** 全部补丁在 preflight 显式冲突，源与目的保持原状，不覆盖并发内容

#### Scenario: 移动目的已发布但源删除失败

- **WHEN** 目的文件已发布，而源文件删除失败或其结果不可确认
- **THEN** 逐路径报告已核目的存在及内容、源路径的失败或未知状态，不报整体移动完成、不宣称两路径均已回滚

### Requirement: 跨端文件操作必须在固定目标端执行

系统 MUST 复用既有联邦身份、授权、星型路由和总 deadline，把操作交给目标资源 owner 所属进程执行。Gateway 只负责路由/代理，不能读取工作区业务数据或返回真实路径让 source 端代执行。各实际操作点校验最新权限，send/read/wait 的通信 grant 不自动授权文件读写；文件操作复用既有授权机制登记独立操作。不可达、不支持或撤权必须显式失败，不改投本地同名目标。

#### Scenario: 相同路径在两个 Gateway 中

- **WHEN** 两端有同名文件，对远端 URI 执行 grep 或 patch
- **THEN** 结果和修改发生在远端，source 同名文件不变；跨界资源目标使用 URI，展示与诊断路径不在 source 本机解析，凭据继续保护

#### Scenario: 对端故障或不支持文件操作

- **WHEN** 目标不可达、撤权或缺少该操作能力
- **THEN** 返回该阶段明确失败，不切换本地执行，不伪报空结果

### Requirement: 超时取消和响应丢失必须反映执行知识边界

文件执行错误 MUST 与 grammar/resolve/联邦寻址错误分开，由文件 owner 区分 `revision_conflict`、`invalid_patch`、`invalid_encoding`、`output_limit_exceeded` 和 `execution_failed`，不得用它们替代寻址阶段登记。响应 MUST 披露目标实际效果为确定未执行、确定完成、部分完成或未知。发出取消请求不等于目标已停止；deadline 或响应丢失不证明未写入。写入结果未知时 MUST 返回可核实的目标引用和已知前置版本，阻止自动重放直到核实；不新增通用 operation_id/去重账本，实际业务需要恢复时复用既有稳定调用身份并由对应 owner 定义回执。

#### Scenario: 发布后响应丢失

- **WHEN** 目标可能已发布文件，而 source 端收到连接断开或超时
- **THEN** source 将效果报告为未知并核实原目标，不声称未执行、已回滚或自动重新选路重放

#### Scenario: 请求取消仍在执行

- **WHEN** source 发出取消而尚未收到目标停止确认
- **THEN** 返回取消已请求及当前已知效果，不宣称目标实际停止

### Requirement: 会话产物引用必须迁入统一寻址并保留原 owner

附件 MUST 使用唯一寻址 owner 登记的 workspace attachments 目录及文件 child 引用，按 `managed-attachment-directories` 保留每次独立上传的目录身份、精确关联和 30 天回收；旧 Session 附件 URI只用于迁入后的精确历史解析，不生成新引用。目录可通过同一文件 owner 导航，原件与预览只读，派生区复用现有授权文件写入；MUST NOT 因开放附件目录而暴露其它 `.boxteam` 私有数据。工具输出仍使用 Session 单文件引用，保留原 result ID、精确访问授权及生命周期，不开放产物目录遍历或通用修改。生成、读取、工具结果、Provider 输入及 Web/历史投影 MUST 使用同一规范 URI；`boxteam-session://` scheme 和旧解析分支迁齐调用方后物理下线，不保留别名、旧 blob writer 或双读。未授权与不存在遵守各原 owner 的披露合同。

统一 URI 的读取分派 MUST 将附件交原附件 owner 取得内容，保留既有 `original`/`thumbnail` 变体参数；变体不成为 URI query、fragment 或另一套文件身份。Web 附件内容接口仍消费同一 owner，既有 `read_file` 对受支持媒体返回原有媒体 block，并经现有 `project_tool_message_content` 和目标 Provider 能力处理。通用文本读取仅消费文本能力，不能替代二进制原件或将其以替换字符返回；不新增 `attachment.xxx` 工具、通用二进制写入平台或私有目录读取旁路。

#### Scenario: 新附件与工具输出可重开读取

- **WHEN** 新产物经消息/工具结果及历史投影发布后重启 owner
- **THEN** 同一规范 URI 经原 owner 可访问相同内容，授权及删除结果仍与原业务行为一致

#### Scenario: 图片附件 URI 保留已有媒体读取

- **WHEN** 经统一 URI 使用既有 read_file 读取受支持图片附件，或客户端请求该附件的 original/thumbnail 变体
- **THEN** 内容由原附件 owner 在固定目标提供，媒体工具结果与 Provider 投影遵守既有合同，不报 UTF-8 文本错误、不返回真实路径，也不开放 Session 私有目录

#### Scenario: 附件目录派生文件复用原文件链

- **WHEN** 用户或模型导航附件目录，读取原件并在 derived 区生成或编辑文本文件
- **THEN** 同一 URI 解析和文件 owner 执行访问，原件/预览不可被覆盖，派生结果可继续按资源 URI 读取；其它私有存储仍拒绝，工具输出不因此获得目录或修改能力

#### Scenario: 旧 scheme 被拒绝

- **WHEN** 入口收到 boxteam-session scheme 或猜测会话私有目录
- **THEN** 明确拒绝，不走旧 parser，不扫描旧开发数据或生成兼容地址

### Requirement: Webview 资源缓存沿原版加载与隔离规则

受控 Webview 文件资源 SHALL 沿原 asWebviewUri、Service Worker Cache Storage、loadLocalResource 和同一 FileService 加载；有缓存时携带其 ETag 校验，NotModified 复用缓存，新内容沿原流显示与更新。普通图片编辑器 SHALL 保留原 FileService／Blob 路径，不被替换成 Webview 来伪造缓存接入。两条原加载链 MUST NOT 再叠加应用自管字节库、home 文件镜像、原生文件系统 IPC 或第二资源解析器。外部 HTTP(S) 图片遵守其来源和原 Webview 安全／HTTP 策略，不承诺全部第三方内容可缓存。

缓存使用 SHALL 保留稳定 Gateway／工作区／规范资源归属、原 Webview localResourceRoots、origin／profile 与当前认证边界。存在缓存 MUST NOT 跳过当前权限校验，退出或身份切换 SHALL 取消旧读取并撤销旧展示引用；新上下文验证前不使用旧资源。原 watcher 的变更、删除、重连及 overflow SHALL 触发原文件服务重新核实；目标删除、不可达或拒绝访问 SHALL 明确失败，不能默认以缓存冒充当前成功。缓存键、业务 URI 和日志不得嵌凭据；路由重用不能改变原资源归属。

Range SHALL 保留原 206、Content-Range、取消和按需字节读取，不进入完整资源缓存，不为预览或缓存而完整下载音视频。仅有修改时间／大小时 SHALL 明确其观察值局限，不承诺检测二者均未变化的任意外部改写或据此提供可复现版本。

#### Scenario: 同路径目标、认证及 route 变化
- **WHEN** A/B 有同显示路径图片，客户端切换身份，或旧 route 被另一个工作区复用
- **THEN** 当前授权及完整资源身份决定校验和读取，A 缓存不成为 B 或新身份的成功响应；迟到旧请求不覆盖当前图片

#### Scenario: 缓存存在但原资源不可用
- **WHEN** 图片已有缓存，但文件被删除、权限被撤销或原目标断连
- **THEN** 当前读取明确失败，缓存不绕过原 localResourceRoots 或权限，也不作为离线成功回退

#### Scenario: Webview 与分段媒体各用原链路
- **WHEN** Webview 对未变文件请求完整 GET，另一媒体请求指定 Range
- **THEN** 前者经宿主校验后可复用 Cache Storage，后者只读取对应范围且不写成完整缓存；两者不新增解析／下载服务或推进保存基线

### Requirement: 资源缓存跨 Web 与 Electron 持久且可丢弃

Web SHALL 使用浏览器 origin 的原 HTTP 缓存／Cache Storage；Electron SHALL 使用同一前端读取链、稳定 renderer origin、既有 persist partition 和固定 profile，由 Chromium 管理磁盘格式，正常重启不主动清资源缓存。两者 MUST NOT 为此分叉前端源码或添加 native FS IPC。缓存沿引擎配额、淘汰与原缓存版本生命周期，MUST NOT 无界预热或成为业务权威。资源缓存清理 SHALL 只作用于所属缓存，不删除聊天历史、设置、草稿或后端文件。淘汰按原权限重新读取，来源读取结果仍按原合同表达，不能以成功读取宣称持久化成功。

官方隔离 Webview Worker 的 Cache Storage 异步写入 SHALL 沿用上游尽力而为语义：配额或写入失败不影响已成功取得资源的响应，不要求额外日志或宿主错误上报。MUST NOT 为补充该诊断复制 Worker、另行部署隔离宿主或增加写入探测。资源读取失败、权限拒绝及其它缓存层的原诊断要求继续适用。

验收 SHALL 在真实 Gateway 和目标工作区下分别覆盖 Web 与打包 Electron 的普通图片及 Webview：首次、再次、正常重启、修改更新、身份隔离、断连／删除、Range 及缓存淘汰。证据 SHALL 区分网络 304 与浏览器合成的 fetch 200，记录实际条件请求、服务端状态及正文传输量，不以图片可见、进程启动、上游源码存在或浏览器 parity 代替原生证明。原 Webview Worker／宿主未匹配固定版本时 SHALL 明确未完成，不替换原编辑器绕开。

#### Scenario: Electron 重启后复用资源字节
- **WHEN** 打包 Electron 已缓存普通图片和 Webview 资源，正常退出后以相同 profile／来源重启，缓存未被引擎淘汰且原资源未变
- **THEN** 两类入口均经原链路校验后复用字节而不重传正文；证据包含实际产物、缓存存储边界和网络行为，不依赖开发服务器或源码目录

#### Scenario: 缓存被淘汰
- **WHEN** 浏览器淘汰缓存，而原资源仍可访问
- **THEN** 原读取链可重新取得正确字节；不创建 home 文件副本或清除其它展示态补偿

#### Scenario: 官方 Webview 缓存写入失败
- **WHEN** 官方隔离 Worker 已取得正确资源，但异步缓存写入因配额或其它写入异常失败
- **THEN** 沿用上游响应与错误处理，不要求新增写入失败诊断，不宣称资源已经持久化；后续读取继续遵守原权限和校验合同

### Requirement: 文件搜索选项与坐标必须显式表达
同一导航 search SHALL 接受有类型的可选 `search_options`，声明文本匹配的正则、大小写模式、整词及自定义分隔符、多行与全部命中，以及路径 include／exclude 和 ignore 模式。省略选项时保留既有大小写敏感字面量与每行首个命中；显式全部命中按非重叠匹配返回，不建立第二个搜索器。smart case 对未转义的大写字符敏感，正则转义不单独触发大写判定，沿原 QueryBuilder 的规则。非法正则、无效选项及尚未支持的父目录／全局 ignore 选项 MUST 明确拒绝，即使目标为空也不得伪报无匹配；不能把固定目录排除冒充 `.gitignore` 支持。

include／exclude SHALL 按选定根内相对路径使用原 glob 合同，exclude 在进入子树和正文读取前生效；省略 ignore 模式沿原固定排除，显式关闭仍不得绕过私有存储及目标权限。正则执行 SHALL 消费同一次剩余 deadline，不让单个匹配重新获得完整预算。选项进入原 cursor 绑定，改变模式或匹配选项不得沿旧页继续。

原通用导航搜索 SHALL 保留目录候选。文件 Search Provider SHALL 沿同一 owner 明确启用 `files_only`，在计量和分页前排除目录候选，不能取到受限页后在客户端丢掉目录并推进页尾 cursor。名称页按文件数、正文页按实际命中区间计量；上下文行不占用命中名额。

为接入原版打开模型覆盖，文件查询 SHALL 接受调用方明确传入的覆盖资源身份集合，由稳定工作区及原文件 owner 的 canonical 身份限定；省略时仍查询原已提交资源。文件 owner SHALL 在正文读取及输出计量／分页前排除该集合，不将被覆盖磁盘旧命中计入结果数或上下文；该选项参与查询缓存与 cursor 绑定。集合不包含模型正文，不扩大根或授予资源访问能力，MUST NOT 用显示路径屏蔽其它工作区文件；模型搜索和已打开集合的选择仍由客户端原服务负责。

父子搜索根 SHALL 各自保留相对 include／exclude 与 ignore 选项。父根通过 `excluded_subtree_uris` 明确交出由独立分支处理的严格子树，原文件 owner 在递归、规则及正文读取和输出计量前剪枝；该集合最多256项，沿原 URI 归属校验及 cursor 绑定，不接受查询根本身或其它 owner／根。子树新增文件不构成父分支的正文前缀依赖，改变分区集合使旧 cursor 失效。客户端模型按相同分区归属，不借父根较宽选项恢复被子根排除的文件；相同根的冲突局部选项仍明确拒绝，不静默择一。

#### Scenario: 父子根使用不同局部选项

- **WHEN** 父根只查 TXT，独立子根只查 Markdown 且使用自己的 ignore 模式，查询同时包含该子根的未保存模型
- **THEN** 父分支不读取子根正文或规则，子根只交付自身选项允许的磁盘／模型命中；同一资源只计量一次，已打开精确单文件不携带不属于该文件的子树排除项

`respect` SHALL 在目标机器解析明确搜索根以内的 `.gitignore` 与 `.ignore`，支持目录继承、锚定和否定；`.ignore` 优先于 `.gitignore`，同类规则由最近目录的最后匹配决定。目录在递归及正文读取前剪枝，子目录规则不能复活已剪枝目录。不读取所选根之外的父目录或全局规则，不依赖中继进程的工作目录。显式单文件及已打开模型沿原搜索行为，不另用磁盘规则隐藏它们，仍核验完整 owner、根和显式 glob。每目录规则文件只读取一次，所有规则正文累计受同一 `max_bytes` 预算及总 deadline 约束；无效 UTF-8、非普通文件和越界规则明确报错。规则文件观察值及缺失事实进入原续页前缀绑定，规则被 include／exclude 隐藏也不失去新鲜度校验，不为规则新增正文 hash 或持久索引。

文本命中 SHALL 使用一索引 Unicode 码点行列，携带不包含终点的结束行列；多行、CRLF 和片段截断不得改变真实命中区间。原 owner SHALL 同时给出起点、终点及片段起点的 UTF-16 列，按完整原文计算；客户端接入编辑器时消费这些列，不从裁剪片段猜测省略前缀，也不为转换额外读取完整文件。仅已打开文件的选择归客户端原 editor/model 服务，后端不猜测浏览器已打开集合；查询发起前必须限定精确目标，后续搜索服务接入仍须独立验收。

`context_lines` SHALL 明确指定命中区间前后各 0～100 行，省略时为零。上下文与命中来自同一次有界读取，使用资源 URI 和一索引行号，每页按资源及行号去重；不计入命中数量，仍受片段字节、响应预算与原 cursor 约束。客户端按最终接受的命中合并跨页上下文，去掉命中行与上限之外的无关行；截断必须可辨认，不为上下文额外读取正文。未保存模型沿原模型搜索提供上下文，不能混入同文件的磁盘旧内容。

文件续页 SHALL 区分已完成的文件与当前文件内已交付的命中，续点停在首条未交付项。已消费前缀 SHALL 使用原文件观察值及 ignore 版本核验；续查不重新读取、匹配或序列化此前已完成文件的正文，不为每条命中重复保存正文指纹。当前文件的部分页仍核验文件观察值，并沿同一匹配实现恢复行列及上下文。续点不依赖进程内匹配列表或新建持久目录索引，重启后可继续。已消费文件即使大小和 mtime 相同，其其它原观察值发生变化仍明确拒绝；未消费文件的后续正文变化保持可见，不把普通可变搜索扩大为历史快照。

每页输出条数 `limit` 与响应字节 `max_response_bytes` SHALL 按本次请求执行，不参与查询身份绑定；相同查询的续页可以增加或减少这两项预算，包括联邦从多根继续单根时重新分配的页配额。根、操作、匹配及覆盖选项、扫描和单文件读取限制、原 `timeout_ms` 以及文件版本／已交付区间仍 SHALL 保留原续点校验；预算变化不得使未交付命中被跳过，也不得绕过其它查询限制。

#### Scenario: 多文件小页续查跳过已完成正文
- **WHEN** 调用者以小页查询多个文件并跨重建 owner 或 Gateway 重启继续，或通过原保存入口修改已消费文件
- **THEN** 续查返回连续、无重复的原命中位置，已完成文件仅核对观察值而不重读正文；已消费文件变化拒绝原 cursor，尚未消费文件的正文变化可由后续页读取

#### Scenario: 目录名称也匹配的小文件页
- **WHEN** 文件查询使用一条结果的页配额，搜索根中同时有同名匹配目录与多个文件
- **THEN** 文件页交付一个真实文件及原合法续点，目录不消耗文件名额；通用导航仍可查询该目录

#### Scenario: Search Editor 带上下文重查
- **WHEN** 原 SearchView 以非零上下文行数创建 Search Editor 并自动重查，或相邻命中跨页返回重叠上下文
- **THEN** 使用原明确范围和同一文件查询链，保留上下文行号、去重及截断事实，不重复显示命中行

#### Scenario: 本地覆盖身份参与有界分页
- **WHEN** A 文件有未保存零命中模型，客户端以其精确覆盖身份查询小配额正文页，而 A 其它文件与 B 同显示路径仍匹配
- **THEN** A 被覆盖文件不读取旧正文、不占结果额度，原 cursor 可取得其余所选匹配；B 的独立身份不被排除，改变覆盖集合后旧 cursor 明确失效

#### Scenario: 查询选项保持意义并有界执行
- **WHEN** 对同一文本使用敏感、忽略大小写、smart case、整词和正则，或正则耗尽本次预算
- **THEN** 返回与声明一致的命中或明确 deadline 错误，不把全部选项按 substring 执行

#### Scenario: 多行命中包含 emoji 和 CRLF
- **WHEN** 多行匹配从 emoji 后开始并跨越 CRLF，或起始行的展示片段被裁剪
- **THEN** 返回精确码点起止区间及独立片段起点，保留后续 UTF-16 转换所需信息

#### Scenario: 排除子树和不支持的规则
- **WHEN** include／exclude 或目标 ignore 规则排除未知编码文件或整个子树，或显式要求尚未支持的父目录／全局规则
- **THEN** 被排除正文不参与读取；不支持的规则明确报错，不在更广范围执行后过滤

#### Scenario: 目标规则与中继规则不同
- **WHEN** 目标机器与中继有同名文件及相反的 ignore 规则，或用户关闭 ignore 后重查
- **THEN** `respect` 只解释目标根以内的规则，关闭后沿同一文件链返回原先被排除的文件，不查询中继文件系统

#### Scenario: 规则变更与有界读取
- **WHEN** 规则在续页前被创建、改写或删除，或嵌套规则累计超过读取预算
- **THEN** 前者明确拒绝旧 cursor，后者明确报告规则读取受限，不继续使用旧规则或伪报完整无匹配

### Requirement: 文件名称模糊召回复用原导航预算
原文件导航 owner SHALL 通过同一 search 操作的显式 `fuzzy` 模式，按所选根内已解码相对文件路径进行大小写折叠的顺序字符召回。相同 query 的字符必须按顺序出现在同一路径字段中；不得使用 URI 的 Gateway／工作区标识或规范根前缀代替文件路径匹配。只返回文件，目录可参与路径匹配但不作为文件候选；不读取正文，不计算正文 hash。原 `path` 包含查询、`glob` 和 `content` 语义继续保持。

模糊查询 SHALL 复用原文件遍历、目标归属、独立 cursor、扫描节点／结果／响应字节预算与总 deadline。结果按原稳定遍历顺序分页，相关性评分交结果消费者完成；不先取无关前页再由客户端过滤冒充召回。达到扫描或时间上限时返回原 owner 的明确受限错误；已返回的部分页继续披露截断原因与 continuation，不伪称完整覆盖。取消调用沿原异步等待及 deadline 合同收尾，不声称可强行中断目标机器的原生阻塞 I/O。

#### Scenario: 首批之外的间隔字符缩写
- **WHEN** 根内首批无关文件之后的多层中文、大小写混合或 emoji 文件仅匹配顺序字符缩写
- **THEN** 仍能通过原 owner 的模糊查询和明确续页发现，结果只含精确文件 URI，不依赖正文读取

#### Scenario: 模糊查询预算与旧 cursor
- **WHEN** 模糊查询超过扫描／响应字节／时间预算，或 cursor 改用于另一模式、根或查询
- **THEN** 明确返回受限、截断或 cursor 失效事实，不伪报无匹配，也不改查其它目标

### Requirement: 目录与文件描述提供真实轻量观察值
原资源导航 owner SHALL 为本机实际文件与目录的 describe 结果提供真实节点类型、字节长度及毫秒时间戳；同一观察值可随 list/search 节点投影返回，不创建逐文件持久身份。describe MUST NOT 读取文件正文、计算全文 hash 或推进编辑器的内容 revision。无文件系统观察值的领域资源可以不提供 stat，不得用固定成功或虚假时间冒充实际文件。资源缺失、权限不足和目标归属错误继续使用原 owner 的错误合同。

工作台唯一文件内部投影 SHALL 保存稳定 Gateway／工作区归属、后端公布的规范根及相对子路径，并支持原 URI joinPath、relativePath 和往返定位。临时 route 不进入编辑器身份或恢复记录，执行前重新解析已登记目标；旧记录缺少可靠归属时明确不可恢复，不改投当前工作区。目录与正文读写 SHALL 消费同一原寻址／文件 owner；保存继续使用原内容 revision／CAS，轻量 stat 不代替写入基线。

#### Scenario: 从规范根拼接中文与字面百分号文件
- **WHEN** 原版编辑器从后端规范目录根拼接多层中文、空格、emoji 和字面百分号文件名
- **THEN** 内部投影可取得原相对路径，往返回到同一规范资源 URI，不丢失编码或混入其它根的同名文件

#### Scenario: 描述目录不读取正文
- **WHEN** 工作台在打开文本前 stat 真实目录根或非文本文件
- **THEN** 描述返回真实类型及文件系统观察值，不调用文本读取；不存在的目录明确失败，内容模型的写入基线不受 stat 影响

#### Scenario: 已登记 route 改变后保存
- **WHEN** 同一稳定 Gateway／工作区的 route 改变，或编辑器 stat 后后台文件正文改变
- **THEN** 编辑器身份保持不变、请求重解原 owner；保存仍携带实际读入正文的原 revision，不能借新 stat 接受覆盖冲突

### Requirement: 原文件预览复用私有条件缓存

普通工作区原文件预览的完整 raw GET SHALL 使用 `Cache-Control: private, no-cache` 和原 owner 的有效 ETag，允许浏览器／Chromium 私有缓存但每次复用前验证；替换该场景原 no-store 策略。适用范围 SHALL 由原资源读取能力决定，不仅限于图片；文字原字节与其它已接通原预览入口中的文件保持原 MIME 和原加载方式，不把所有对象强制转为文本或普通文件。文件 URI、返回字节、访问权限和原保存契约 SHALL 保持。附件、只读来源和 Diff 版本沿各自原读取／版本 owner，不为缓存绕过它们。显式下载、临时归档、Range 与错误响应 MUST NOT 因此开放完整资源缓存；其它 API 的缓存策略保持各自合同。Gateway 与 Electron 回环代理 SHALL 保持条件头、ETag、Vary、Cache-Control 及 304 语义，不另建文件内容缓存服务。

条件读取 SHALL 在原认证、目标路由与文件 owner 校验当前访问后比较 validator。未修改 SHALL 返回空正文 304，不重新完整读取或传输资源正文；变化 SHALL 返回当前字节与新 validator。validator SHALL 绑定稳定工作区、规范资源身份及当前版本观察值，Vary SHALL 覆盖该入口实际使用的工作区／后端身份请求头和认证头／Cookie，并合并已有字段，不按临时 route、标题或单独路径混用。304 SHALL 返回适用 validator、缓存策略、Vary 及本次网络读取的 request_id。stat ETag 不得冒充内容 hash 或保存 CAS；无有效 validator 时沿原读取，不能伪造恒定版本。强制刷新 SHALL 能绕过旧缓存重取原目标，不通过清全部存储实现。

#### Scenario: 普通图片二次打开无需重传正文
- **WHEN** 用户通过原图片编辑器首次打开远程图片，随后关闭再打开，资源版本未变且缓存仍存在
- **THEN** 原 FileService／Blob 编辑器保持，真实 Gateway 条件读取校验后不重传图片正文，图片从私有缓存字节解码；不能以单次显示成功或仅创建缓存目录代替证明

#### Scenario: 图片变化与旧保存基线独立
- **WHEN** 原 owner 的版本观察值随图片修改而变化，watch 通知刷新或用户再次打开
- **THEN** 取得新字节和 validator 并更新显示；未保存文本、文件保存 revision 与工作副本备份不被媒体缓存或校验推进，媒体内部 version 参数不成为业务版本

### Requirement: 原文件响应头沿同一 owner 提供 MIME

既有原文件 raw 入口 SHALL 同时支持 HEAD 和 GET，使用相同的身份、路径、权限与附件目录准入。HEAD SHALL 返回与 GET 一致的 MIME、原下载名称和字节长度，不传输正文、不推进文本保存 revision，也不建立另一份媒体元数据缓存。附件 original／preview 的 MIME 与名称 SHALL 来自原附件 catalog，不能根据固定物理名 `content` 猜测；derived 与普通文件保持原文件 owner 的 MIME 合同。必要的工作副本重建继续由原附件 owner 负责，不将 HEAD 作为复制引用或浏览候选的前置动作。

#### Scenario: 无扩展名附件按真实媒体类型重开

- **WHEN** 用户复制附件的规范 URI，关闭后从 Quick Open 重开图片、音频或视频原件
- **THEN** 读取原 owner 的响应头后选择原媒体编辑器；图片 Blob 与隔离 Webview 响应保留相同 MIME，原件字节和 Gateway／工作区归属保持，不能按 `content` 后缀落入文本编辑器

#### Scenario: 只读响应头不传输正文

- **WHEN** 调用者对原 raw 入口发起 HEAD
- **THEN** 返回同一原件 MIME、名称和字节长度、当前 request_id 及空正文；错误继续明确返回，不能借错误或缺少 MIME 假报成功
