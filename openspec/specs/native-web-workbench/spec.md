## Purpose

以完整 Code OSS Web 工作台提供文件编辑、分组、命令和设置行为，在原生 Thread 编辑器中复用既有 React 会话组件与会话资源，保持业务归属和后端权威一致。独立构建边界属于客户端入口与外层布局。

## Requirements

### Requirement: 完整原版 Web 工作台

客户端 SHALL 保留固定上游版本的原版 Web 布局、编辑器、命令面板、菜单、快捷键、设置与主题体系。

#### Scenario: 文件编辑和分组
- **WHEN** 用户单击、双击文件或标签并拆分编辑器
- **THEN** 原版预览替换、保持打开、拖拽及分组行为生效，编辑内容可以保存并重新读取

#### Scenario: 设置恢复
- **WHEN** 用户通过原版设置界面或设置 JSON 修改设置并重启客户端
- **THEN** 原版设置服务保存并应用值，文件内容和适用布局状态恢复

### Requirement: 独立且可复现的客户端

客户端 SHALL 具有独立目录、依赖、构建入口和样式，并以版本控制固定官方源码；构建运行 MUST 不依赖 reference_repo 或既有 web 的布局入口。

#### Scenario: 固定版本构建
- **WHEN** 检出项目及其固定源码依赖并执行客户端安装和构建
- **THEN** 生成完整工作台、必要 Worker 和资源，版本身份可核验，构建运行不依赖旧客户端布局入口

### Requirement: 精确 Thread 编辑器

客户端 SHALL 将会话导航接入资源管理器，将 Thread 作为原生编辑器类型，并将会话资源放在对应编辑器内部。业务数据 MUST 以 Gateway 转发的工作区后端为权威。

#### Scenario: 多 Thread 同屏
- **WHEN** 用户从资源管理器打开两个 Session 中的不同 Thread 并分屏
- **THEN** 预览、固定与分组沿用原版机制，历史、发送目标和会话资源保持各自精确 owner，焦点切换不改变其他组内容

#### Scenario: 关闭编辑器
- **WHEN** 用户关闭 Thread 标签
- **THEN** 只关闭展示，不删除 Thread、不停止其后端任务

#### Scenario: 请求失败
- **WHEN** 业务请求失败或 owner 不匹配
- **THEN** 界面明确展示错误，不以本地状态伪造业务成功
