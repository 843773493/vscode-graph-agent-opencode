# gateway-model-credentials Specification

## Purpose

将模型 API Key 的持久化集中到其所属 Gateway 的现有加密密钥库，让多个模型服务和工作区能够显式复用稳定引用，同时保留环境注入、真实错误和原执行边界。界面只管理引用与元数据，密钥不能随着配置、会话或普通展示存储扩散。

## Requirements

### Requirement: 模型密钥只能由所属 Gateway 持久化

模型 API Key SHALL 由工作区所属 Gateway 的密钥库加密保存，Workspace／Backend 不建立模型密钥库。普通模型配置只接受正式 `secret:sec_…` 引用或已有显式环境引用，不保存 API Key 字面量。解析后的值仅用于原执行或当前发现／测试请求的必要内存，不写入配置物化、会话、Trace、浏览器缓存、诊断或导出。已有 OAuth 及插件秘密维持各自 owner，不因此互换引用格式。

#### Scenario: 在工作区设置中新增凭据
- **WHEN** 用户为工作区的 Provider 新建并绑定 API Key
- **THEN** 值写入该工作区所属 Gateway，工作区配置只写引用；普通响应和重新打开的设置只显示元数据，不含正文

#### Scenario: 手工在普通配置填入密钥字面量
- **WHEN** 用户通过 JSONC 或普通配置 API 提交模型 API Key 字面量
- **THEN** 提交明确拒绝并指向原密钥创建／引用入口，不在来源保存后再偷偷抽取明文或伪称已加密

### Requirement: 密钥复用必须使用同一 Gateway 的稳定引用

多个 Provider／Model SHALL 能显式引用同一稳定密钥 ID；引用由真实所属 Gateway 解释，名称仅用于显示。Model 可继承 Provider 默认密钥或明确选择同 Gateway 另一密钥。系统 MUST NOT 按密钥正文自动去重、按同名条目改绑或跨 Gateway 自动复制；目标切换不得改变已发起管理操作的归属。

#### Scenario: 同一密钥供多个模型使用
- **WHEN** 两个 Provider 和各自的 Model 引用同一密钥 ID，随后用户重命名该密钥
- **THEN** 引用均保持，配置不复制密钥值，不因名称变化失效

#### Scenario: 远端与本地出现相同密钥名称
- **WHEN** 远端 B 和入口 A 各有名称相同的密钥，用户从 B Thread 进入模型设置
- **THEN** 只展示和管理 B 允许的密钥，失败不改投 A；跨目标复制配置不会自动复制密钥正文或寻找同名替代

### Requirement: 环境变量必须是明确来源而非隐式优先级

`${ENV_NAME}` SHALL 保留为由实际发出模型请求的目标 Workspace 进程解释的非持久化注入，界面必须说明环境归属。最终合并的引用指向 vault 就只读 vault，指向环境就只读该环境；缺失、解密失败或无权限 SHALL 详细报错，不自动切换来源，不读取浏览器或另一目标环境补值，也不将环境值导入配置或密钥库。

#### Scenario: 环境和密钥库中同时有可用值
- **WHEN** 模型明确选择密钥库引用，而进程环境中还设置了 API Key
- **THEN** 实际调用只使用选定引用；改为环境引用后才使用其环境值，不存在环境变量自动压过密钥库的规则

#### Scenario: 所选来源缺失
- **WHEN** 引用密钥不存在，或选择的环境变量在目标进程中未设置
- **THEN** 新执行明确失败并指出来源及稳定身份，不把引用字符串发给模型、不偷偷复用旧值或试另一来源

### Requirement: 定义读取与凭据使用必须分离

普通配置查看、列表和非秘密预检 SHALL 不以成功解析全部凭据、登录或构造模型客户端为前置。凭据状态 SHALL 区分未配置、已配置引用、已知缺失／无权限和未验证，不能将引用存在当成真实调用成功。模型执行在原允许的准备边界 SHALL 只解析选定 Agent 实际 primary／fallback 所需引用，并对重复 ID 去重批量获取，不逐模型、逐 Tab 或逐请求层重复解密。

#### Scenario: 失效密钥不妨碍修正定义
- **WHEN** 工作区存在一个失效凭据引用，用户打开设置修改其他模型参数
- **THEN** 定义仍可查看和编辑，错误与未验证状态准确显示；普通读取不因另一模型的密钥失效而返回虚假空列表

#### Scenario: 多模型复用密钥进入一个执行
- **WHEN** 一个 Agent 的 primary 与 fallback 中多次使用相同密钥引用
- **THEN** 该准备边界对实际所需密钥去重后批量解析，其他未使用 Provider 不被解密；后端不持久化解析结果

### Requirement: 改引用、轮换和删除必须具有不同效果

改用其他密钥 SHALL 只更新所选模型配置引用；更新共享密钥 SHALL 沿原 revision CAS 保持稳定 ID 并影响之后新执行。密钥 revision 变化必须使后续执行不再复用旧凭据的 runtime。正在执行的 Job 保持原快照，不强制中断或重建。

目录发现与快速测试 SHALL 在原请求边界冻结实际使用的 secret ID／revision，并仅在本次非秘密观察回执中返回该身份；普通定义读取不为此 resolve 或解密。结果只证明所示版本与时刻的调用，已知轮换／删除回执或显式元数据重读表明变化后标为过期，不在调用中再次 resolve、不自动重测或新增秘密变更轮询。没有收到外部变更通知时不得声称旧测试持续有效；临时 Key 与环境来源不计算秘密摘要或虚构 vault revision。

删除 Provider／Model MUST NOT 删除共享密钥。密钥删除 SHALL 是独立显式操作，说明后续引用会不可用，只报告原 owner 已知影响，不为此新增全局引用索引、扫描所有工作区或后台审计。删除后新执行不能使用缓存旧值冒充正常。

#### Scenario: 更新共享密钥后继续会话
- **WHEN** 共享密钥更新成功，旧 Job 仍在运行，随后发起一个新 Job
- **THEN** 旧 Job 保持，新 Job 使用新 revision 的值；其他引用同 ID 的模型在各自后续执行采用更新，不需要复制或修改每个模型配置

#### Scenario: 快速测试观察与密钥轮换并存
- **WHEN** 测试已按某 revision 发出请求，随后页面收到密钥更新回执或显式刷新发现 revision 已变化
- **THEN** 结果保留实际使用的旧 revision 及观察时刻并标过期，不能把其通过解释为新 Key 已测试；本次请求不重新解密、重发或写入正式 runtime

#### Scenario: 移除模型后独立删除密钥
- **WHEN** 用户移除一个 Model，之后再从密钥管理明确删除其曾引用的密钥
- **THEN** 前一步保留密钥；后一步分别反馈实际删除结果，其他引用它的新执行明确报缺失，不自动重建或换来源

### Requirement: 密钥写入与引用保存必须分别报告真实结果

前端 SHALL 通过短暂密码输入与原受保护写接口创建／更新密钥，只接收名称、稳定 ID、revision 和状态，不读取已存明文。创建密钥与保存配置引用使用各自 owner 和并发合同，不能伪装为跨 owner 原子事务。后续取消或配置保存失败不自动删除可能被复用的密钥，也不擅自重发未知写入或将目标换成本地。配置保存沿原 submission key 查询；vault 当前没有同等回执接口，不得宣称可查询密钥操作历史。

创建请求 SHALL 必填由客户端提交前生成并冻结的 `id: sec_<32hex>`，原 vault writer 原子拒绝已存在 ID；协议与所有客户端替换原随机分配链，不保留第二种创建方式，不比较正文实现去重。发出前原 Workbench 展示存储只保留原路由、secret ID 与操作种类。响应丢失后只显式读取原目标既有元数据列表：同 ID 存在可确认资源已创建并显示当前 revision，缺失或读失败保持未知；不能按名称找替代、回读秘密或自动重新 POST。

更新／删除 SHALL 继续以原 ID 和 revision CAS 提交；响应丢失时分别显示原结果未知和重读的当前状态，不能凭 revision 增加或当前不存在推断原操作已成功。用户明确基于新元数据发起的后续操作与原未知操作分开；恢复不保存秘密／摘要／整份请求，不新增操作账本、删除墓碑或后台轮询。

#### Scenario: 密钥创建成功但绑定冲突
- **WHEN** 新密钥已创建，配置引用保存因 CAS 冲突被拒绝
- **THEN** 明确显示密钥已创建、引用尚未保存，保留可处理的非秘密草稿与元数据，不假报全部成功、回显明文或自动删除密钥

#### Scenario: 创建已落盘但响应丢失
- **WHEN** 原目标已创建客户端预先确定 ID 的密钥，但前端未收到响应，随后重新打开管理入口
- **THEN** 只读原目标元数据并按该 ID 确认当前资源，显示 revision 后允许明确选择绑定；没有第二次 POST，不按名称或秘密匹配

#### Scenario: 更新或删除的响应丢失后发生并发修改
- **WHEN** 密钥更新／删除没有回执，重读时 revision 已改变或该 ID 已不存在
- **THEN** 展示当前事实且保留原操作未知，不将其他窗口的更改当成原提交成功，不自动重放写入或借配置回执查询 vault

### Requirement: 草稿发现与测试允许短暂凭据但不能扩大持久化边界

尚未创建密钥的草稿发现／测试 SHALL 能通过独立短暂密码输入和受保护请求的 `credential_input` 使用当前 Key，不要求先保存密钥或模型配置。此输入只允许用于明确标为 draft 的当前连接，不能进入普通 JSONC、通用文本模型、请求日志、会话、Trace、诊断导出或浏览器持久存储；请求结束后不在服务端另建临时秘密缓存或持久 handle。关闭／取消表单或切换目标 SHALL 清理前端输入，结果和迟到响应不得暴露正文。

选择已有 vault 或环境引用 SHALL 仍使用原 owner，仅解析当前连接所需凭据；缺失不尝试另一来源。active 测试不能夹带临时 Key。草稿测试成功不创建／更新 vault、不替换其他模型引用；用户明确保存时才沿原密钥写入与来源引用保存链反馈结果。

`credential_input` SHALL 包含 scope、provider_id、可选 model_id 及短暂 value。provider scope 禁止 model_id，替换本次内存副本的 Provider defaults.api_key；model scope 必须有 model_id，替换该 Model overrides.api_key。对象必须属于本次选择，替换后先完成正常继承再解析最终唯一凭据；已被替换的引用不得先行解析。Provider 临时输入不压过 Model 显式覆盖；输入未实际成为本次有效凭据时 SHALL 网络前拒绝并指出覆盖来源，不静默忽略或测试另一把 Key。Provider 发现只允许对应 provider scope，active 与 OAuth 模式拒绝此输入；保存时沿同一绑定位置写入新 vault 引用。

#### Scenario: 新 Key 测试后取消创建
- **WHEN** 用户在 B 的新连接表单输入 Key，完成自动发现或显式测试后取消
- **THEN** 仅 B 对应请求在内存中使用 Key，vault 和配置均未新增；输入被清理，浏览器持久存储及普通日志／错误详情中没有正文

#### Scenario: 已有失效引用不能借临时输入冒充 active
- **WHEN** 用户选定 active 测试而该引用失效，或者为草稿明确输入另一个 Key
- **THEN** 前者按所选引用明确失败；后者仅作为 draft 测试并标明身份，不静默改写 vault 或将草稿结果显示为 active 已恢复

#### Scenario: 草稿以新 Key 替换失效引用
- **WHEN** 原配置引用的密钥已失效，用户为同一有效凭据字段明确提供临时 Key 并测试 draft
- **THEN** 先在本次内存副本替换，再解析实际凭据，不查询失效旧引用；使用新 Key 的请求不写 vault 或污染 active runtime

#### Scenario: Model 覆盖不能被 Provider 临时 Key 绕过
- **WHEN** Model 已显式使用另一密钥，而测试请求仅提供 Provider 范围临时 Key，或绑定了另一 Model
- **THEN** 网络前明确拒绝未生效或不匹配的临时输入，显示真实覆盖位置；不会悄悄使用 Model 旧 Key 并把成功归因于新输入
