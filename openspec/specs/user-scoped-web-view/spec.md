# user-scoped-web-view Specification

## Purpose
为每个 Gateway 用户保存独立的 Web 视图和会话阅读位置，使用户在同一 Gateway 的不同电脑之间恢复自己的界面，同时避免不同用户共享主题、布局和历史浏览状态。
## Requirements
### Requirement: 用户视图隔离

Web 前端 SHALL 根据当前 Gateway 用户加载主题、布局、当前工作区、当前会话和会话阅读状态；不同普通用户之间不得共享这些视图状态。

#### Scenario: 切换普通用户

- **WHEN** 当前客户端退出用户 A 并选择用户 B
- **THEN** 前端使用用户 B 的视图状态替换用户 A 的状态，不得继续显示用户 A 的主题、布局或会话阅读位置

#### Scenario: 共享功能配置不随用户切换

- **WHEN** 用户在同一 Gateway 中切换普通用户
- **THEN** Gateway 和工作区的功能配置保持一致，用户切换只影响用户视图和个人偏好

#### Scenario: 用户草稿隔离

- **WHEN** 两个普通用户在同一工作区和同一会话中分别编辑 Composer 草稿
- **THEN** 草稿按 `user_id` 隔离；游客草稿只存在当前页面内，不写入持久化浏览器存储

### Requirement: 会话阅读位置恢复

系统 SHALL 为用户和工作区会话保存历史阅读锚点、锚点偏移、是否跟随最新消息和历史投影版本；恢复时必须优先按稳定 Turn 锚点定位，而不是仅恢复原始像素滚动值。

#### Scenario: 切换回已浏览会话

- **WHEN** 用户在会话中加载更早历史并切换到另一会话后再切回
- **THEN** 前端恢复该用户在原会话的可见 Turn 附近和阅读模式，不默认跳到尾部

#### Scenario: 更换电脑访问同一 Gateway

- **WHEN** 用户在电脑 A 退出后，在电脑 B 选择同一个普通用户并打开同一会话
- **THEN** 电脑 B 从 Gateway 读取该用户的会话视图状态并恢复对应阅读位置

#### Scenario: 锚点已不可恢复

- **WHEN** 保存的 Turn 锚点因投影变化或历史清理无法直接加载
- **THEN** 系统选择明确的最近可用位置或尾部位置，并向前端报告恢复结果，不得静默伪造原位置

### Requirement: 新消息与阅读位置共存

系统 SHALL 在用户不跟随尾部阅读时保留其阅读位置；新消息到达时可以更新会话摘要和未读提示，但不得强制滚动当前阅读位置。

#### Scenario: 阅读旧历史时任务完成

- **WHEN** 用户停留在旧历史位置且该会话产生新的完成事件
- **THEN** 前端保持当前阅读位置并显示新消息或任务完成提示

#### Scenario: 用户跟随尾部

- **WHEN** 用户处于跟随最新消息模式且当前会话产生新输出
- **THEN** 前端继续跟随尾部并更新当前会话内容
