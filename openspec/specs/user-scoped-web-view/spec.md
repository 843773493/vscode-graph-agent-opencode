# user-scoped-web-view Specification

## Purpose
浏览器展示状态由现有本地存储与 Workbench profile 持有，按 Gateway、工作区、Session、Thread 及窗口或编辑器归属隔离，不依赖已退役的 Gateway 用户体系。
## Requirements
### Requirement: 浏览器视图隔离

前端 SHALL 复用既有 IndexedDB 和 Workbench 存储保存主题、布局、Composer 草稿、折叠和阅读状态，工作区与会话状态使用完整稳定 owner。阅读与折叠状态 MUST 属于当前客户端安装／浏览器配置；相同 Gateway、工作区、Session 和 Thread 的业务身份可以共享，不意味着 Web、Electron、移动端或其它浏览器共享阅读游标。首次使用采用产品默认值，不从后端导入其它客户端展示状态。

#### Scenario: 切换工作区或 Thread
- **WHEN** 用户在同一客户端切换 Gateway、工作区或 Thread
- **THEN** 按各自完整 scope 恢复视图和草稿，不混入其它 owner 数据

#### Scenario: 两个客户端独立阅读
- **WHEN** 浏览器 A 阅读同一 Thread 的 Item X，另一个独立客户端阅读 Item Y
- **THEN** A 的滚动、折叠、刷新和重新打开不改变另一客户端的位置；后端更新只同步业务内容，不下发 A 的阅读状态

#### Scenario: 新浏览器访问
- **WHEN** 没有该站点本地数据的浏览器访问相同 Gateway
- **THEN** 使用默认展示状态，不从 Gateway 用户视图或另一客户端恢复阅读偏好

#### Scenario: main 别名解析与 fork
- **WHEN** 用户以 main 入口打开或 fork 后进入新 Thread
- **THEN** main 先解析为权威真实 Thread ID，再按完整 scope 读写本客户端视图；fork 使用新 owner，不继承来源阅读位置或跨客户端偏好。

### Requirement: 会话阅读位置恢复

前端 SHALL 保存稳定来源＋展示 slot、客户端内内容位置、相对视口偏移、follow_latest、折叠选择和阅读格式版本。已提交内容的来源 MUST 只引用真实 `item_id`，不包含 `part_id`、Part ordinal、DOM 下标或展示父容器；标题与上下文标记继续引用原过程／组首 Item／消费边界。长正文的块号与局部偏移仅为当前渲染器的内容内位置，不升级为后端实体、URI 或业务操作边界。

恢复 SHALL 先应用折叠状态，再沿原 owner 有界加载 Item 及其可见祖先；普通恢复不强制展开，显式 Item 跳转遵循原展开规则。宽度、折叠和分页改变时保持相同内容附近，不依赖绝对 scrollTop 或整轮像素偏移。follow_latest 与锚点保位互斥，用户主动滚动或取消后停止旧定位补偿。

未提交 draft SHALL 只在当前编辑器临时定位，持久记录使用可恢复的真实过程来源和跟随模式；实际提交后按来源关联替换，不伪造持久 Item。支持来源的旧阅读记录只有能确证 Item 对应关系时才能转换；未支持格式保留原记录并明确恢复受限，不删除全库或静默丢弃 Part 坐标后宣称精确恢复。

#### Scenario: 返回已浏览 Thread
- **WHEN** 用户返回同一客户端已浏览的 Thread
- **THEN** 恢复该 scope 的 Item、折叠和跟随模式，不默认跳尾；单个长文本内使用本地内容位置恢复附近内容

#### Scenario: 目标位于折叠组内
- **WHEN** 所读 Item 被过程或活动组收起
- **THEN** 定位最近真实可见祖先，保留目标 Item 身份，不自动展开或误选同名兄弟内容

#### Scenario: 宽度或内容高度变化
- **WHEN** 上方插入上下文虚线、final 内容移出过程区、图片增高或宽度重排
- **THEN** 保持原 Item／slot 附近阅读位置，不重新选视口外目标；final 容器变更不改变内容 Item 节点键

#### Scenario: 虚拟列表尚未挂载
- **WHEN** Item 因分页或虚拟列表尚未成为 DOM 节点
- **THEN** 沿原分页／虚拟列表入口有界加载并挂载，不能判为已删除、全量拉历史或定时无限重试

#### Scenario: 锚点已不可恢复
- **WHEN** 原 owner 确认 Item 不可见、已删除、无权限、过期，或请求遭遇网络／服务故障
- **THEN** 区分真实结果；普通恢复明确说明受限并选择声明的可用位置，显式跳转报告目标结果，网络错误不能伪装成目标删除或空成功

#### Scenario: 流式 Part 尚未持久提交
- **WHEN** 当前阅读来源仍为未提交的流式 draft
- **THEN** 仅在编辑器内临时定位，持久记录使用可恢复过程来源；真实提交沿明确来源关联接续，不保存 Part 或伪造 Item ID。

### Requirement: 新消息与阅读位置共存

用户阅读旧历史时 SHALL 保持其位置并展示新消息提示；跟随最新消息时继续跟随输出。

#### Scenario: 阅读旧历史时收到新输出

- **WHEN** 新消息到达且用户未跟随尾部
- **THEN** 保留当前位置和阅读模式

#### Scenario: 跟随尾部收到新输出

- **WHEN** 用户处于跟随最新消息模式
- **THEN** 更新内容并继续跟随尾部

### Requirement: 统一定位入口区分未显示与真实不可用

所有阅读恢复和明确跳转 SHALL 经同一定位入口处理，区分精确目标、折叠祖先、尚未加载／挂载、已确认不可用及实际失败。没有 DOM 节点 MUST NOT 被直接视为业务删除；虚拟卸载不删除阅读记录，缺页经原 owner 有界取得。相邻位置只用于已经确认不可用的普通恢复，显式目标不存在或无法精确定位 SHALL 明确失败而不以另一对象冒充成功。超时、归属／权限拒绝、数据损坏、不支持的格式及其它 I/O 故障 SHALL 传播原原因并保留记录，不转换为不存在，不自动跳最新或相邻对象。结果处理不得新增全局异常服务、第二业务 owner 或持久恢复账本。

#### Scenario: 折叠和虚拟卸载都导致 DOM 查找为空
- **WHEN** 目标未出现在 DOM，但原展示关系表明它被折叠，或虚拟列表尚未挂载该项
- **THEN** 前者按恢复／显式跳转规则处理祖先，后者挂载真实目标；两者都不报告资源删除或丢弃锚点

#### Scenario: 缺页加载发生超时
- **WHEN** 恢复目标所在页尚未加载且原 owner 请求超时
- **THEN** 明确返回实际加载失败及已有请求身份，原记录和当前可用内容保留，不宣称目标不存在或通过滚到其它位置报成功

#### Scenario: 资源存在但目标 Part 已不可用
- **WHEN** Item 仍可见，但原投影确认所需 Part 或展示部位已不存在
- **THEN** 普通恢复可以定位该 Item 的可见标题并说明原位置未恢复，显式 Part 跳转明确报告目标不可用，不把另一 Part 作为精确命中

#### Scenario: 无 Turn 的独立回报
- **WHEN** 显式 Item 定位指向内部 execution 的独立展示回报
- **THEN** 使用回报真实的 notice 部位完成定位，不要求合成 Turn 或等待不存在的 body 节点

#### Scenario: 规范 Item URI 指向无 Turn 的内部执行
- **WHEN** 用户通过规范 Item URI 打开内部执行中的 Item
- **THEN** 原 Opener 核验该 Item 的真实位置并交原 Thread 定位入口，不因缺少 turn_id 自动改为查看原文；缺少已核验位置或读取期间身份失效时明确拒绝，不打开替代对象

#### Scenario: 恢复内部执行的早期分段标题
- **WHEN** 保存的标题指向尚未加载的早期分段，而当前窗口仅包含同一 execution 的尾段、独立回报或空过程标题
- **THEN** 使用原标题 slot 中真实段首 Item 沿原 around 入口定点读取；同 execution 的其它展示节点不算该分段已加载，不读取执行尾页代替原段，也不遍历全部历史或新增持久坐标

#### Scenario: 节点类型或来源格式无法识别
- **WHEN** 阅读记录引用当前版本无法解释的节点来源或坐标格式
- **THEN** 明确说明格式不支持并保留记录，不猜测来源、不当成资源已删除，也不扫描其它 owner 寻找替代

#### Scenario: 执行正文被回收但分段标题仍在
- **WHEN** 恢复的 execution 分段标题仍由当前投影提供，但隐藏正文已被内存回收
- **THEN** 直接定位标题，不为恢复标题重读正文；原空过程标题已被真实分段替换时明确报告旧位置不可用，不等待不存在的节点

#### Scenario: 上下文标记位于元数据首128项之外
- **WHEN** 用户已读到后续消费请求的标记并保存位置，刷新后的初始元数据页没有该标记
- **THEN** 按同一过程内真实 model_call_id 与 anchor 类型经原 history owner 定点读取，不扫描元数据续页；目标存在则挂载原标记，不存在则交付带请求身份的不可用结果并保留原记录

### Requirement: 折叠记忆与多个编辑器的运行位置分离

每个已打开编辑器 SHALL 保持独立运行中的阅读／折叠状态。同一 Thread 的持久默认记录由最后实际交互的编辑器保存，程序性挂载与恢复不抢写；其它窗口收到存储通知不得自动移动已打开视图。用户关闭再打开时恢复该 Thread 最后保存的展示状态，虚拟化卸载不清空折叠选择。逐项折叠状态 SHALL 只有一个展示 owner，不保留多个同义局部或全局布尔值。

#### Scenario: 同一 Thread 在两个编辑器中阅读
- **WHEN** 用户在编辑器 A 展开工具并滚动，而编辑器 B 停留在另一条内容
- **THEN** B 不被强制同步滚动或开关；新打开该 Thread 可以恢复 A 最后实际交互后保存的位置

### Requirement: 视图格式变化不得清除其它本地数据

阅读格式 SHALL 使用原视图 owner 的既有投影版本登记，仅当持久记录结构或节点来源／展示部位／坐标语义不兼容时评估受支持来源的版本及转换；新增节点类型、普通行增删或保持坐标不变的组件／样式调整不得自动触发格式迁移。转换仅归阅读展示记录 owner，Item、上下文、附件等业务数据仍归各自 owner；不得为开发中间态自动保留旧新两套 reader。未知或不支持的视图格式、记录损坏和 IndexedDB 故障 SHALL 明确报告且保留原记录，不伪造恢复成功，不通过清空数据库、Storage 或 Electron 存储来修复。Composer 草稿、消息 outbox、凭据、附件上传和其它设置不得受阅读格式更新影响。

#### Scenario: 发现不支持的旧阅读记录
- **WHEN** 新客户端读到没有受支持转换合同的旧格式记录
- **THEN** 明确表示原位置未恢复并保留原件，其它业务可正常打开；后续用户实际浏览按新格式保存，不运行猜测转换或清空共享存储

#### Scenario: 新增展示类型但坐标合同未变
- **WHEN** 客户端加入一种数据卡片或改变布局，既有节点身份与阅读记录结构不变
- **THEN** 既有阅读记录直接继续使用，不提升格式、不执行数据库转换或为每个节点新增迁移代码

#### Scenario: 节点身份语义发生不兼容变化
- **WHEN** 修改持久 source_ref／slot 含义或阅读记录结构，使已支持来源的坐标不再等价
- **THEN** 原视图 owner 登记明确目标版本并按真实支持来源提供必要转换或不支持结果，不伪造精确位置，也不接管业务数据库迁移
