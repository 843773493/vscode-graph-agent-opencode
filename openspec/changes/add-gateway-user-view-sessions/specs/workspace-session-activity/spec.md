## Purpose

为工作区内所有会话提供轻量、可持久化和可追赶的活动通知，使未打开会话的 Agent 完成、失败或状态变化能够及时反映到不同用户的会话列表，而不需要加载完整历史。

## ADDED Requirements

### Requirement: 工作区级会话活动事件

工作区后端 SHALL 为会话状态变化生成带单调递增游标的轻量活动事件；事件至少包含会话 ID、事件类型、摘要状态、发生时间和可用于去重的事件 ID。

#### Scenario: Agent 完成

- **WHEN** 工作区中的 Agent 任务完成
- **THEN** 工作区后端持久化该会话的完成摘要事件，并使其可以被工作区级事件读取接口获取

#### Scenario: 未打开会话产生事件

- **WHEN** 事件所属会话不是当前前端打开的会话
- **THEN** 前端仍可以只依据该活动事件更新会话列表和未读提示，不需要加载该会话的 Turn 历史

### Requirement: 工作区事件流和断线追赶

系统 SHALL 提供经 Gateway 透明代理的工作区级活动事件读取和 SSE 流；客户端必须可以使用最后收到的事件游标补取断线期间的事件。

#### Scenario: 实时接收活动

- **WHEN** 前端通过 Gateway 订阅当前工作区活动流且工作区产生新事件
- **THEN** 前端在不切换当前会话的情况下收到该事件并更新对应会话摘要

#### Scenario: 断线后补取

- **WHEN** 客户端带最后事件游标重新连接
- **THEN** 工作区后端返回游标之后的所有可用活动事件，并避免同一事件重复造成错误状态

#### Scenario: 游标不可用

- **WHEN** 客户端游标已超过保留范围或对应投影已失效
- **THEN** 服务返回明确的游标失效结果，前端重新获取工作区会话摘要，不得静默跳过事件

### Requirement: 活动事件不泄漏完整内容

工作区级活动事件 SHALL 只包含会话列表和未读提示所需的摘要，不得因为后台通知自动传输完整用户消息、工具结果或 rollout 内容。

#### Scenario: 收到工具任务完成

- **WHEN** 未打开会话中的工具任务完成并生成活动事件
- **THEN** 活动事件只包含完成状态和摘要信息，完整工具调用和结果仍在用户主动打开会话后按历史加载策略读取
