## Purpose

使公共模型价格和能力目录能够在外部网络缓慢或不可用时继续提供上次已验证的数据，并在后台有界刷新。模型请求的业务期限不得被导入期的目录下载无限占用，成功刷新应供后续请求与进程复用。

## ADDED Requirements

### Requirement: 本地优先与有界前台等待

系统 MUST 从唯一运行时入口加载模型 SDK，首次导入不得同步下载远程目录。系统 SHALL 优先采用匹配来源的上次成功缓存，无有效缓存时使用安装包内置目录。前台等待刷新默认不超过一秒网络等待预算；超过预算 SHALL 使用已有目录，后台任务继续受独立总期限约束。SDK 本地导入耗时不属于网络等待预算。

#### Scenario: 远程目录迟到
- **WHEN** 远程目录在前台预算内尚未返回
- **THEN** 当前调用使用旧目录返回，后台继续刷新，后续请求可以采用经校验的新目录

#### Scenario: 远程目录持续不可用
- **WHEN** 后台总期限耗尽或有限重试失败
- **THEN** 保留已有目录并明确记录失败原因，后续按退避期限重试，不改变模型请求本身的错误归属

### Requirement: 已验证缓存与模型注册保持

系统 MUST 在完整校验刷新结果后原子写入按来源隔离的用户级缓存。损坏或无效缓存 SHALL 明确记录并使用内置目录。刷新 MUST 保留用户显式模型注册和 Provider 能力覆盖，失效旧目录查询缓存；不得改写已构造请求、封存历史或会话数据。

#### Scenario: 刷新与下次启动
- **WHEN** 后台成功保存新目录后进程重新启动
- **THEN** 在无远程服务时仍可从相同来源缓存读取该目录

#### Scenario: 自定义能力与无效响应
- **WHEN** 进程已有自定义模型能力，刷新收到有效目录或无效正文
- **THEN** 有效目录采用后自定义能力仍保持，无效正文不能替换当前目录或成功缓存

### Requirement: 唯一刷新及明确本地模式

Chat、Responses、Embedding、认证能力注册和回放 MUST 复用同一加载入口；并发调用 MUST 共享一个刷新任务。显式本地模式 MUST 禁止远程刷新，沿用 SDK 官方本地目录行为。后台刷新不得占用业务模型回放 transport。

#### Scenario: 并发首次调用
- **WHEN** 多个线程同时准备模型 SDK
- **THEN** 只启动一次目录刷新，所有调用仍可使用现有目录

#### Scenario: 本地回放模式
- **WHEN** 显式启用官方本地目录开关并运行同步或异步模型回放
- **THEN** 不发起目录网络请求，原模型请求参数和回放身份保持不变
