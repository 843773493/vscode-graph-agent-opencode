## Purpose

为多目标 Agent Harness 提供清晰且可发现的 Workbench 管理入口，区分客户端、Gateway、共享配置来源、工作区和会话资源；保证默认本地管理、显式远端选择与多编辑器操作归属，避免入口重组产生第二套状态和配置体系。

## ADDED Requirements

### Requirement: 管理入口初次默认本地且远端选择必须显式

管理入口 SHALL 初次选择当前入口 Gateway 的本地目标，持续展示目标名称与必要身份；“本地”指入口 Gateway 所在运行环境，不能按浏览器地址、SSH 转发端口或浏览器机器推断。用户在当前管理入口显式选择远端后 SHALL 保留该入口的展示选择，其他管理页或远端 Thread 焦点不得改写它。新启动默认仍为本地；已恢复的目标化编辑器必须保留原 owner，不受入口默认值影响。

Provider／Agent／工具等需要 Workspace owner 的全局管理入口，SHALL 在该入口所选 Gateway（初次本地）的候选范围内默认首个已登记工作区，并在切回 Gateway 时恢复本入口上次选择；通过联动下拉调整工作区，再按需选择来源。不能用焦点 Thread 或导航 activeId 补齐 owner，也不能为了进入页面自动创建／激活工作区。对象入口已传精确 owner 时使用该参数，不重复选择或改全局默认。

#### Scenario: 远端 Thread 获焦后首次打开管理
- **WHEN** 入口为 A，焦点 Thread 属于远端 B，用户首次从全局入口打开设置、插件或目标管理
- **THEN** 管理入口选择 A 本地并显示归属，不因 B 获焦就请求其设置；用户明确切换后才访问 B

#### Scenario: SSH 转发访问与远端不可用
- **WHEN** 用户通过浏览器机器的转发端口访问 A，或已选择的 B 离线
- **THEN** 本地仍指 A；B 页面保留其目标与离线原因，不把请求改投 A、不自动启动或重连目标

#### Scenario: 本地 Gateway 尚未选择工作区
- **WHEN** 远端 Thread 正获焦，用户首次从全局命令进入 Provider／Agent／工具管理
- **THEN** 在本地 Gateway 范围默认首个已登记工作区并显示选择，不借远端焦点；用户可直接从下拉调整，无重复工作区弹窗；没有候选时展示原状态与创建／注册入口，不自动注册工作区

### Requirement: 管理范围与资源 owner 必须分离

界面 SHALL 区分客户端设置、Gateway 配置、Workspace 用户来源及其共享影响范围、具体工作区覆盖、Session／Thread 的选择与运行状态。后台进程不是工作区，一个 Backend 管理多个工作区时其生命周期操作 SHALL 显示实际受影响工作区。用户级 Workspace 来源的作用域 SHALL 根据原配置 owner 报告的共享来源确定，不能虚构成每个 Backend 独享或仅影响新工作区；插件新建工作区默认值保持其独立语义。fan-out 汇总 SHALL 标明仅覆盖原来源 owner 已观察到的消费者，管理列表不能充当完整消费者清单；停机／不可见消费者的应用事实未知，已有合同允许时说明下次启动追赶，不伪称全部同步。

#### Scenario: 修改共享用户来源
- **WHEN** 用户编辑多个工作区共同使用的 Workspace 用户来源
- **THEN** 界面在保存前说明共享来源及已知范围，结果标为 owner 已观察到的消费者及逐工作区应用事实；未观察到或停机消费者不报告已生效，不冒充当前工作区私有修改或全部立即生效

#### Scenario: 重启共享 Backend
- **WHEN** 两个工作区共用一个 Backend，用户从其中一个工作区进入重启操作
- **THEN** 展示同一进程的受影响工作区，复用原生命周期操作，不为每个工作区重复启动或重启同一进程

### Requirement: 全局管理与资源操作必须保持独立目标

从对象上下文打开管理详情 SHALL 使用发起对象的明确 owner 并显示范围；全局管理选择不能改变既有详情、脏草稿或运行操作的归属。异步结果、保存及错误重读 SHALL 绑定发起时目标；目标或授权失效时明确终止，不猜测同名替代对象。仅需展示／配置的入口 MUST NOT 为发现数据隐式启动 Backend、插件或模型请求。

#### Scenario: 远端草稿与本地入口并存
- **WHEN** B 的设置 Tab 有脏草稿，用户将管理选择切到 A 并打开 A 的同名配置
- **THEN** 原草稿继续属于 B，A 使用不同目标的编辑器输入；保存和失败重读只访问各自 owner，不将 B 的草稿写入 A

#### Scenario: 从远端对象进入管理
- **WHEN** 用户从 B Thread 的模型选择器打开其 Provider 详情，随后切换导航工作区
- **THEN** 详情明确显示 B 原工作区及来源，后续操作继续属于该对象，不修改全局本地默认或新导航目标

### Requirement: 管理能力必须可从原版 Workbench 入口发现

产品 SHALL 为已支持的管理能力提供具有一致名称的命令及适当菜单、视图标题或上下文入口，遵守原版键盘、焦点、预览／固定、分屏和编辑器恢复习惯。简单选择使用选择器，参数使用设置，复杂实体使用列表与详情；同一对象由不同入口到达时保持同一业务身份。客户端外观不应要求用户先进入 Gateway 连接管理。

对象上下文命令 SHALL 显式传递稳定 Gateway／Workspace，必要时带来源、实体或 Session／Thread 身份，在首个 await 前捕获参数及路由；后续焦点变化不能重定向。ContextKey 仅沿原视图／编辑器作用域控制菜单显隐与可用性，不充当权威 owner 或服务端授权。无参数全局管理命令沿上文选择流程，直接命令调用仍核必要参数；表单字段直接编辑原模型，不逐字段注册命令或另建命令派发层。

#### Scenario: 无会话时配置模型
- **WHEN** 新用户尚未创建 Session，从欢迎入口或命令面板选择模型 Provider 管理
- **THEN** 可以进入本地目标的配置流程，不要求先打开 Composer 或创建虚假会话；Backend 未就绪时显示其真实状态、原因和原启动／连接入口，就绪后才读取 Workspace 来源，不显示虚假空列表或静默启动服务

#### Scenario: 配置错误阻断 Backend 初始化
- **WHEN** 本地目标因配置错误无法初始化，用户从欢迎入口进入 Provider 管理
- **THEN** 保留目标身份并定位原可取得的启动错误，提供既有配置工具的处理指引；不放松初始化校验、不让 Gateway 代读工作区配置，也不伪装成可保存的配置页

#### Scenario: 同一实体多个入口
- **WHEN** 用户分别从命令、树的上下文菜单和会话内选择器打开同一个 Agent／Provider
- **THEN** 这些入口到达同一 owner 的管理能力，不出现独立保存的第二份业务对象

#### Scenario: 菜单命令等待期间焦点改变
- **WHEN** 从 B 对象的上下文菜单调用管理命令，异步读取期间焦点切到 A
- **THEN** 读取／保存继续使用传入的 B 身份和发起路由；ContextKey 更新不替换参数，直接调用同一命令仍经过原业务准入

### Requirement: 界面容器必须遵守业务资源归属

左侧侧边栏 SHALL 提供 Gateway、连接、工作区导航等控制面入口；底部面板 SHALL 按当前工作区展示终端、输出、端口、浏览器和自动化等运行资源，客户端原版工具仍保留其本来语义；精确 Thread 的文件、更改、任务与运行关联资源 SHALL 保留在对应 Thread 编辑器中。全局辅助侧边栏的 Agent 设计保持 TODO，不为填充入口复制会话资源。复杂管理详情可在主编辑区打开，不改变资源所有权。

目标／工作区节点与现有会话树 SHALL 共用同一工作区导航事实和激活操作；管理目标选择仅是各管理页的展示选择，不另建一套“当前工作区”。打开目标管理详情不能自动切换会话树，显式激活工作区才更新原导航状态。

#### Scenario: 工作区与 Thread 焦点不同
- **WHEN** 底部面板当前工作区是 A，用户在分屏中查看 B Thread 的资源
- **THEN** 底部操作明确属于 A，B 的会话资源仍属于 B；打开详情不会隐式搬移其 owner

#### Scenario: 目标管理与会话导航共存
- **WHEN** 用户从导航中的 B 工作区打开管理详情，再显式激活 A 工作区
- **THEN** 打开详情时不隐式激活 B；显式激活 A 仅通过原导航动作更新会话树及底部面板，B 的详情仍保持原 owner，没有另一套工作区选中状态

### Requirement: 支持状态必须真实且客户端实现保持一致

管理能力 SHALL 区分可用、只读、无权限、目标离线及尚未支持，并说明原因和已有替代入口；不以禁用占位按钮、静态示例或成功通知冒充业务完成。Web／Electron SHALL 共用界面与网络／文件 URI 链路，客户端配置档案不得解释成旧 Gateway 用户档案；显示语言保持默认中文、内置英文、切换重载。

#### Scenario: 尚未具备的系统能力
- **WHEN** 用户查看系统密钥链、云同步或尚无 owner 的存储维护能力
- **THEN** 不伪造可用操作或成功状态，不引入原生 IPC、旧账户体系或浏览器直接读远端目录作为替代

### Requirement: 管理入口遵循原版活动栏与菜单

活动栏搜索 SHALL 打开原内容搜索侧栏，活动栏扩展 SHALL 打开扩展侧栏并保留当前编辑器；左下管理齿轮 SHALL 先弹出原管理菜单，Ctrl+, 仍直接打开 Settings，不用原型按钮重做这些原入口。Settings SHALL 提供“模型与 Provider”入口及模型、Provider、API、密钥的说明，进入相同来源 Settings／JSONC 模型和保存流程，不生成第二份 Provider 配置或草稿。

#### Scenario: 原生入口与窄窗口
- **WHEN** 用户在 685px 窗口打开扩展并单击插件，然后使用 Ctrl+Shift+F 或管理菜单
- **THEN** 扩展列表停靠主侧栏，详情占用原编辑器 Tab；搜索仍进入搜索侧栏，管理齿轮先显示原菜单，不因窄窗口把列表变成覆盖层或自动关闭
