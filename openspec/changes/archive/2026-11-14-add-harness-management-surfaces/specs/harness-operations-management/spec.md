## Purpose

把多目标 Agent Harness 已有运行、插件、任务、诊断和资源功能组织成可发现的 Workbench 管理体验，保留各领域状态与生命周期 owner；对缓存、统计和维护明确能力边界，并用真实入口验证正确归属和有界交互成本。

## ADDED Requirements

### Requirement: 插件与 MCP 管理必须保留交付运行和连接的区别

插件入口 SHALL 按插件包分组安装、更新和卸载，按具体插件的 Gateway／工作区范围启停，实例用于查看状态、错误、日志及原重启操作；新工作区默认值不修改现有工作区。MCP SHALL 复用已有列表、详情、连接和授权入口，区分插件实例状态与工作区 MCP 连接状态。安装不等于启用、进程 ready 不等于 MCP 目录可用、停止一个连接不等于关闭其他工作区实例；自有下载源不转向 VSIX 或第三方市场。

#### Scenario: 同包插件与双工作区实例
- **WHEN** 用户停用开发工具包中的浏览器插件，而终端插件及另一工作区实例仍在使用
- **THEN** 仅按选定插件和范围执行原控制，显示真实状态；更新新工作区默认值不改写既有工作区

### Requirement: 运行资源和持续任务必须沿原控制语义接入

管理入口 SHALL 可达已有终端、浏览器、端口、源码调试、持续任务及 Goal 操作，详情展示 owner、可用动作、运行／等待原因和已有记录。会话 Goal SHALL 保留新建开始、编辑、暂停、继续、重新开始、删除及预算／用量；工作区任务继续由自动化管理。关闭视图／Tab 不删除资源或停止执行，暂停 Goal 不冒充打断当前轮次。源码调试只暴露已有调试器支持，不将 DAP 接入解释为任意语言可调试；原版构建 Tasks 不替代持续任务调度。

#### Scenario: 从关联任务进入自动化
- **WHEN** 用户从 Thread 查看关联任务，再从工作区自动化打开同一任务
- **THEN** 显示同一权威任务及真实可用操作，无第二 Goal 状态或复制调度；关闭任一视图不改变运行状态

### Requirement: 移除控制面注册必须保持原生命周期及数据边界

工作区移除 SHALL 沿原 Gateway 注册及生命周期 owner，不删除磁盘工作区或 `.boxteam`，不等于关闭 Tab、删除会话或停止远端机器。连接移除遵守原 config／manual owner。共享 Backend 操作 SHALL 展示原 generation、完整成员及影响，遵守阻塞和安全／强制动作合同；不逐工作区循环 stop／restart，不把 blocked 回执当成功或自动转为强制。移除后的详情及脏草稿保留原 owner 与不可达原因，不重绑同名目标或自动重新注册。

#### Scenario: 移除共享 Backend 的工作区成员
- **WHEN** 用户移除与其他工作区共用 Backend 的工作区，原 owner 返回 blocked 或成员已变化
- **THEN** 显示原阻塞／冲突与影响范围，保留真实注册结果，不删磁盘数据、不自动强制或逐成员重启；用户后续显式操作重新使用原 owner 合同

### Requirement: 诊断必须定位真实 owner 并有界读取

产品 SHALL 提供目标健康、配置应用状态、进程日志和会话 Trace／LLM 请求／上下文的可发现入口，并区分产品诊断与工作区会话业务数据。日志／历史按原 owner 的尾读、分页或游标有界读取，正文按需展开，不能为生成列表摘要补读全历史。错误 SHALL 保留可定位原因和既有 request_id；不把敏感正文纳入默认诊断复制，不编造资源 URI、系统路径或成功结果。

#### Scenario: 大型 Trace 与多目标日志
- **WHEN** 用户在 B Thread 打开有十万条记录的 Trace，随后切到 A Gateway 诊断
- **THEN** B 先按有界页展示真实记录，A 仅读取其所选日志；不全读约百 MB 文件才能返回首项，不把 B 业务正文写入 A 全局日志

### Requirement: 用量和统计必须表达已知范围而非虚假汇总

产品 SHALL 展示已有 Thread／Goal 的 Token、耗时和预算；目标级遥测与统计开关沿正式 Gateway 配置。聚合仅使用原 owner 已支持并被用户选择的范围，说明覆盖、计量来源与缺失。没有价格或完整计量时 SHALL 明确未知，不显示零成本；不因访问统计页自动查询全部 Gateway、启动计费调用或新建采集 daemon。

#### Scenario: 缺少价格与远端离线
- **WHEN** 用户查看所选工作区用量，其中部分模型无价格或目标离线
- **THEN** 保留可确认数据并显示未知／未覆盖及原因，不把不完整数据表示为全部总计，不自动扩大查询范围

### Requirement: 缓存和存储维护必须区分展示数据与业务数据

缓存入口 SHALL 展示原缓存 owner 已有信息并支持其已有精确清理操作，清除浏览器历史镜像不删除后端历史。工作区数据、Gateway 控制面及产品日志的存储位置与保留配置分别展示；删除、备份、修复等操作只有原 owner 明确提供合同后才可开放，不能新增浏览器扫盘、全库一致性检查、跨目标自动清理或一键删除 .boxteam。客户端展示档案不能创建或恢复旧 Gateway 用户目录。

#### Scenario: 清理当前 Thread 缓存
- **WHEN** 用户清理 B Thread 的客户端缓存，同时另一组打开 A Thread
- **THEN** 只清理 B 对应镜像，不删除任一后端记录或 A 缓存；操作明确展示固定 owner，焦点改变不重定向

### Requirement: 管理页加载必须按需并遵守完整交互预算

管理页 SHALL 在可见或执行明确操作时加载所需范围，复用原事件和必要订阅，隐藏／关闭后释放本页持有的读取、监听与模型引用；共享订阅沿原 owner 在最后观察者释放后结束，不因一个 Tab 关闭而中断其他观察者，不释放脏草稿的原工作副本。丢弃晚到的旧范围读取不能取消已提交的保存、任务或插件执行；副作用结果仍按原回执处理。不得新增常驻全目标轮询或以每个 Tab 重复获取全局目录。服务就绪、本机回环且无外部等待时，不超过 512 KiB 的普通暖 API SHALL 满足 p95≤500ms、单次≤1500ms，工作区列表／当前工作区／目录三步导航总 p95≤1000ms、单次≤2000ms，已支持普通管理详情的真实数据和控件首次可用≤3000ms；已有更严格的会话／文件预算保持不变。

计时 MUST 包括选择目标后的排队、鉴权、预检、内部请求、序列化和重试，到完整响应或真实可操作 UI 为止；不能以 loading、旧缓存或仅注册命令作为结束。模型、网络外部服务、进程启动和人工输入等待 SHALL 单列，不能扣除同软件内部的等待或叠加多层完整超时。必要身份／CAS 校验保持，全库审计和全历史 hash 不进入普通暖读。

#### Scenario: 六组编辑器并存时打开管理
- **WHEN** 六个 Thread 分屏保持打开，用户打开本地 Provider 管理再关闭
- **THEN** 详情在规定预算内真实可用，不阻塞原 Composer，不请求未选远端、不触发模型／工具／审批；关闭后释放本页订阅且不停止六个 Thread

### Requirement: 完成声明必须由真实入口及原始证据支持

验收 SHALL 覆盖 Workbench→实际 Gateway→目标 owner，包含本地默认、显式远端、目标切换与草稿、共享来源影响、实体保存后重读、已有运行入口及无审批／全目标轮询。暖 API 样本至少 20 次记录原值、nearest-rank p50／p95／max、响应大小与 request_id；单次超预算不能被平均值或自动重试掩盖。测试 SHALL 使用进程外超时和内存保护，保留准确命令、源码指纹、原始输出和退出码；昂贵检查按风险选择，不默认串行全套测试。浏览器通过不替代 Electron 原生验收。

本变更每个纵向切片的暖采样 SHALL 选该切片实际新增／改变的最多一个代表列表 API 和一个代表详情 API，记录选择依据及一条真实浏览器操作路径；不将 20 次采样乘上全部页面、目标、语言或客户端。纯接线可复用依赖源码未变的既有 owner 证据，同时验证新增入口的 owner 与真实结果；相关依赖改变时补验受影响部分。远端功能核归属、路由与错误，不将本机回环绝对预算硬套真实 WAN 耗时，也不排除产品内部 Relay 处理时间。

#### Scenario: 占位或错误归属通过不了验收
- **WHEN** 页面快速显示占位内容、请求返回错误 owner，或仅健康接口和局部 helper 通过
- **THEN** 不将该页面标记完成；记录失败阶段和未验证范围，无相关修改不重复跑失败检查碰运气

### Requirement: 插件列表与固定范围详情复用原工作台

插件 SHALL 在原扩展侧栏按包分组，行显示图标、名称、简介、真实配置及运行状态；行齿轮使用原上下文菜单，直接提供当前范围启用、停用、可用时重启及设置操作，包菜单提供批量开关、安装／更新和卸载。单击插件 SHALL 在真正 EditorPane 打开详情，遵循预览／固定、分屏和重载恢复；不在侧栏尾部再展示一份详情。详情身份固定 Gateway、工作区或范围、包、版本及插件；切换侧栏目标不能重绑已打开详情。

视觉与控件 SHALL 复用固定 upstream 的扩展视图：使用 WorkbenchList、InputBox、SelectBox、ActionBar 及原扩展行、图标、详情页头和正文导航样式。插件页头按图标、名称／版本、归属、简介、主操作和状态组织；配置 schema 放入功能贡献，不在默认详情堆放原始 JSON 或将每项操作绘成主要按钮。项目 CSS 只补包分组、范围和业务内容布局，不能把仅复用主题颜色、菜单与 EditorPane 外壳视为视觉复用；不为复用外观恢复 Gallery、VSIX 或伪造 IExtension。

Gateway 与其内部工作区 SHALL 使用联动下拉，初次默认本地与首个已登记工作区，切回恢复本 Gateway 上次选择；Gateway 范围及以后新工作区默认值入口在省略菜单，不能混入工作区候选或重复询问工作区。无候选明确显示，不自动创建、激活或改投。列表与详情共用原绑定／参数 writer 和状态流合同，不新增轮询或市场协议。

#### Scenario: 原扩展视觉与交互一起验收
- **WHEN** 用户在宽窗口及 685px 窗口查看插件列表、打开详情并切换正文导航
- **THEN** 实际页面使用原扩展行高、图标及标题样式，保留原列表键盘、预览和固定行为；主操作与次操作有原版层级，schema 在功能贡献中可见，未读取日志不显示空日志块；保留真实截图，不以控件可点击替代视觉检查

#### Scenario: 独立详情与侧栏停用
- **WHEN** 用户在工作区 A 的插件详情打开后，将侧栏切到 B，再在 A 详情停用插件
- **THEN** 写入仍只属于 A，B 列表与已打开 Thread owner 不变；切回 A 显示后端真实期望与运行状态，配置启用不冒充实例 ready
