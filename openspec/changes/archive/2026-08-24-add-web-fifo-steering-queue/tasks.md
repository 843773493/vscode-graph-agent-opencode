## 1. 队列模型与持久化

- [x] 1.1 将后端 pending request schema 从 `pending_kind` 改为 `delivery_policy`，补充不可变入队序号、队列项状态、等待原因和快照版本字段。
- [x] 1.2 重写会话待处理队列为单一 FIFO 结构，提供队首查看、队首取出、策略更新和撤回操作，删除 steering 优先插入、分组读取、合并读取和消费确认接口。
- [x] 1.3 更新 pending request store，只持久化仍在等待的消息；入队成功响应建立在落盘之后，取出后的消息不进入恢复队列。
- [x] 1.4 为队列模型补充后端单元测试：严格顺序、并发入队、尾部策略更新不改序、撤回后继任队首和非法提升/重排。

## 2. 边界投递与 Job 调度

- [x] 2.1 重构 JobService 的排队路径，使所有用户消息先进入 FIFO 队列，移除 `steering` 优先、连续 steering 合并、`job_merged` 和 immediate 分支。
- [x] 2.2 实现 `after_turn`、`after_tool_result`、`after_interrupt` 三类边界通知与队首资格判断，确保 tool call/result 原子性和无 tool-result 时的安全回退。
- [x] 2.3 为单条消息实现队首取出即移除；不建立 delivery attempt、执行确认、失败重试或崩溃恢复状态。
- [x] 2.4 将入队、策略更新、撤回、边界通知和消费状态转换统一纳入会话级线性化闸门，并添加并发竞态测试。
- [x] 2.5 更新 Job、trace 和 SSE 事件，使每个事件包含单条消息标识、入队序号、投递策略、边界和队列快照版本。

## 3. HTTP API 与旧控制面清理

- [x] 3.1 更新消息发送接口，接收并校验 `delivery_policy`，为新消息返回权威队列快照或队列回执。
- [x] 3.2 增加仅修改投递策略的待处理消息 API，并确保不能通过 payload 修改位置或入队序号。
- [x] 3.3 保留内容编辑和撤回 API 的非排序语义，删除 reorder、send-immediately 及 `pending_kind`/`dispatch_mode` 的旧接口与字段。
- [x] 3.4 为 API 补充无效策略、非队首投递、非法重排/提升、过期快照和恢复错误的明确错误响应测试。
