## Context

旧实现中 Gateway 注册工作区并透明代理工作区 API；每个工作区后端曾通过固定 `.boxteam/sessions/{session_id}/session.json` 保存会话；Web 启动时对所有工作区拉取会话数组，再在浏览器中分组和过滤。该结构既没有工作区文件夹、分页目录、跨工作区轻量搜索和通用自动生成能力，也让用户无法通过真实目录组织、移动和检索会话本体。

本地产品必须保持故障透明、无云端控制面、Gateway 不直接读写工作区 `.boxteam/`、工作区业务数据彼此隔离。已有大量未提交功能改动，本变更必须增量集成并保持现有 API 的明确错误语义。

## Goals / Non-Goals

**Goals:**

- 以稳定节点 ID 和 revision 管理 Gateway 工作区文件夹与工作区引用。
- 为会话提供轻量目录查询、分页、搜索、breadcrumb 与可重建索引。
- 让物理目录树成为会话位置的唯一权威来源，支持稳定 ID、手工访问、移动检测和旧布局迁移。
- 以 Gateway 权威配置实现可注册 Session Generator，支持跨工作区挂载与三种 session strategy。
- 让 Web 只加载可见目录节点，并能从全局搜索结果定位真实节点。
- 保证磁盘、API、Gateway 镜像和 UI 错误状态透明可观察。

**Non-Goals:**

- 不搜索完整消息正文、checkpoint、Trace 或工具输出。
- 不提供云端调度；本地 Gateway 停止期间仅按显式 misfire 策略处理。
- 不允许任意配置字符串动态加载 Python 可执行代码。
- 第一版不支持同一工作区的多个快捷方式，也不支持复杂多触发器布尔表达式。
- 第一版要求会话所在工作区、live session 上下文工作区与 Agent 执行工作区一致；Gateway 可以从任意当前工作区管理和挂载该定义，但不做跨后端 checkpoint 搬运或远程工具执行。
- 不把 Gateway 工作区文件夹理解为移动任意工作区根目录；Gateway 仍只组织工作区引用。

## Decisions

### Gateway 保存全局组织和生成器权威配置

`workspace-tree.json`、`generators/*.json` 与 `generation-runs/<generator_id>/*.json` 保存到 Gateway 根目录。Gateway 只通过 API 校验和驱动目标工作区，不直接读取目标 `.boxteam/`。相比把配置放进创建者工作区，这能避免活动工作区切换、远程挂载和创建者会话删除导致全局配置失去所有者。

第一版执行路由必须满足 `execution_workspace_id == session target workspace`；`live_session` 上下文也必须来自同一工作区。不满足时保存定义即失败。后续若引入 checkpoint 导出/导入与远程执行协议，再解除该限制。

### 索引是可重建缓存而不是第二权威来源

工作区目录快照来源于物理目录树中的 folder manifest 与 session manifest；Gateway 全局索引来源于工作区清单、工作区目录快照和生成器定义。索引损坏、缺失或与目录状态不一致时标记 unhealthy 并重建，不回滚已经成功的物理业务操作，也不静默返回空结果。旧的 `session-folders.json` 仅允许作为一次性迁移输入，迁移成功后不得继续参与读写。

### 会话本体使用带稳定标识的真实物理树

工作区会话根目录仍为 `.boxteam/sessions/`，但其直接和递归子项是用户可见的真实文件夹与会话目录：`<folder-name>--<folder-id>/.../<session-name>--<session-id>/`。文件夹目录含 `.boxteam-folder.json` 保存稳定 folder ID；会话目录含 `session.json` 保存稳定 session ID，并继续聚合该会话的 checkpoint、日志、Trace、后台任务、上下文历史、变更和工具结果。显示路径来自实际目录，稳定引用来自 manifest，二者不得由独立 JSON 树重复维护。

会话节点允许通过保留的 `children/` 边界包含物理子树：`<parent-session>/children/<child-session>/`。`children/` 只承载子会话和用于组织这些子会话的真实文件夹，不属于父会话自身的 checkpoint、日志或附件数据。直接绑定为子会话时，系统把子会话的整个物理子树原子移动到父会话的 `children/` 下并写入 `parent_session_id`；解绑时把整个子树移回父会话所在的会话文件夹并清空该字段。移动父会话会自然携带全部后代；删除父会话必须在 UI 明确确认后级联删除后代；导出父会话必须包含完整子树；跨工作区绑定必须拒绝。

`parent_session_id` 与最近的物理祖先会话必须一致，表达可管理的父子会话关系；创建时采用了哪个会话上下文由独立 `context_source` 记录，避免把上下文来源与当前物理归属混为一谈。生成器挂到会话并创建新会话时，以该会话的 `children/` 为物理基准；目录模板可以在该边界下创建真实文件夹。UI 创建或重命名节点时生成跨平台安全、限长且带短稳定 ID 后缀的路径段；用户手工重命名或移动目录后，重新扫描按 manifest ID 恢复引用并更新 breadcrumb。重复 ID、越出会话根、非法 manifest、`parent_session_id` 与物理祖先不一致或路径冲突必须使目录 unhealthy。

所有业务模块通过单一 `SessionPathResolver` 以 session ID 解析当前物理路径。创建、移动和重命名先执行同文件系统原子目录操作，再使派生索引失效；删除只删除真实目录一次，索引随后重建，不再维护一份虚拟关系。跨文件系统移动不隐式复制，必须明确报错。

### 使用组合定位与独立关系字段

跨工作区引用统一使用 `workspace_id + session_id`。`parent_session_id` 表示同一工作区内的物理父会话；`placement` 表示生成器挂载；`execution` 表示运行工作区；`context_source` 表示创建或续写所使用的上下文来源；`created_from` 仅用于审计。

### Session Generator 采用类型注册、实例配置和运行账本三层模型

可信代码注册 `type_id + version + config_schema`；Gateway 保存 GeneratorDefinition；每次触发创建 GenerationRun。Trigger、Placement、Naming、Context Source、Session Strategy 和 Policies 是组合字段。目标工作区执行统一的生成请求，使用幂等键阻止重试产生重复输出。

工作区生成执行账本采用可恢复阶段机：先持久化输出 session ID，再把完整 MessageDTO 意图保存在对应物理会话包中，然后持久化 message ID、预留 job ID，最后才分派。重启恢复必须复用这些稳定身份；Gateway 轮询工作区生成状态而不是把进程内 task 或 Job 查询当作运行权威。生成结束后清理物理会话包中的消息意图，若会话包本身并发删除则视为意图已随包清除，但其它 I/O 故障继续快速失败。

定义成为 ready 前，Gateway 通过工作区目录 breadcrumb 校验 placement、策略目标和 live context 的稳定 ID 与节点类型。同一工作区和节点组合只探测一次；离线与不存在按 `mount_missing` 策略进入 blocked/fail，类型错误直接作为配置 4xx 返回。

### 三种 session strategy 是通用执行语义

- `new_per_run`：每次创建独立会话。
- `continue_existing`：在指定会话中串行创建新 Job，不创建会话。
- `fork_new_and_report_back`：创建上下文分叉会话，执行结束后按策略把链接、摘要或继续请求排入旧会话。

UI 是否切换到输出会话由独立 `ui_policy` 决定，后台运行默认保持当前会话并显示通知。

### 命名路径采用受限路径段模板

模板拆分为目录路径段模板和会话名称模板，只允许已声明变量；渲染后拒绝空段、`.`、`..`、绝对路径、分隔符和平台保留名称。最终物理会话路径段强制包含稳定 `session_id`。保存前预览在 ID 尚未分配时明确显示物理路径模板与后缀占位语义，运行结果返回实际路径；二者共用规范化规则。生成器运行直接在 placement 对应的物理节点下创建或解析目录；会话 placement 的预览和实际路径均显式包含其保留 `children/` 边界，不得在预览之外追加隐式层级。

### Web 使用懒加载树与搜索定位

根节点、子节点和搜索结果分别分页。搜索结果携带稳定节点 ID、workspace ID、breadcrumb 和 revision；点击后向目标工作区确认最新 breadcrumb，逐级加载、展开并高亮。前端不保存业务权威状态。

树行只保留展开、名称和必要状态；新建、重命名、移动、绑定、解绑与删除等管理操作进入右键菜单。会话和会话文件夹都可复制稳定 ID/资源信息；目标文件夹菜单可把剪贴板会话移动到此处，会话菜单可移动到剪贴板文件夹或把剪贴板会话“绑定为子会话”，不得要求用户手工输入内部 ID。

树同时提供与右键菜单等价的直接拖放入口。工作区引用拖到工作区时更新注册表中的 `parent_workspace_id` 并显示为子工作区；拖到工作区文件夹时解除现有父工作区关系并更新 Gateway 虚拟父节点。工作区文件夹可拖到另一工作区文件夹形成任意深度的虚拟层级，但不得把工作区文件夹映射为或写入任何工作区物理目录。会话、会话文件夹的拖放必须携带来源 `workspace_id`，目标在另一工作区时前后端均拒绝。

同一工作区内，会话拖到会话文件夹表示移动到该物理文件夹，会话拖到会话表示绑定为物理子会话；会话文件夹拖到会话文件夹表示移动为物理子文件夹，会话文件夹拖到会话表示移动到该会话的 `children/` 边界下。拖到工作区行表示移动到该工作区会话根。拖动父节点到自身或后代、把会话文件夹跨出所属工作区、以及跨工作区会话绑定均必须明确拒绝。拖放成功后重新获取后端权威树；失败时同样刷新，不通过本地状态伪造结果。

已有工作区文件夹的新建子项、重命名和删除通过树节点右键菜单触发；导航根使用与树一致的“工作区文件夹”标题作为根级右键区和拖放目标，不把标题伪装成创建按钮。工作区与会话右键菜单分别提供在工作区会话根和会话 `children/` 边界新建物理会话文件夹的入口，树行右侧不重复放置新建按钮。所有输入和危险确认使用与工作区重命名一致的暖色主题窗口，不使用浏览器原生 `prompt`/`confirm`，提交后以 Gateway 或工作区后端返回的权威状态刷新。递归删除虚拟工作区文件夹时只删除虚拟文件夹节点，把所含工作区引用提升到被删子树的父级，不移除注册表工作区。工作区拖到工作区或从子工作区拖入虚拟文件夹时涉及注册表和导航两次控制面写入，前端先更新虚拟位置，第二步失败时补偿恢复原虚拟位置并重新读取两份权威状态。

### 配置和派生索引使用原子 JSON/JSONL，不引入数据库依赖

Gateway 配置和运行账本写入使用临时文件、`fsync` 和原子替换；工作区轻量目录索引可保存在内存并输出原子快照。物理目录和 manifest 才是工作区导航权威，快照不得反向覆盖目录。规模测试决定是否引入成熟的本地倒排索引库，但第一版只索引名称、ID、物理相对路径和 breadcrumb，避免全文扫描会话内容。

## Risks / Trade-offs

- [现有代码广泛硬编码扁平会话路径] → 先引入单一 resolver 并迁移所有读写入口，再启用物理搬迁；静态检查和测试禁止新增路径拼接。
- [用户手工移动导致索引过期] → API 操作即时失效索引，启动和显式刷新执行一致性扫描；重复 ID 或损坏 manifest 立即报告冲突路径。
- [物理重命名与长路径的跨平台差异] → 使用受限安全段、长度预算和稳定 ID 后缀；拒绝保留名、路径穿越及跨文件系统隐式移动。
- [Gateway 增加聚合索引职责] → 明确索引非权威且不读取工作区文件，只消费 API 快照；控制面接口使用 `/api/gateway/*`。
- [跨工作区或远程工作区离线] → 保留配置与上次目录快照，返回 `offline/stale/blocked`，禁止自动改绑。
- [递归删除物理文件夹或父会话会真实删除会话本体] → 默认只允许删除空文件夹；递归删除文件夹或含子会话的父会话要求显式参数并返回将删除的会话清单，取得全部相关会话的删除准入后只执行一次真实目录删除。
- [生成任务重试造成重复会话] → Gateway 与工作区共同使用稳定 idempotency key，并把输出 locator 写入运行账本。
- [继续旧会话时并发写入] → 每个目标会话串行排队；`forbid/queue/skip` 策略显式记录结果。

## Migration Plan

1. 修改项目存储契约，新增集中式 resolver、物理节点 manifest、递归扫描和只读诊断，先让现有扁平目录也能由 resolver 解析。
2. 在工作区级迁移锁下读取旧 `session-folders.json` 和扁平会话目录，创建目标文件夹节点并以原子 rename 移动会话目录；每步写入可恢复迁移账本。旧导航若把会话挂在会话下，迁移器在目标父会话的 `children/` 下恢复该物理关系；若把普通文件夹挂在会话下，则在 `children/` 下恢复为真实组织文件夹。循环关系、缺失父节点和跨工作区关系必须明确阻止。
3. 全量复扫并核对 session ID、文件计数与目标路径；仅在验证成功后把旧逻辑导航文件移入 `.boxteam/migrations/` 作为只读备份，运行时不再读取它。
4. 将会话创建、移动、重命名、删除、导出、Job、checkpoint、Trace、工具结果和生成器全部切换到 resolver；随后启用目录 API 与 Gateway 索引。
5. Web 切换到目录 API；生成器接入目录模板、会话名称模板和三种 strategy，保留明确错误，不回退伪造空树。
6. 完成旧布局迁移、手工文件系统变更、跨工作区生成、重启恢复、大目录 E2E 和真实 UX 审查。

迁移前和迁移中失败时依据账本恢复或继续，不得同时启用两套权威关系。迁移完成后的回滚只允许使用迁移备份执行显式反向迁移，不能让旧 JSON 与物理树并行写入。

## Open Questions

- 长期的 cron 解析库和本地索引实现需要在当前目标平台上完成基准与打包验证。
- Windows 路径长度预算和文件监听差异需要在对应平台 E2E 中持续验证；不影响以显式扫描作为正确性基础。
