## Why

当前完整 Code OSS 工作台已有 Thread、文件和变更编辑器，项目也已有统一资源 URI、会话目录搜索与文件导航搜索，但这些能力尚未汇入原版快速访问。用户需要通过同一个入口查找目标、确认归属并选择动作，避免每类资源各建一套搜索与操作界面。

## What Changes

- 以“找目标 → 确定目标 → 选择并执行动作”建立工作台快速访问能力；打开、引用、管理是并列动作，不要求先打开详情再操作。
- 保存概念目录树、概念表和项目接入分析，区分已确认合同、当前源码能力及领域接入缺口。
- 将用户确认的输入、列表、键盘、焦点、加载、记忆六类交互表作为共同设计基准；后续 Provider 和动作流程继承原版机制，不另定冲突规则。
- 无前缀 Ctrl+P 统一搜索会话、Thread 和文件，按类型分组；空输入显示最近打开。默认搜索范围取打开入口前焦点业务编辑器所属工作区，没有业务编辑器时使用导航当前工作区，并明确显示范围。
- 搜索严格限制在用户当前选定范围；没有命中就展示没有命中，不自动扩大范围、不在后台预先查询其它工作区。只有用户明确选择更多范围，才发起对应查询。
- 用户主动进入内容搜索时，文件、会话消息、工具结果、LLM 请求记录、Trace／运行日志全部纳入，并允许明确选择类别。默认 Ctrl+P 仍只查名称、路径等资源信息，不自动扫描正文，也不以内容搜索补偿无命中。
- 索引的必要性、实现与维护由各搜索 owner 决定；统一入口不强建全局索引、不要求所有 owner 使用同一索引技术。
- 将搜索明确拆成 Gateway 联邦 SearchService 与工作区领域 SearchService 两级：Gateway 负责范围解析、跨运行目标调度、增量汇总、稳定查询顺序及显式可比相关性模式；工作区通过轻量 Search Provider 合同调用原 owner，不把正文匹配、索引或业务状态搬到 Gateway。
- 明确 Provider 的确定性分派、注册／释放、能力版本与安全结算；区分一次请求、连续输入缓存、原 cursor 和持久镜像，保留上游 cacheKey／clearCache 合同，受限预热不冒充完整候选。统一计量、分支配额、合法续点和机器可判别诊断，补批次、慢消费及终态验收。
- 核心搜索生命周期不依赖传输：Gateway 的 SSE 只是当前网络编码。后端默认提供稳定查询顺序，Quick Access 保留原版 fuzzy／MRU 交互评分与本地模型覆盖，包括零命中对旧磁盘命中的屏蔽；跨工作区覆盖按资源身份分区，在文件输出计量和分页前排除，不上传模型正文，不为统一调度重写原版评分器。
- Web、Electron、Agent 搜索工具与脚本共享同一后端查询合同。支持指定工作区集合及显式“当前 Gateway 全部工作区”；“相关工作区”先查询控制面名称／导航归属，再以明确候选集合执行领域查询，不因无命中自动扩圈。
- 将 Provider 能力、独立稳定身份、规范资源 URI、命中位置和版本分开：可打开或可引用的资源命中默认提供规范 URI；命令、分组和进度不造 URI，索引不以显示名、临时 route 或客户端投影 URI 为身份。
- 统一现有 Gateway 目录快照搜索与前端多目标分发的搜索合同，迁齐全部消费者后移除同义调度与匹配链；保留导航权威排序、领域原 cursor、缓存新鲜度及原版未保存模型覆盖，不以浏览器存在作为搜索服务前提。
- 复用原版 Quick Access、Quick Input、搜索、命令、打开服务与编辑器组；项目贡献提供领域候选、明确目标和动作，不新建搜索浮层或复制上游实现。
- 将会话／Thread、文件、资源来源、变更、工作区与持续任务等按各自 owner 接入；只有需要资源引用或重新打开的对象才补规范 URI，并由统一寻址 owner 登记。不为所有候选、命令或瞬时状态普遍造 URI。
- 文件引用、粘贴内容分别处理，需要可复现时再明确冻结版本，不新增统一的默认冻结时点；既有请求、历史及附件的版本合同继续生效。引用接收者优先使用发起操作的 Thread，全局入口没有明确接收者时再选择，切换标签不改投。
- 让规范资源 URI、现有编辑器资源与结构化定位参数各司其职，统一已有入口对同一目标的打开与操作语义。
- 保留原版快捷键、预览／固定、分屏、设置、历史和无障碍机制，以及既有文件树单击在会话资源内预览的行为。
- 固定单一默认 Provider、原文件搜索服务与业务资源根的接入方式，补齐排序／去重、分页取消、精确定位、路由重解、Thread Outline、Command Center 模式帮助、原调用参数及每个 Search Editor 的范围持久化和迁移边界。复用原搜索视图和编辑器，不另造控件或全局索引。
- 定义真实 Gateway、多工作区、多 Thread、异步搜索和业务动作的验收边界。按规范、设计和可追踪任务清单推进产品实现；任务按职责及必要依赖组织，编号不代表排期或要求串行执行。

## Capabilities

### New Capabilities

- `workbench-quick-access`: 完整工作台中查找目标、辨认归属、选择并执行打开／引用／管理动作的统一交互合同，以及由客户端、工具和脚本共享的两级搜索、范围、Provider 与聚合合同。

### Modified Capabilities

- `resource-file-operations`：实际目录／文件 describe 提供轻量 stat，工作台文件投影保存稳定归属并支持目录根拼接；原导航 search 增加有界模糊召回、显式文本／路径匹配选项及多行码点区间；正文保存继续消费原 revision／CAS。
- `scalable-session-navigation`：目录名称、稳定 ID 与逻辑路径在原 owner 支持顺序字符模糊召回，分页绑定查询语义和 revision；Gateway 目录搜索统一接入联邦合同，公开目录镜像沿用相同节点匹配规则且明确新鲜度。工作区 Thread 名称发现复用原 catalog 与 Session 控制库，显式表达预算、覆盖和续查，不依赖已打开标签。

本稿新增上述交互 capability，不直接修改现行规范正文。复用既有寻址、文件操作、会话目录、上下文和持续任务合同，不重新定义其身份、状态机或权限规则。具体资源确有规范 URI 缺口时，新增模板必须在统一寻址 owner 中正式登记并同步其 delta；本稿只确定按需补齐原则，不预造模板或在前端另立协议。领域搜索缺口同样由原 owner 补齐，不另立事实源。已确认涉及 catalog／Thread 发现、文件搜索选项和根投影、消息／工具／请求／日志查询与定位、编辑器恢复及上下文引用消费者；这些是本改动的实现依赖，不能以本稿未创建各owner delta视作无需修改。确需改变原外部合同或新增 URI 模板时，在对应业务代码实施前补齐原 owner 的正式 delta 与真实类型合同；仅新增查询消费或沿用已有动作不重复定义其业务状态机。

## Impact

- 客户端集成面：`src/clients/workbench/src` 的业务贡献、编辑器与原版服务；`src/clients/web/src` 的现有 API、会话业务 hook、输入区和展示状态。
- 领域数据面：工作区会话 catalog／Thread、资源导航与文件搜索、变更、持久任务；沿用其权威 owner。Gateway 承担控制面查询、目标路由和统一联邦查询编排，不扫描工作区业务存储。统一信封仅表达查询生命周期与归属，命中正文和位置继续使用领域 typed 合同，不建立通用业务对象数据库。
- 复用关系：`add-native-web-workbench` 与 `integrate-workbench-features` 提供完整宿主和编辑器；`add-unified-virtual-resource-addressing` 独占 URI 合同；`resource-file-operations`、`session-context-resource-addressing`、`persistent-task-management` 等保留原领域职责。
- 组织选择：新增一个聚焦的 change、一个用户可观察 capability，在 design 内拆分接入职责。既有工作台 change 已完成，URI owner 又不负责此交互，因此不重开旧 change，也不把搜索、命令、打开拆成多套互相重复的规范。
- 不修改固定上游子模块；在既有 Vite／生产构建共用的 sourceTransform 中精确接入原贡献和搜索范围数据，不复制上游 UI 或另建转换管线。不新增原生 Electron 能力、后台全局索引或第二套业务存储。Web 与 Electron 复用同一工作台贡献；各宿主仍须分别验证实际行为。
