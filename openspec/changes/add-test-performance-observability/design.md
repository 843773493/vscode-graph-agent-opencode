## Context

动机见 proposal。当前可复用的事实：

- `tests/runner/run-tests.mjs` 负责矩阵选择、运行身份、进程外保护和退出回收，覆盖 Python/Bun 命令，但 stdout/stderr 直接继承，尚无统一性能收据。
- Python/JS 的 `run_context` 提供运行及节点产物归属；Python 当前使用 `runs/run-<hash>/nodes/...`。新增性能归档遵守当前 UTC 日期约定，不顺手移动旧结果、workspace、runtime 或锁。
- `tests/conftest.py` 已注册 harness 插件；`integration_gate.py` 持有跨进程集成闸门，`web_workbench.py` 已记录共享构建耗时；进程 scope 负责登记/回收，不应承担第二份生命周期权威。
- `FixtureStageObserver` 包含 427-turn 装具专用计数，`compaction_runtime_call_profile` 通过替换方法产生单例诊断。统一的是其中通用计时/记录职责，业务专属数量留在原装具或断言。
- 已依赖 psutil；浏览器测试通过现有 Python/Bun 驱动运行真实 Workbench。现有交互延迟 OpenSpec 是业务验收合同，采集器不另定义宽松替代预算。

## Goals / Non-Goals

**Goals:** 普通矩阵运行直接留下轻量证据；核心场景能解释阶段、工作量和资源成本；单次诊断和跨版本比较不必重写探针；指标作用域、缺失和测量开销可核验；重复专用记录器逐片移除。

**Non-Goals:** 不建立生产遥测、监控 UI、指标数据库、常驻 Agent 或自动优化系统；不调整产品校验时机、业务合同和模型参数；不重写全部测试或为所有函数埋点；不以观察装具取代真实依赖、原性能门和进程保护。

## Decisions

### 1. 单一记录格式，三个采集档位

沿现有 runner 增加选择入口：默认 `basic`、显式 `core`、显式 `diagnostic`，并允许明确 `off`。runner 和直接 pytest 的选项映射到相同语义；直接 pytest 可输出生命周期/阶段记录，但只有经正式 runner 启动才保证进程外采样和保护，报告必须标明实际覆盖，不从 fixture 自行另起一套 supervisor。core/diagnostic 可以只选择所需采集器，不自动打开全部追踪。不增加第二个 benchmark runner。

选项留在测试命令和现有测试矩阵中；若需要持久化，每个 suite 使用 `performance.collection` 管理 `mode`、`sample_interval_ms`、`sample_limit_bytes` 等新增参数，明确默认值、范围及命令行覆盖优先级，不新增 product/env 配置。复用 JSONC 解析和校验边界，不引入通用配置框架。basic 默认资源采样间隔 250ms，后代发现使用 psutil 跨平台接口、间隔至少2秒，明确短进程覆盖缺口；不得为本机优化新增 Linux /proc 特例；参数错误启动前拒绝，选定采集器不支持时明确报告。

每个进程使用独立 JSONL writer，共享同一逻辑 envelope；Python/JS 只各实现必要的记录薄入口，不通过运行时跨语言 RPC 每条传输。基本字段包括 `schema_version/run_id/suite_id/test_id/worker_id/process_identity/stage_id/parent_stage_id/event/status`，以及单调区间、单位、来源和标量字段。业务工作量放入固定 `workload` 映射，避免任意对象序列化。层次/身份字段只在适用时存在。

替代方案是直接拼接现有 JSON：无法稳定关联，且会留下两套计时口径；通用 telemetry SDK 则引入当前不需要的传播、导出和运行依赖。

### 2. 监督方负责资源，测试进程负责语义

runner 继续拥有 suite 的启动/超时/中断/回收；资源采样使用测试专属的短生命周期进程，通过现有 uv 环境运行 psutil，不修改产品 `app/runtime` 的保护语义。采样器自身有超时、内存和回收归属，必须随 suite 结束；不得只因测试主进程退出就丢掉后代结算证据。复用已有 supervisor 能力，必要的测试侧扩展保持一条调用链。

监控从 suite 创建开始覆盖启动与业务阶段；后代通过已知根和现有进程登记确认，PID/创建时间区分重用。登记仅提供关联，不向 scope 塞入资源管理副本。外部共享服务只在现有 handle 明确关联后观察，标为共享，不按端口猜测或扫描整机服务。

basic 每次样本记录测试树汇总及必要进程角色，core 可增加目标进程细分；CPU/IO 对同一身份计算增量，退出进程保留最后可观测值。全树 RSS 使用同一采样时刻的合计，峰值取该序列最大值，不能将每个进程在不同时刻的峰值相加。CPU 百分比说明分母及是否按核归一化，原始 CPU 秒为主要比较值。句柄/线程数为瞬时量；不支持的内存/IO口径使用状态而非替代值。

不把所有主机负载归给测试。环境只在启动/结束等低频边界记录 CPU 数、可用内存、可获取的负载和 CPU 配额；不新增环境调优逻辑。

### 3. pytest 生命周期自动记录，业务阶段显式标记

插件在会话/collection和节点报告钩子记录真实生命周期，fixture 只负责业务阶段 API。节点 call 不包含 setup，但报告必须展示其包含的准备过程；session/module fixture 的共享成本单列，使用节点已有 setup 包含关系避免重复相加。对闸门、共享 Workbench 构建等已知边界加少量显式 stage，不逐个分析所有 fixture。

Python 提供 `perf.stage("snapshot.read", workload={...})` 形式的同步 context manager，可包住 await；ContextVar 保持异步归属，线程/子进程只在现有调度入口显式携带标量关联信息，不安装全局线程 monkey patch。阶段 finally 写完成事件并原样传播取消/异常。未正常退出仅保留 start，由汇总标记 incomplete。

JS/Bun 复用 `tests/harness/js/run-context.mjs` 的身份和输出规则，提供最小阶段入口。basic 保证所有 suite 指标；本轮不承诺为所有 Bun 测试补造 pytest 式 setup/teardown，优先复用运行时已有结构化报告，不解析易变终端文字。JS 核心业务阶段显式接入，未覆盖的节点明细明确报告。

未分解的进程启动区间包含 uv、解释器和早期导入，不能伪称精确导入统计；逐模块 importtime 仅诊断时开启。单调时钟只用于各自时钟域内耗时，跨进程以已有请求身份关联。需计算浏览器到服务的跨度时单独校准并报告误差，不默认将各方时间戳相减。

### 4. 指标按场景接入，保持最少观察点

| 范围 | 记录内容与实施边界 |
|---|---|
| basic 资源 | wall、CPU user/system、RSS、可用 IO、fd/handle、线程/后代数量、结果和采样能力；CPU/IO是进程作用域 |
| 异步调度 | core 中低频 loop lag，记录计划/实际调度差与最大值；在已有队列/锁/连接池边界记录等待和执行，不全局代理 asyncio |
| 数据库与文件 | 选定测试连接/装具观察 execute/fetch 的真实边界，分清执行耗时和消费行数；busy 与锁等待只报可直接观测部分；进程 IO 与业务读写计数分别命名 |
| 缓存 | 在核心场景已有缓存入口记录命中、填充及后续工作；不为采集读取全部 cache 或扫描历史 |
| HTTP/LLM | 现有客户端/流回放装具记录请求尝试、状态、字节及首字节/完整消费；模型 usage 使用真实回执，区分首字节、首 token、首个可见文本；重试保留总账 |
| 资源增长 | 预热后固定 workload 的轮次边界取样；连接/任务只从现有生命周期登记取得计数，不依赖私有连接池结构或强制 GC |
| 浏览器 | 现有浏览器驱动通过标准 PerformanceObserver/网络事件与必要 CDP 能力记录长任务、资源、DOM；SSE关联与真实渲染边界在现有流式场景显式标记 |

上述采集器均落到同一记录格式，按指定场景启用，不为每项指标建立插件注册框架或新状态源。确需包装测试连接/请求时使用窄的观察边界，完整转发原值/异常并恢复，禁止多次读取 cursor、消费响应流、修改事务或侵入产品代码。SQL/操作次数是诊断值；业务断言按输入输出和风险验证。

详细 CPU 诊断复用 Python cProfile 和现有 JS/浏览器 profiler；Python 分配使用 tracemalloc；浏览器 trace 使用 CDP timeline 的无正文元数据导出，避免默认 Playwright 网络 trace 包含凭据/正文。记录工具能力及作用范围，Bun 不支持某诊断时明确拒绝该选择，不静默换运行时。深度产物单独关联，可能含敏感内容的工具产物须明确说明，使用隔离测试数据，写入前移除凭据/请求正文或禁用会记录真实秘密的选项，不上传外部服务。

### 5. 原始证据增量保存，汇总可以重建

沿 TestRunContext 扩展性能产物定位，不新造 run_id/node_id。测试事件落在 `out/tests/<测试文件去后缀>/artifacts/YYYY/MM/DD/<run_id>/...`，worker/node 分隔；suite 监督证据落在 `out/tests/runner/run-tests/artifacts/YYYY/MM/DD/<run_id>/<suite_id>/`，相对引用各节点数据。日期来自一次冻结的开始时间，跨天不改；本轮只统一性能产物，不搬迁既有其他日志。测试开始/完成与异常边界及时 flush，资源样本周期性 flush；不承诺整机断电后的 fsync 持久化。

输出包括原始 `performance.jsonl`、可重建 `performance-summary.json` 和终端前若干慢阶段摘要。suite 收据关联准确命令、退出码/信号、保护参数、采集错误和测试结果；不劫持产品 `result.json` 的成功语义。继续保留 stdout/stderr 原始文件并镜像控制台，复用既有输出 helper，不能只保留解析后摘要。

详细资源样本默认每 suite 限 64MiB，达到上限停止保留详细样本但继续常数空间聚合与进程保护，明确记录截断时间、数量和区间；不得用截断后的样本计算被宣称为完整的分位数。阶段记录在核心场景数量有界，禁止默认逐 SQL/逐 token 生成事件；任何额外容量限制均显式报告，不能因采集积压阻塞产品请求。汇总只保存有限统计及有界样本，不将全部 JSONL 重新加载到内存。

对预期退出竞争记录终点，对平台不支持记录 unavailable；意外采集/写盘错误通过独立错误状态和 stderr 暴露，runner 最终报告基础设施失败，同时保留原测试退出结果。即使证据失败，仍先完成进程回收，不以写盘异常覆盖原始业务异常。

### 6. 证据足以比较，但不自动判定所有指标回归

记录 HEAD、dirty、相关源码/配置的工作区内容指纹和指纹范围，不只用 Git diff（包含未跟踪的受影响源码）。指纹一次计算，不在每节点扫描全仓；测试前后核对范围变化，变化时标记混合版本。参数和命令做秘密过滤，不采全量环境变量；URL去掉敏感 query，SQL不含绑定参数，模型不记录正文。

提供显式 `compare <baseline-summary> <candidate-summary>` 测试工具入口，复用现有 runner/harness 命令组织。检查 workload、冷热、并发、采集器/周期、schema、平台/运行时等；源码本身变化是比较目标，环境差异列为限制。报告原始样本、差值/相对差值（零基线不除零）、nearest-rank p50/p95/max 和样本量；样本不足只保留描述性统计及警示，不声称稳定 P99。失败/取消样本单列且保留，不通过丢弃失败“改善”成功率。

默认指标不新增门槛，复用已有交互预算及更严格 reader 预算，业务请求从发起计至完整消费，UI 至正确内容/操作可用；内部排队/重试不得扣除。性能基线只由用户指定，不自动选择最近成功/最好一次，也不自动覆盖。

### 7. 按纵向切片迁移和验收

依次完成“suite basic → pytest/共享准备 → rollout/压缩 → 异步存储与网络/模型 → 浏览器/资源增长 → 深诊断及比较”。每片迁齐写入方、消费者与相关测试后集中验证，避免先建一堆无人使用的采集器。沿用现有真实入口 fixture，不批量新增性能测试文件；观察器必要行为通过少量可区分错误实现的用例覆盖。

采集开销使用同源码的 off/basic 配对测量：固定至少 2 秒的 CPU workload 和 I/O workload，各 5 对交替顺序；保留全部样本，以配对相对增量中位数不超过 5% 为 basic 的目标。额外采集进程启动成本和短 suite 总开销另报且不从真实总耗时扣除；资源采样内存/输出量一并记录。首次未达目标时精简频率、聚合及记录，不改产品预算；仅性能开销验证需要此重复运行，不扩展为全套重复执行。

## Risks / Trade-offs

- [采样错过短进程/尖峰] → 保留已知生命周期与覆盖缺口，不将缺失填 0，必要时选择更细诊断。
- [共享进程/多 worker 使归因失真] → CPU/IO 保持进程作用域，显式标记共享和并发，阶段 wall 不伪装独占成本。
- [采集改变被测性能或生成过量数据] → 默认低频、聚合与容量边界，配对验证开销，深诊断显式启用。
- [测试观察包装改变 cursor/stream 或异常] → 仅在现有装具边界接入，验证完整消费、取消与原错误传播，迁后移除专用记录分支。
- [平台能力差异] → 输出能力状态；Linux 实测不能宣称 Windows/macOS 通过，平台相关保护与句柄能力分别验证。
- [真实 Provider 与 trace 包含秘密] → 默认只记录标量与脱敏身份，深诊断限隔离数据和安全工具选项，不对真实凭据采全量请求。

## Migration Plan

1. 在当前测试基础设施内增加统一 writer/收据和 basic 监督采样，保留原命令语义及保护，不改产品运行时。
2. 接入 pytest 生命周期、闸门和共享构建，迁移 rollout/压缩的通用计时；业务专属计数不搬入通用采集器。
3. 逐片接入核心观察和代表性真实入口，确认覆盖后检索并物理删除本次替换的专用记录机制与重复解析器。
4. 接入深诊断和显式比较，完成开销验证、最小充分实现复审与所需平台证据。历史性能文件不做自动迁移/双读，新比较工具明确拒绝未知格式。
5. 若实现出现故障，显式关闭新采集用于定位，保持原业务门与保护；修复当前唯一实现，不保留旧新观察器两套运行路径。不自动撤销共享工作区其他任务改动。
