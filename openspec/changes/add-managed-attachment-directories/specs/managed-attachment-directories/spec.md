## Purpose

将用户上传附件作为可由现有文件工具和 Shell 处理的工作区目录资源，统一目录关联、使用占用、历史版本、fork 和延迟回收，使异常退出后的清理可核验且不依赖 Agent 主动释放。

## ADDED Requirements

### Requirement: 附件目录是工作区级资源与回收单位

每次独立上传 SHALL 创建具有稳定资源身份的独立附件目录，包含原始文件、预览及后续处理结果。相同字节的独立上传 MUST NOT 合并可变目录身份。Thread 关联和回收 SHALL 作用于整个目录，MUST NOT 为每个派生文件另建 Thread 引用计数。原件 MUST 保留，处理结果 SHALL 写入新文件或子目录；具体文件的完整性摘要 MUST NOT 被当作可变目录的整体身份。工作区访问权限与用于保活的 Thread 关联 SHALL 分离，读取本身不产生永久关联。

#### Scenario: 相同内容被独立上传两次

- **WHEN** 用户在两个 Thread 分别上传相同字节的文件
- **THEN** 两次上传得到独立目录资源和关联；一个目录中的处理结果不出现在另一个目录，解除一个关联不影响另一个目录的保留

#### Scenario: Shell 生成处理结果

- **WHEN** Agent 在附件目录下生成多个文本、图片或解压后的文件
- **THEN** 文件可通过原文件操作链路继续使用，原件不被覆盖，目录整体保活且不需要逐文件 attach

### Requirement: 文件工具与 Shell 使用同一附件目录 URI

附件目录及子文件 SHALL 使用统一 URI owner 登记的 workspace 模板和 child 规则。模型消息 SHALL 提供目录 URI、原件 URI及必要元信息，并提示处理结果保存到该目录的新文件或子目录。Shell 的结构化工作目录 SHALL 在目标机器解析为原生 cwd 后执行，命令正文保留操作系统路径语义；MUST NOT 扫描替换任意命令字符串中的 URI。URI 不属于 Shell 目标时 SHALL 明确拒绝，不得在中继进程或其它机器解释。普通响应和持久业务引用 MUST NOT 泄漏真实附件目录路径，既有具名管理/Browser例外不扩张到本入口。

#### Scenario: 远端 Shell 处理附件

- **WHEN** Agent 将远端附件目录 URI 作为 Shell 工作目录，命令读取相对路径并生成派生文件
- **THEN** 所有文件操作发生在 URI 指定的目标机器和目录，使用原文件 owner/PTY 链路，响应继续使用规范 URI

#### Scenario: URI 目标与 Shell 目标冲突

- **WHEN** Shell 绑定的工作区与工作目录 URI 的目标不同
- **THEN** 在启动命令前明确拒绝，不能转换为本机相对路径或静默切换目标

#### Scenario: 附件工作目录的来源识别或复核等待原生访问

- **WHEN** Terminal 创建已进入附件目录准入，catalog 来源识别、可用性或原生目录检查仍在执行或在线程池排队
- **THEN** 复用原受保护 worker 并传递请求上下文，同一服务的其它资源请求仍能推进；原 Thread 准入覆盖结算，目录 holder 从复核前取得并覆盖排队及 worker 结束。调用者取消后等待同一 worker 结算并传播原取消，不继续发布目录占用或创建 PTY；原 intent 与 operation lease 仍由原创建失败链处理，不据此宣称没有创建意图。成功后沿原链保存目录 URI、发布绑定持久终端身份的目录 lease 并创建真实 PTY，不新增解析或文件操作链路；原生 I/O 抢占、同步 lease 写盘和整个 operation／shutdown 期限仍单独验收

### Requirement: 最后解除关联后默认保留附件目录三十天

上传 SHALL 经现有接受边界自动关联发起 Thread，Thread runtime 卸载、Thread 删除或 Session 删除 SHALL 由后端通知附件 owner 幂等解除精确关联。最后一个关联解除时 SHALL 持久记录零关联起点与默认 30 天回收期限；重新 attach SHALL 取消该期限，下一次归零重新计时。上传、排队输入、fork 和文件处理的有效操作占用 SHALL 阻止回收。周期检查 SHALL 使用低频到期查询，普通重启 MUST NOT 重置期限，也不要求精确到秒触发。删除前 SHALL 与新关联/占用互斥复核并登记可恢复删除状态，失败明确可见且可重试。Shell/Browser 原有临时资源的 30 分钟或 unload 立即清理规则 MUST NOT 扩张为附件规则。

#### Scenario: 三十日前重新关联

- **WHEN** 一个上传很久的目录刚刚解除最后一个关联，随后在第 29 天重新 attach
- **THEN** 目录未被按创建时间回收，原回收期限取消；再次归零后获得新的完整 30 天期限

#### Scenario: 到期时仍在处理文件

- **WHEN** 目录零关联超过 30 天，但 Shell 或其后台处理进程仍有经 owner 核实的占用
- **THEN** 目录不被删除，操作结束后再次复核到期、关联和占用，不能把工具调用提前返回视为进程已停止

#### Scenario: 回收与重新关联竞争

- **WHEN** 到期回收与 attach 或 fork 保留同一目录并发
- **THEN** 只有一个串行顺序生效；关联先行阻止删除，删除状态先行则新操作明确报告不可用，重启继续原删除记录而不复活空目录

### Requirement: 原件回收不得改写历史请求或破坏恢复依赖

canonical 历史引用 SHALL 保留原资源身份、来源和具体已用文件版本；已封存的模型输入、预览与请求 hash SHALL 从原历史 owner 的冻结内容重建，MUST NOT 读取当前目录猜测过去输入。历史里出现 URI 本身不构成无限期目录保活；无关联目录按期限回收后，附件查看或需要原件的新操作 SHALL 明确报告不可用。checkpoint/assembly 恢复仍依赖的冻结资产 MUST 保留，不能随目录 GC 删除。

#### Scenario: 派生文件变化后恢复旧请求

- **WHEN** 某派生文件已用于一次模型请求，之后文件被修改或整个附件目录被回收
- **THEN** 原请求仍可使用冻结输入重建并核对原 hash；查看当前原件明确反映当前可用性，不篡改 canonical 或从现有配置补造过去输入

### Requirement: Fork 通过原资源处理合同保留目录

fork SHALL 沿用统一资源目标检查及现有 journal/claim/publication，按所选历史的依赖保留目录。同工作区 SHALL 复用原目录身份并为目标建立关联；跨工作区 SHALL 按冻结目录版本复制为独立目标资源。历史来源身份及 URI MUST NOT 被改写为目标历史。必需目录已回收时 MUST 明确拒绝依赖它的 fork，不能创建空目录伪造成功；可选目录省略时 SHALL 保留不可用原因。预留失败或目标删除 SHALL 收敛本次关联，不能留下无限保活。

#### Scenario: Fork 后删除来源 Thread

- **WHEN** 同工作区 fork 已发布并关联所需附件目录，随后来源 Thread 被删除
- **THEN** 只解除来源关联，目标关联继续保活同一目录，历史来源身份保持不变

#### Scenario: 跨工作区复制期间目录改变

- **WHEN** 跨工作区 fork 捕获目录版本后，派生文件集合在发布前改变
- **THEN** 目标只发布冻结版本或明确冲突，不产生混合时刻的文件集合，失败不发布半个目标

### Requirement: 异常退出的占用与关联必须有 owner 对账

系统 SHALL 根据后端/Thread runtime 代次、权威 Thread 与任务状态收敛失效占用及关联，MUST NOT 只依靠 Agent 发送 detach 或仅看 Thread ID 仍存在。旧代迟到释放 MUST NOT 移除新代关联；cold Thread 和尚待执行输入 MUST NOT 被当作已删除。失去持有者不证明外部资源已停止；Shell、Browser、后台文件处理仍 SHALL 由原 owner 终止并核实，未知结果保持可发现的待核实状态与管理操作，不得伪报已释放。该对账 SHALL 复用原账本，不创建第二套资源事实源。

#### Scenario: 已 attach 后后端崩溃

- **WHEN** 后端在关联资源后退出且未发送 detach，随后重启
- **THEN** owner 按原持久事实区分待恢复任务、新代关联和已失效持有者，解除可证明失效的关联并开始相应回收规则，未知外部进程仍要求核实

#### Scenario: 停止派发前 Backend 硬退出

- **WHEN** 管理停止已登记原 operation lease 并完成撤权，但尚未向外部 owner 派发停止时 Backend 硬退出
- **THEN** 新 Backend 保留原待核实 lease，不自动重放停止；仍存活的处理进程继续保护其附件目录占用和原到期期限，只有显式管理停止核实真实进程终态后才结清占用

#### Scenario: 真实停止回执返回后 Backend 硬退出

- **WHEN** 外部 owner 已停止处理进程并返回正式回执，但 Backend 尚未提交该终态就硬退出
- **THEN** 新 Backend 沿原资源身份核实外部终态并结清原 operation 与目录占用，不重复派发停止；到期目录按原 locator 和期限回收，后续重启不得复活目录或改写 canonical 历史

#### Scenario: 单个资源的冷恢复授权同步失败

- **WHEN** Terminal或Browser owner冷恢复时，某个资源的新授权版本同步失败或回执丢失
- **THEN** 保留该资源unknown与原失败，继续完成其它资源同步及账本更新后明确上抛原单错或按原顺序聚合多错；后续访问不重新推进已完成批次的全部版本，健康资源继续使用原查询、授权和工具入口，未知资源仍由原管理入口核实。取消或进程退出立即传播，不假报整批恢复完成；挂起期间共享等待隔离和总期限仍按后续任务验收

#### Scenario: 冷恢复同步失败后显式管理重试

- **WHEN** Terminal或Browser冷恢复的版本同步以普通异常返回，包括请求尚未到达外部owner及版本已提交但回执丢失
- **THEN** 原owner保留该冻结版本，普通查询仍可返回unknown且不重新发送同步；新的显式stop/delete在原资源锁内先核expected_revision、有效lease及关联限制，再以停止意图重试同一版本。重试再次失败仍保留pending和原待核实占用，不提前取得管理lease或派发停止；只有同步成功才移除pending，真实停止、持久终态与旧占用结算继续沿原链完成。普通同步被取消时仍允许原同版本恢复，不把取消等同已返回的普通失败

#### Scenario: 首次冷恢复清单回执挂起

- **WHEN** Terminal或Browser首次冷恢复的一个调用尚未收到原运行清单，另一个调用需要恢复健康资源
- **THEN** 清单网络等待不持共享初始化锁，其它调用可独立读取并核实原清单；首个成功结果沿同一owner的唯一准备提交冻结恢复版本与原lease，记录写入交由worker且准备锁覆盖整次结算。迟到清单不得覆盖已提交结果或再次推进版本，准备开始后的取消须等原提交结算再传播，保留原异常且不撤销其它调用的提交；不重复创建、停止或删除资源，不建立另一份恢复事实。其它同步存储及整个operation终止核实仍由后续任务验收

#### Scenario: 单资源冷恢复授权同步挂起

- **WHEN** 原 owner 已核对运行清单并持久冻结各资源的新版本，其中一个资源的授权同步仍未收到回执
- **THEN** 针对其它资源的查询、传输授权、工具调用、关联及其 Thread/Session 清理只等待各自所选资源的原版本同步；同一资源仍沿原锁串行。取消一个等待者不取消其它调用已持有的同步，取消批量恢复排空本次任务并保留尚未核实的原版本，后续重试不得重新推进已完成资源或重放创建/停止。单次恢复的清单核对、资源锁和授权同步共用入口取得的一次30秒等待预算；阶段切换不重置。事件循环正常调度且传输可取消时，到期排空本调用的等待并明确失败；未开始同步不改写为unknown，已发送但回执未核实的同步保留unknown、原占用与冻结版本。同一版本重试只核授权，不重放旧业务操作；同步阻塞、线程池及整个operation终止核实仍按后续任务验收

#### Scenario: 批量冷恢复中断时已有同步失败

- **WHEN** Terminal或Browser批量冷恢复中部分资源已返回同步失败，其它资源仍在等待，随后本次恢复到期或被调用者取消
- **THEN** 排空本次任务后按原资源选择顺序保留已完成的原异常对象；预算到期时将这些异常与本次预算错误共同上抛，调用者取消保持原CancelledError和消息，并以聚合cause保留此前失败。已成功的恢复不回滚，失败与取消项保留各自冻结版本及原占用，普通失败仍仅允许管理重试，不把取消项改成已返回的普通失败；健康资源继续可读，不重放原工具或重复推进版本

#### Scenario: 资源记录写盘失败不得提前发布

- **WHEN** Terminal 或 Browser 的创建、版本、关联、fork 回执、运行观察或终态记录在序列化、fsync 或原子替换阶段失败
- **THEN** 原 owner 只保留最后持久成功的记录，不将失败草稿发布为当前状态；等待资源锁后重新读取当前记录，终态持久成功后才结清占用。unknown 记录也写盘失败时，原账本继续保护待核实操作，普通存活快照不得消除该事实，显式管理重试仍沿原身份核实，不重放已结束的副作用或增加第二套记录链

#### Scenario: 资源记录失败时诊断输出再次失败

- **WHEN** 原资源记录的读取、写入或格式校验失败，记录该错误的日志出口也抛出异常
- **THEN** 沿现有统一错误出口保留原存储或校验错误的类别、原生错误码及直接原因，不以日志错误替代；公开说明仅增加日志错误类别，原记录位置与日志错误正文只保留在原异常诊断中。失败不发布候选状态，原占用与外部资源保持，后续显式重试仍沿原 owner

#### Scenario: 普通工具派发后的失败收尾也无法写盘

- **WHEN** Terminal普通调用、workspace完成查询或Browser动作已进入外部回调，但未取得可提交的正式回执，随后原unknown账本或owner记录写入也失败
- **THEN** 派发前已在原账本持久保护同一lease；operation和Turn普通收尾保留待核实占用，普通存活查询不能消除，冷恢复与显式管理停止仍按原身份核实后才结清。正式成功或完整已核实失败回执须先校验并持久提交，再解除本次派发保护；不重放原动作，不由普通占用释放推断资源已停止。准备写失败不得进入外部回调；准备在线程池排队时取消或关闭不开始新写入，已开始的原写入持锁结算。仍在场的原调用证明尚未派发时可撤回准备，撤回失败保留保护及原错误；清单缺失不能代替该证明。创建、版本管理及传输授权的派发保护按各自未完成任务继续验收

#### Scenario: 资源记录原生写入尚未结算

- **WHEN** Terminal或Browser记录的序列化、fsync或replace在线程池排队或执行，另一个资源请求写入或原调用被取消
- **THEN** 全部writer等待唯一异步save，文件写锁覆盖worker结算，后写合并此前已发布的资源记录；事件循环继续响应，原资源锁和准入不提前释放。取消不得遗弃worker或提前结清原lease，unknown写盘作为原失败的受保护收尾，后续取消不得丢失原错误；本地版本已发布但外部同步未核实则沿原pending等待显式stop/delete核实，不在普通查询重发；fork已持久committed回执仍为提交证明，未提交回执保留待核实身份。冷恢复用唯一准备锁覆盖版本冻结与pending发布，取消等原准备结算且重试不再推进版本；原生I/O不可抢占、同步lease账本及完整shutdown仍由后续任务验收

#### Scenario: 首条创建 intent 写盘后原调用尚未派发即取消

- **WHEN** 原调用在首条资源记录写盘时被取消，worker 已提交该 intent，但原调用尚未进入外部创建回调、登记 operation lease 或派发创建
- **THEN** 原调用持有原资源锁和准入，将已持久 intent 沿同一 owner 记录链关闭为 deleted/verified，解除关联并将原账本身份同步为 stopped；不补造 operation lease 或外部创建/停止/删除回执。重复取消不得中断该收尾；记录持久成功后才发布账本终态，收尾失败须同时保留原取消及原生存储错误，不宣称已完成。成功后列表不再暴露活动资源，详情与冷重建保留同一终态和版本。此证明只来自仍在场的原调用，旧 intent、清单缺失或缺少 lease 本身不能推断未创建

#### Scenario: 原生 worker 完成时交付调用者取消

- **WHEN** 原生 worker 已完成，外部取消与原调用恢复执行或继续等待下一个步骤竞争
- **THEN** 同步 worker 原语不在成功或原生失败后另建受保护收尾等待；调用者已接受的取消必须继续传播，不能吞掉取消后返回成功或继续无限等待。取消发生于 worker 仍在执行时，仍等待该 worker 结算并保持原锁和准入，重复取消不遗弃它；原生失败保持原异常身份及原取消上下文。取消请求发生在调用任务已结束后可明确返回未接受，但不能伪报取消已接受

#### Scenario: Terminal 完成监控关闭时原扫描消耗取消

- **WHEN** 原 Terminal steering 扫描的受保护收尾消耗了关闭取消，并在结算后正常返回
- **THEN** 关闭请求先禁止下一轮扫描；原扫描结束后监控直接退出，不再轮询睡眠或接纳下一轮。原任务结算前保留唯一句柄，重入关闭继续等待该任务，不重复派发关闭取消或创建另一个监控；正常结束后方可移除句柄。该准入规则不构成不合作扫描可强制终止、关闭观察者取消或完整 shutdown 硬期限的证明

#### Scenario: Terminal 监控关闭观察取消与原任务失败

- **WHEN** Terminal 监控关闭尚未取得原任务结果时，关闭观察者被取消，或原监控在关闭前／收尾期间失败
- **THEN** 观察取消继续交回该观察者，不再次取消原监控；保留同一任务供重入关闭取得真实结果。原非取消失败必须按原异常交回关闭调用方，不能仅记录日志后假报成功；关闭期间的连接、超时或资源待核实错误也不得按正常轮询的稍后重试处理而消耗。Workspace／Backend 保留未完成阶段及后续依赖，由同入口重试继续，不重新启动失败监控或重放已完成通知。正常的监控停止取消可以结算成功；该规则不构成不合作扫描可强制终止或整个进程退出硬期限的证明

#### Scenario: Terminal 监控关闭观察到期

- **WHEN** 事件循环正常调度，但原 Terminal 完成监控的扫描在关闭后仍未结算
- **THEN** 每次关闭调用最多观察30秒，到期明确报告原任务仍未排空；原任务、关闭准入和Workspace后续依赖保持。重入只观察同一原任务，不再次派发取消或启动新监控；原任务迟到成功或失败后，仍由同一关闭入口取得真实结果并继续原生命周期步骤。观察期限不表示扫描已终止，也不构成同步阻塞可抢占或整个shutdown硬期限的证明

#### Scenario: 创建请求取消或回执丢失

- **WHEN** 创建 intent 已登记原 operation lease，但创建 HTTP 请求被取消、超时或未收到正式结果
- **THEN** 原 lease 保持待核实并跨调用收尾、Turn 清理和重启保留；存活快照不能自动核实创建结果，只有原 owner 核实终态或本次正式创建结果后才能结清

#### Scenario: 创建在接纳前明确拒绝

- **WHEN** 外部 owner 确认尚未接纳具有唯一 resource/workspace/revision 的本次创建，并返回绑定该 intent 的正式未创建回执
- **THEN** Python owner 核对身份与版本后关闭该 intent、解除关联并结清其原占用；普通 HTTP 错误、冲突身份和其它创建的回执不得触发同样处理

#### Scenario: Terminal 在就绪前退出并取得停止证明

- **WHEN** 已接纳的 Terminal 在就绪前退出，原 Worker 沿唯一进程树终止链核实停止，宿主确认 Worker 退出且终态持久化成功
- **THEN** 外部 owner 保留原资源身份与恢复记录，返回绑定本次 intent 的正式失败回执和 verified 终态快照；Python owner 核对身份、整数版本及终态后结清本次 lease 和受管工作目录占用，回执丢失后可从原终态记录恢复对账，不重放创建

#### Scenario: Terminal 启动失败后原生身份及停止回执迟到

- **WHEN** 原启动已失败或超时，同一仍在收尾的 Worker 随后首次交付合法原生 PID，并沿原停止链返回绑定该 PID 的真实进程树结果
- **THEN** 宿主保留原身份和正式停止结果，不恢复就绪、不替换已有 PID，也不重放创建或停止信号；Session 等待原 Worker 退出，取得原停止证明并持久化终态后才签创建失败回执。没有停止证明或结果未核实，仍保留原身份及 created/unknown，不以 Worker 退出代替进程树停止。该规则不证明始终没有原生身份、Backend 已退出或停止回执丢失后的操作已经接管

#### Scenario: 停止证明丢失后沿原创建身份管理恢复

- **WHEN** 同一 Worker 已交付原 PID 及真实进程组、系统 session、启动标记，但正式停止证明丢失，资源保持 created/unknown，当前或硬重启后的 Node Manager 接到用户显式 kill/delete
- **THEN** 正常启动与失败收尾均复用 Worker 原读取的身份写入唯一恢复记录，不在宿主重新采样创建标记。Manager 读取记录不自动结清；原管理入口核实该实例与原系统 session，持久终态成功后才返回核实结果，保持原资源和版本身份，不重放创建。缺少完整原生身份仍明确拒绝，不用 Worker 退出、缺根或时间到期替代进程树停止证明

#### Scenario: 启动异常尚无进程树停止证明

- **WHEN** native 启动抛错、Worker 异常退出或清理失败，尚未取得本次 PTY 进程树的正式停止证明
- **THEN** 外部 owner 保留已取得的原身份与未知记录，不签发未创建或已停止回执；Python 保留本次待核实 lease，Worker 退出、已发送信号及普通 HTTP 错误均不能代替停止证明

#### Scenario: Terminal 原生创建前发布恢复意图

- **WHEN** Node接纳具有合法资源、工作区及版本身份的Terminal创建
- **THEN** 在调用原生启动前先经既有writer发布同一资源的created/unknown恢复记录；就绪后沿原身份和记录链核实。首条意图写入失败时，只有仍在场且确认尚未调用启动的原调用，才能持久关闭该身份并返回绑定本次intent的not_created回执；收尾再次失败保留unknown和按发生顺序的两份原错，不签未创建回执。Node在就绪交付前硬退出后，冷Manager仍可发现原意图，不能用缺少PID、Worker退出或原进程已消失替代停止证明，也不允许迟到创建覆盖该身份；没有原生身份的终止接管仍须另行核实

#### Scenario: Terminal 待核实删除不受历史配额裁剪

- **WHEN** Terminal在冷启动或接纳新建前裁剪已删除历史
- **THEN** 仅deleted/verified记录参与原256条历史配额及排序；deleted/unknown和deleted/reconcile_required保持原恢复记录、资源身份与版本，不占已核实历史配额，也不能被迟到创建覆盖。裁剪不能作为原操作已停止或已核实的证明

#### Scenario: Browser 原生创建前发布恢复意图

- **WHEN** Browser原生context创建尚未派发或就绪回执尚未交给Session
- **THEN** 原Manager先经唯一writer发布同一资源的created/unknown；首次导航完成后才核实并完成原最终保存。意图写入失败时，只有仍在场且确认start未派发的原调用才能沿原失败关闭链持久保存failed/verified后签not_created；收尾失败保留unknown、原错误及收尾错误且不签回执。created记录的close/delete明确409/browser_creation_unverified，不以空context核实停止，也不改变原创建的操作准入；原调用可继续完成创建及后续交互。Node硬退出后的冷Manager保留原意图并拒绝同身份重复创建，没有原context身份的旧代接管另行核实

#### Scenario: Terminal 原生创建后就绪交付失败

- **WHEN** 原生PTY已创建并交付唯一PID，但就绪前发生错误、超时或Worker退出
- **THEN** 外部owner保留原PID和unknown，沿原进程树停止链核实PTY及后代、确认Worker退出并持久化终态后，才返回本次intent的正式failed回执；停止失败保留原句柄及可查询记录，允许原管理停止入口重试同一执行。就绪和正式清理回执必须匹配已交付PID，晚到消息不得替换原身份。尚无原生PID的创建不得凭Worker退出或管理调用伪报已停止

#### Scenario: Terminal 关闭与在途创建共享原任务

- **WHEN** Terminal Manager关闭时仍有容量排队、异步工作目录检查或已登记Session的启动尚未完成
- **THEN** 立即停止新创建准入，等待原容量队尾排空后处理最终终端集合；尚未登记Session的排队及准备请求重核准入并以绑定本次合法intent的not_created回执拒绝，身份冲突不签该回执。已登记启动的迟到就绪仍进入原关闭链，未知启动明确拒绝关闭，不能假报已停止。一次关闭调用默认最多观察5秒，到期保留原执行并明确失败；重叠调用复用原执行，全部资源及最终写盘真正排空并失败后才允许重试。普通信号关闭失败保留原进程和HTTP管理入口，可再次信号重试；未捕获异常和未处理rejection保持退出1，关闭中到达的致命错误也不能被去重忽略。运行中PTY沿既有Manager退出合同保留并标记待恢复核实，不把该观察预算称为整个进程退出总期限

#### Scenario: Terminal 工作目录检查在线程池排队

- **WHEN** 唯一工作目录检查的原生stat仍在线程池排队
- **THEN** 使用异步文件检查，原创建仍由容量队尾持有，事件循环可服务其它HTTP查询；关闭后检查返回须重核准入。路径解析、工作区外绝对路径、目标平台语义和原始诊断cause保持原合同，持久记录继续使用相对表达，不增加同步兼容入口，也不将等待到期当作原生文件操作已取消

#### Scenario: 正式停止回执必须属于本次版本

- **WHEN** Terminal 或 Browser 的停止/删除请求收到完整外部回执
- **THEN** owner 在更新终态和结清占用前核对资源、工作区及本次发布的整数版本；旧版本、未来版本或布尔版本均不得作为本次成功证明，冲突保留原精确 lease 与待核实状态

#### Scenario: Browser 操作的失败回执校验或提交再次失败

- **WHEN** 工具或管理操作收到Browser成功或正式失败回执
- **THEN** 两种回执共用资源身份、工作区、本次整数版本、核实状态、投影与持久提交链；旧版本、未来版本、非法身份或回执处理/提交失败均保留本次精确lease及unknown，不因异常发生在失败处理分支而普通释放。处理失败保留原Browser异常为cause；正式失败报告未核实页面转换时继续返回原HTTP错误并保护占用，完整已核实失败继续抛出原异常并正常释放本次lease。存活查询不证明旧动作成功，只有原owner核实终态后才结清待核实占用

#### Scenario: Terminal 普通调用与工作区完成共用回执核验

- **WHEN** Terminal工具查询、读写、后台或steering操作，以及workspace终端的命令完成查询收到外部回执
- **THEN** 在原资源锁内复用同一核验、持久提交与投影链，先核对资源、工作区、本次整数版本及verified；错误版本、身份冲突、未知或缺失回执不得成功或普通释放本次精确lease，受管工作目录继续保活。工作区完成查询取得真实已核实终态时提交该事实并结清目录占用，保留workspace资源记录及Thread关联，正常operation占用仍按原规则收尾；存活查询不能结清此前未核实的动作

#### Scenario: Terminal 停止确认或终态写盘失败

- **WHEN** 原 PTY 进程树已进入停止链，但 Worker 退出未确认或最终终态写盘失败
- **THEN** 保留原 Worker 句柄和未知状态，不提前发布停止完成事件；显式重试复用原执行及唯一停止链，只有进程树停止、Worker 退出确认与终态写盘均成功后才清除句柄和返回成功；未知状态写盘也失败时保留两份原异常及因果关系

#### Scenario: Terminal 自发退出后隔离 Worker 仍未退出

- **WHEN** PTY 自发退出并交付原退出观察，但隔离 Worker 尚未确认退出，或其关闭期限内未能退出
- **THEN** 复用原 Worker 关闭入口等待确认，期间保留原句柄和 unknown；重叠关闭共享唯一在途任务，不能重复派发或提前成功，迟到退出处理不得覆盖原管理停止结果。关闭失败发布 exited/unknown 及原诊断，原 kill/delete 管理入口可重试同一执行，不重建 Worker 或将 PTY 退出当作宿主停止证明。已经确认退出的 Worker 才可移除句柄；正常自发退出确认后恢复原 verified 状态

#### Scenario: Linux 旧代终端的执行根退出但原 SID 仍有后代

- **WHEN** 原停止失败已保留完整进程身份和 unknown，Worker 已退出，随后 Linux PTY 根进程自行退出，同一 Manager 或冷 Manager 收到显式 kill/delete
- **THEN** 原 PID、进程组与 SID 符合原 PTY 根身份时，根进程缺失不提前拒绝或签发停止成功；继续沿既有进程树停止链核实原 SID 的全部后代，真实终态及原记录落盘后才发布 verified。缺失身份、仍存在但身份不符的 PID 继续拒绝，不重建终端、不重放旧操作

#### Scenario: POSIX 终端在停止快照后创建后代

- **WHEN** 原停止链捕获的 PID 收到 SIGTERM 或 SIGKILL 后退出，但快照到信号生效之间创建了同一操作系统 session 的新后代
- **THEN** 复用首次取得的 session 与启动身份，在宽限等待结束后重新核对整个 session；SIGTERM 阶段遗留后代沿原强杀链处理，强杀阶段仍发现存活后代则返回未停止，不凭旧 PID 集合退出发布成功或结清目录占用。根 PID 已回收不得丢失原 session，身份不匹配时继续保护无关进程

#### Scenario: Browser 已关闭运行时但最终发布失败

- **WHEN** Browser 已关闭原 context，但删除检查点或最终终态写盘失败
- **THEN** 原外部 owner 将该关闭结果保留为 unknown 并明确返回失败，Python 保留原精确 operation lease；下一次显式关闭沿原转换链完成检查点删除与终态落盘，不能凭内存中的 deleted 状态提前返回成功，也不能创建替代 context；关闭与 unknown 写盘都失败时保留两份异常及 cause

#### Scenario: Browser 工具超时后原脚本仍在执行

- **WHEN** 工具等待已经超时、页面已重置，但原脚本或页面恢复尚未结束，用户从原入口发起停止或删除
- **THEN** 原脚本与恢复句柄继续保存在同一操作队列；关闭context后仍用默认五秒单次预算排空，等待期间新增的执行句柄不遗漏、不重置预算。未排空明确返回408与unknown，不发布已核实终态；原执行结束后同身份/版本重试完成原关闭链，不重复关闭context，也不把超时当作脚本终止证明

#### Scenario: 未知资源由新管理操作核实停止

- **WHEN** 用户从现有资源管理入口对 unknown 或 reconcile_required 的资源显式发起 stop，或对无关联资源显式发起 delete
- **THEN** owner 先核对外部资源身份与当前传输版本；已有正式终态时只对账，否则为新管理请求创建独立 operation lease，提升并同步版本后复用原停止链；本次正式终态回执与 owner 持久化成功后才结清原待核实占用，不能把新停止当作旧工具动作成功

#### Scenario: 显式停止不能绕过仍有效的操作或复用未知身份

- **WHEN** 管理停止仍遇到 active lease、重复的未知 operation 身份、不匹配的外部版本或尚未核实完成的删除
- **THEN** 原 owner 明确拒绝冲突并保留原占用；普通资源列表为身份和版本可核对的未知资源提供候选停止/删除动作，使用、关联和授权仍须 verified；自动恢复、卸载与扫描不得据此重发未知副作用，缺少外部身份或 native 停止证明仍保持待核实

#### Scenario: 冷恢复取消后显式停止等待关闭的旧执行

- **WHEN** 普通冷恢复已冻结并发送授权版本，但等待旧执行排空时被取消，用户随后从原管理入口显式发起stop/delete
- **THEN** 原owner在同一资源锁内先核expected_revision、active lease和delete关联限制，再以停止意图同步尚未完成的同一冻结版本；不先等待依赖context关闭才能结束的旧执行。实际关闭、原执行排空、当前版本终态提交与原占用结清继续复用唯一停止链；普通访问仍使用普通排空。过期版本或仍有关联的delete在撤权前明确拒绝，保留原pending、记录及占用；取消本次同步仍保留未核实版本，不把停止准备当作真实停止证明

### Requirement: 单个 Thread 清理失败不得停止其它 Thread 的周期回收

闲置清理 SHALL 独立尝试每个候选 Thread；失败 SHALL 保留该 Thread 的 scope/generation 和未核实资源，并明确报告 owner 与原始原因。事件循环正常调度时，扫描对单个卸载任务的等待 SHALL 最多为 30 秒，到期明确报告尚未完成并继续其它候选 Thread。该预算 MUST NOT 被解释为外部资源已经停止；唯一在途卸载任务 SHALL 继续由原 owner 持有，后续扫描 MUST NOT 为同代重复发起清理，新 admission MUST 等原任务完成。迟到成功 SHALL 沿原链释放，迟到失败 SHALL 记录原始原因并保留状态供后续周期重试。周期 worker SHALL 记录整批异常并继续原周期，不得因单项失败永久停止或把失败声明为已卸载；任务取消与关闭 MUST 正常传播。

#### Scenario: 一个资源 owner 暂时不可达

- **WHEN** 两个 Thread 同时到达卸载条件，第一个 Thread 的清理回执失败
- **THEN** 第二个 Thread 仍完成卸载，第一个保持待清理，错误可见且后续周期继续重试，核实成功后才报告该 Thread 已释放

#### Scenario: 清理回调超过本轮等待预算

- **WHEN** 第一个 Thread 的 listener 或 scope close 尚未完成，扫描等待达到 30 秒
- **THEN** 本轮报告精确 owner/generation 的等待超时并检查其它候选；原任务不被取消、资源不被标记为已释放；再次扫描不会重复启动清理，新 admission 不能复用仍在卸载的 runtime

#### Scenario: 超时后才收到清理失败回执

- **WHEN** 本轮已结束等待，原卸载任务随后收到真实失败
- **THEN** 后台回调完整记录原错误和 owner，保留失败 scope/generation，后续周期可以沿原 owner 重试，不能丢失异常或提前创建下一代 runtime

### Requirement: 挂起操作的终止与关闭期限必须由原 owner 核实

扫描等待预算 SHALL 与真实 operation 的截止时间和终止事实分开。挂起资源操作 SHALL 由原执行 owner 在截止时间后取消或终止并核实；锁等待、线程池排队、多次网络调用和迟到回执 SHALL 纳入同一 operation 的处理，MUST NOT 仅依靠单次 HTTP 超时。无关资源 SHALL 不因另一个挂起操作无限等待共享 owner 锁；同步阻塞代码 SHALL 不阻断整个事件循环的扫描与诊断。换代 admission、Session 删除和 shutdown SHALL 有明确等待期限及失败返回，期限到达时保留原未核实资源、lease、scope 和必要 locator，MUST NOT 在仍有副作用时宣称排空或物理删除恢复依据。该完整合同属于后续 5.4，本轮扫描有界等待不足以证明它已经实现。

#### Scenario: 挂起释放占有共享 owner 锁

- **WHEN** 一个资源的真实释放未收到回执，其它无关资源也需要同一 owner 处理
- **THEN** 无关资源能够独立推进，挂起操作保持唯一执行身份并交由原 owner 终止核实，不通过丢弃锁内任务或重发删除伪造进度

#### Scenario: Windows 终止工具尚未返回

- **WHEN** Terminal 原进程树停止链正在等待 `taskkill /T /F /PID` 回执
- **THEN** 工具通过原异步子进程入口执行，保留原 1500 毫秒调用上限，辅助服务事件循环仍能处理其它请求。启动、非零退出、信号及超时错误保留原始原因和诊断；工具被期限终止时不得仅凭根进程消失忽略失败。正常回执后仍沿原存在性轮询核实退出，不把命令派发或回执成功当作进程树已经停止，也不将本工具上限视为整个关闭期限

#### Scenario: 聚合列表等待外部清单

- **WHEN** Terminal或Browser列表正在等待本次外部清单，另一请求需要查询、管理或操作其中某个资源
- **THEN** 列表不跨网络持有资源锁，独立请求沿原资源锁推进；列表取得一次清单后逐资源加锁并重检过滤及已核实删除状态。仍应返回的资源完整持久记录已变化时明确返回冲突，不应用迟到观察；同版本的外部状态更新也受保护，不只比较owner_revision。取消未返回的清单不发布观察，不自动重发查询；整批释放的全量preflight合同保持

#### Scenario: 单次领域列表耗尽总等待预算

- **WHEN** Terminal或Browser的原领域列表仍在等待准备、所选资源恢复、外部清单或逐资源锁
- **THEN** 全部阶段共用入口取得的一次30秒协作式等待预算，阶段切换不重置；到期排空本调用的等待并明确失败，不返回不完整清单。已经持久提交的恢复或观察保留，尚未开始的观察不补造unknown、lease或外部动作，原资源与占用不因读取到期被释放。底层TimeoutError与调用方取消保持原归属，解除故障后显式读取沿同一入口重试，不后台补发清单。领域预算仍受公共HTTP列表入口的剩余预算约束；同步存储和不合作取消仍须后续验收

#### Scenario: 公共资源列表跨领域耗尽同一次预算

- **WHEN** Workspace的公共资源列表HTTP入口依次查询Terminal和Browser，或按kind只查询其中一个领域
- **THEN** 原查询顺序、过滤和领域owner保持，所有所选领域共用HTTP入口取得的一次30秒协作式等待预算，切换领域不重置；到期排空当前等待，沿既有错误合同返回503与原request_id，不返回部分清单。先前持久提交的观察保留，未完成的读取不改写原资源或lease；调用方取消与底层传输错误保持归属，解除故障后由同一入口显式重试，不后台补做。该预算只约束此HTTP入口的领域等待，不扩张到Session资源展示投影、同步存储/序列化或不合作取消，也不证明外部进程已停止

#### Scenario: 单次资源详情耗尽总等待预算

- **WHEN** Terminal或Browser的原详情查询等待冷恢复、资源锁或外部清单
- **THEN** 全部阶段共用入口取得的一次30秒协作式等待预算，阶段切换不重置；到期排空本次等待，沿原HTTP错误合同返回503与原request_id，不以旧快照伪造本次读取成功。已提交的冷恢复版本与核实结果保留，尚未核实的恢复授权仍按原合同处理；详情读取自身不补造unknown或新lease，不释放原资源或其它调用持有的锁与占用。底层TimeoutError及调用方取消保持归属，无关资源可继续查询，解除故障后由同一详情入口显式重试，不后台补做。同步存储与不合作取消仍须后续验收，不把读取到期当作外部资源已停止

#### Scenario: 单次资源传输授权耗尽总等待预算

- **WHEN** Terminal或Browser的传输授权等待原终态预检锁、冷恢复、Thread准入、签发锁、运行快照或授权回执
- **THEN** 全部阶段共用入口取得的一次30秒协作式等待预算，阶段切换不重置；到期排空本次等待，沿原HTTP合同返回503与原request_id。派发前不补造lease或unknown，已派发未核实沿原授权链保留unknown和本次精确占用，已提交的恢复版本不回滚；放行回执不后台补签，无关资源仍可授权。底层TimeoutError及调用方取消保持归属；存活查询不结清未知授权，只有原管理owner核实终态后才settle并拒绝新授权，不把等待结束当成外部授权已撤销或资源已停止。同步存储与不合作取消仍须后续验收

#### Scenario: 同批临时孤儿回收遇到挂起资源

- **WHEN** Terminal或Browser原孤儿回收入口中，一个资源等待冷恢复授权、资源锁或删除回执
- **THEN** 同批其它资源独立沿原锁完成恢复及删除前复核，关联、有效lease、原30分钟期限和workspace保留规则仍阻断不应删除的资源；结果或原始错误按原资源顺序汇总。一次回收的准备、恢复、锁、撤权与删除共用入口取得的30秒预算，阶段切换不重置；协作式到期取消并排空本调用等待，已派发未核实的操作保留unknown与精确原占用，未开始的操作不补造unknown，已完成的终态不回滚。后续周期不自动重发未知删除，显式管理仍须原owner核实；调用方取消和传输原始超时保持归属，预算到期不证明外部进程已停止

#### Scenario: 孤儿回收中断时已有资源失败

- **WHEN** Terminal或Browser同批孤儿回收中部分资源已返回失败，另一项仍等待回执，随后整批到期或调用者取消
- **THEN** 排空本次任务后按原资源选择顺序保留此前的原异常对象；预算到期将其与本次TimeoutError共同聚合，调用者取消保持原CancelledError和消息，并以聚合cause保留此前失败。未核实项继续保留原unknown、版本与精确lease，成功项不回滚；后续周期不得重发未知删除，原显式管理入口核实已执行的终态后才结清原占用

#### Scenario: Thread准入短锁与长资源操作隔离

- **WHEN** Terminal或Browser进入来源Thread准入，并在真实工具操作及收尾期间等待网络或资源锁
- **THEN** 在短Session写准入内从权威catalog核定workspace与精确Thread，省略Thread仍只解析canonical main；Session独占锁不跨真实工具执行。同一Session的无关资源可以独立准入，原operation由共用`workspace_resources` namespace的Session shared OS holder保护；holder先于Session锁取得，删除只登记该namespace一次，先等待holder退出再取得Session锁并清理，不增加另一份业务lease或推断外部终态。holder等待、Session锁与准入读取共用入口一次30秒协作式预算，到期/取消排空本次准入并保留原错误归属，尚未进入主体不创建资源、lease或unknown，不后台补做；deleting Session拒绝新准入。成功准入后预算退出，holder覆盖真实operation及原受保护收尾；此前冷恢复、同步阻塞、不合作取消及整个operation/shutdown期限仍属5.4后续验收

#### Scenario: Session与资源Thread准入等待同步存储

- **WHEN** Session读写准入或Terminal/Browser的Thread准入在active核验、Session目录、canonical main或显式Thread定位时等待同步I/O、catalog连接锁或线程池
- **THEN** 复用原同步查询与受保护worker，原topology/Session gate及已取得的资源holder覆盖该调用真实结算，不阻断事件循环及不依赖该存储的HTTP查询；取消或外层期限到达后不遗弃已提交调用、不提前释放原gate，也不进入后续准入或资源创建。工作区归属、冻结Thread身份、目录核验、原异常及DTO投影保持原合同，不新增查询链或业务lease；正常重试沿原入口完成。worker不能抢占原生I/O，不将协作式等待预算称为线程终止或整个operation/shutdown硬期限

#### Scenario: Terminal 创建的 cwd 解析尚未结算

- **WHEN** Terminal 创建已经取得原 Thread holder，而相对路径、原生绝对路径或目录 URI 的解析仍等待文件系统、同机 Gateway 或线程池
- **THEN** 同一个目录解析调用由既有受保护 worker 执行并保留请求上下文，事件循环及不依赖该等待的资源查询可以继续；原 holder 覆盖排队与执行，取消须等原调用结算后传播，不提前创建资源 intent、lease 或 PTY，不在取消后后台补做。相对输入锚定目标工作区，工作区外绝对路径及目标平台语义保持，URI 仍由原文件 owner 核对目标和权限，原失败及因果关系保持；本等待不构成原生 I/O 可抢占或整个 operation/shutdown 有硬期限的证明

#### Scenario: 工具方法的资源准入等待到期

- **WHEN** Terminal或Browser的单次工具方法等待所选资源冷恢复或原资源锁
- **THEN** 冷恢复、资源锁、校验及取得原lease共用入口取得的一次30秒协作式预算，阶段不重置；到期排空本次等待并明确报告operation、holder及资源身份。保留已提交恢复版本和已有精确占用，尚未派发不补造unknown或新lease，不释放其它调用的锁，解锁后不后台补做；底层TimeoutError与调用者取消保持归属，显式重试仍沿原owner。成功准入后原锁继续覆盖真实工具执行，准入预算退出，不将后续执行误判为准入超时；Thread准入、同步阻塞、不合作取消、整个工具operation及shutdown的完整期限仍属5.4后续验收

#### Scenario: 单次 operation 的部分占用无法释放

- **WHEN** Terminal 或 Browser operation 关闭时，一个资源锁尚被占用或其原 lease 释放写盘失败
- **THEN** 其它资源的占用独立释放，全批共用入口取得的一次30秒协作式等待预算；阶段与资源切换不重置。到期取消并排空本次锁等待，明确报告operation、holder和未释放资源；此前已返回的释放错误与预算错误一并保留，原底层TimeoutError不冒充整批期限。失败保留精确未释放lease，持久成功前不遗忘引用；释放锁后不后台补做释放，同operation显式重试复用原占用。调用方取消保留原CancelledError及消息，先前释放错误按资源顺序聚合为其cause，没有先前错误时不增加cause。不得虚报释放、停止真实资源或将未知/已核实终态的占用改写为普通释放；同步写盘及不合作取消仍须单独验收

#### Scenario: 单次资源管理命令耗尽总等待预算

- **WHEN** Terminal 或 Browser 的 promote/attach/detach/stop/delete 管理命令等待冷恢复、Thread准入、资源锁、授权同步或正式回执
- **THEN** 全链共用入口取得的一次30秒协作式等待预算，阶段不重置；到期明确失败且不声明外部操作已经停止。管理动作尚未派发时不补造unknown或管理lease，已提交的冷恢复事实保留；已经派发但未核实的命令沿原异常链保留unknown及精确占用，外部回执迟到不发布成功。无关资源继续独立推进，新管理请求沿原owner核实已提交终态，不重发已完成停止；底层TimeoutError和调用方取消保持归属。该预算不证明同步阻塞可抢占、不合作执行可终止或整个工具operation已有总期限

#### Scenario: Fork 已发布目标的运行资源关联等待到期

- **WHEN** fork已发布目标，原Terminal或Browser资源关联仍等待恢复、回执查询锁、Thread准入、提交锁或原attach回执
- **THEN** 单次关联从入口共用一次30秒协作式预算，阶段不重置；到期保留已发布目标与已提交恢复事实，关联尚未派发不创建该关联回执或lease，派发未核实保留原dispatching/unknown及精确占用，已提交的关联和committed回执不回滚。公开fork沿原逐资源结算合同返回不可用原因与实际operation状态；释放原锁后不后台补做，同key显式重试复用原目标与回执，不重发未知动作或重复关联。原取消及底层异常保持归属；本预算不替代整个fork期限，也不证明同步存储可抢占或外部操作已停止

#### Scenario: Fork 冻结文件传输的原生 I/O 尚未结算

- **WHEN** 来源导出或目标接收在原生文件读取、写入、同步、关闭、核验或清理中等待，或尚在线程池排队，此时调用取消或外层等待截止到达
- **THEN** 原调用与导出/创建锁覆盖原 worker 的实际结算，未返回的打开句柄也有明确归属并最终关闭；接收任务先排空原写入者再清理临时快照，不遗弃后台写入、不重放或提前发布。冻结字节、长度/hash、marker 顺序和正文/关闭原错误链保持，不能读取 live 来源补造历史或把等待截止当作原生 I/O 已停止

#### Scenario: 批量 runtime 关闭中一个 Thread 挂起或失败

- **WHEN** Session 或服务关闭时，一个 Thread 的原构建、runtime lease、listener 或 scope 尚未完成
- **THEN** 事件循环可正常调度时，其它选中 Thread 独立推进原排空链；同一 Thread 的重入关闭复用原 build/unload，单次 Session 或全局 runtime 关闭全批共用原 30 秒等待预算。取消仅排空本次等待者，原任务与 scope/generation 继续由原 owner 持有；各 Thread 的原异常按输入 owner 顺序汇总，重试沿原 owner 继续，不重发已完成清理。Backend按以下整批观察预算与依赖关闭规则保留原存储；生产进程退出及不合作操作的终止仍须单独核实，不把其它Thread排空成功视为整体关闭完成

#### Scenario: 驻留扫描关闭观察取消或到期

- **WHEN** Agent驻留服务关闭时，原扫描或generation scope尚未结算，关闭观察被取消或本次30秒观察到期
- **THEN** 保留唯一关闭任务及新准入关闭状态，扫描结算前不丢失其句柄、不提前清缓存；取消观察者不再次取消原扫描，重入复用原任务。扫描的受保护收尾返回后不再开启下一轮；关闭期间的普通原错不得作为周期重试消耗。迟到失败先交付观察者，后续显式调用才重试剩余tracker排空，成功重复关闭不产生新副作用；Workspace保留失败步骤、后续存储及Backend维护锁，其它挂载独立关闭。原生I/O抢占、外部停止证明和整个shutdown硬期限仍分别验收

#### Scenario: Backend 关闭失败后保留依赖并重试

- **WHEN** Backend 关闭时，某挂载的 writer、runtime、附件或 catalog 尚未完成或返回失败
- **THEN** 按挂载逆序发起全部原关闭入口，独立挂载并行推进，同一挂载内部仍按依赖顺序关闭；单项挂起或失败不阻止其它挂载。原Workspace只移除成功的关闭步骤，保留失败步骤和后续依赖。全部 Workspace 排空前不关闭 catalog，任一Workspace或catalog关闭未完成前不归还维护锁，原生命周期在全部步骤成功前不被覆盖。沿同入口重试原步骤，不重复已完成副作用，业务及关闭原错均保留；MCP scope 的启动与重试关闭始终在同一原任务中完成。catalog 物理关闭失败可重试，事务回滚失败的连接立即禁止业务访问而不宣称已物理释放。全部阶段共用下述Backend观察预算，但不等于生产进程或外部操作已核实停止

#### Scenario: Workspace周期任务失败后关闭与重试

- **WHEN** 工作区的活动清理、资源回收或fork清理周期任务已失败，或在关闭取消后的原收尾中返回失败
- **THEN** 原任务结束时记录任务身份及完整原异常；关闭先取消本工作区全部周期任务并排空，再按原登记顺序聚合非取消异常。失败明确交回关闭调用方，本次不释放该工作区后续依赖或Backend维护锁；已结算的周期任务从待关闭集合移除，同入口重试继续剩余依赖，不重发周期工作或重复报告已交回的同一错误。普通关闭取消与正常完成不冒充失败；其它挂载仍独立关闭，原同步阻塞和整个进程退出期限仍须分别核实

#### Scenario: Backend整批关闭等待超过期限

- **WHEN** Backend原关闭链的任一协作式等待在本次调用取得的一次30秒观察预算到期后仍未完成
- **THEN** 事件循环正常调度时明确返回当前阶段与未完成的工作区/步骤；workspaces、catalog、维护锁和model_stream阶段不重置预算。取消或到期不取消唯一原关闭owner，保留原生命周期和未释放依赖；其它挂载独立推进。后续调用复用仍在执行的owner，原owner失败后才沿原入口重试剩余步骤，已经成功的全局关闭不重复；迟到错误完整记录，原底层TimeoutError保持原身份。截止与已提交成功同时到达时以真实完成结果为准；该预算不构成同步阻塞可抢占、生产进程退出或外部终止证明

#### Scenario: 已接受但队列投影尚未发布的Job关闭

- **WHEN** 原Job的canonical准入已经提交，但队列装载失败，尚未建立FIFO条目或执行任务
- **THEN** 原Job保持accepted并可被取消或关闭排空发现；只有同一持久队列装载成功，才在调度锁内发布queued。取消先提交原canonical终态，不访问尚未建立的FIFO条目；关闭发布一次取消事件并刷新原快照版本，不虚报执行中断。终态写入失败保留原Job、准入身份和未完成关闭owner，沿原入口重试；正常执行重试也从同一持久队列装载，不另建Job、准入或执行链

#### Scenario: Backend关闭时消息仍在准备或线程提交

- **WHEN** 原发送已进入准备窗口，尚在上传、canonical提交或通过准入后的Job登记阶段，此时Backend开始关闭
- **THEN** 先撤销新准入，再通过现有准备计数等待原调用结束，随后才取得Job取消快照并继续终态与依赖关闭；准备等待与Session删除共用同一主体，不持调度锁等待、不取消原调用或新增账本。尚未通过Job准入的发送继续按原合同返回503，已持久输入和附件保留；已通过准入后迟到登记的Job仍进入原取消与终态写入。Backend观察到期或取消不取消原关闭owner、不提前关闭存储或归还维护锁，其它挂载继续独立关闭；原调用结束后同入口继续，不重发提交。该场景不证明线程可强制终止、事件循环阻塞可抢占或生产进程已经退出

#### Scenario: 准备调用重复取消时调度锁繁忙

- **WHEN** 已登记的准备调用被取消，此时其它Job持有调度锁，原调用又收到取消
- **THEN** 原调用结束时在所属事件循环同步归还自己的计数并唤醒原等待者，不为归还再次排队取锁或创建清理任务；保留原取消归属，不释放其它调用的锁、计数或队列，不留下没有活调用的准备计数阻断后续删除与关闭

#### Scenario: Catalog关闭等待原事务或线程池

- **WHEN** 全部Workspace已排空，而原catalog同步关闭仍在线程池排队，或等待另一线程持有的原SQLite事务锁
- **THEN** 原Backend关闭owner在线程中执行同一个registry关闭入口，排队前同步撤销装配准入；新服务图、catalog和registry作用域准入先拒绝已关闭状态，再在原锁内复核，不因关闭持锁阻断事件循环。线程排队与执行继续消耗本次Backend观察预算；到期或等待者取消仍保留同一执行、catalog记录、生命周期及维护锁，进程级诊断可继续响应。原事务结束后同一关闭任务继续后续依赖步骤，未核实完成前不能归还维护锁；不重复派发同步关闭，也不将等待超时当作原生线程已经停止。其它同步关闭、任意线程终止和生产进程退出期限仍须单独验收

#### Scenario: 文件存储关闭等待原事务

- **WHEN** 工作区文件worker已排空，原文件存储关闭仍等待另一线程持有的SQLite事务锁
- **THEN** 原Workspace任务通过既有同步I/O原语在线程中执行同一关闭调用，不阻塞事件循环；其它挂载与进程级诊断可继续。Backend观察到期仍保留原步骤、catalog、locator和维护锁，后续调用复用原owner，事务结束后才继续依赖关闭，不重复派发。MCP/AnyIO scope继续在原任务关闭，等待超时不构成原线程已经停止或整个shutdown完成的证明

#### Scenario: 附件catalog关闭等待原连接或线程池

- **WHEN** 工作区前序writer已排空，附件catalog的物理关闭仍在线程池排队，或等待原SQLite连接结束读取
- **THEN** 原Workspace关闭任务在线程中执行同一个关闭入口，排队前同步撤销附件准入；新访问在等待连接锁前拒绝，并保留锁内复核。Backend观察到期或取消不取消原执行、不提前遗忘连接或归还维护锁，独立挂载和进程级诊断可继续。原关闭完成后同一任务继续依赖关闭，失败沿原入口重试未关闭连接；已有目录、locator与canonical保持，不把观察结束当作物理关闭或原生线程终止证明

#### Scenario: Backend维护锁原生释放或线程池尚未结算

- **WHEN** 全部Workspace与catalog已排空，Backend原维护锁栈仍等待原生释放或线程池排队
- **THEN** 同一Backend关闭owner通过既有同步I/O原语执行原栈关闭，事件循环和进程级诊断继续响应。观察到期或等待者取消不遗弃原执行、不提前关闭模型传输或清除生命周期引用；尚未归还的锁继续由原栈持有，重入等待同一owner，实际结算后才继续。释放失败保留原异常；原栈已消费的回调不重发，失败步骤经同入口确认后才继续。该等待不改变底层句柄的异常语义，不证明任意线程可终止或完整shutdown有硬期限

#### Scenario: 活动记录库原生关闭或线程池尚未结算

- **WHEN** 工作区已注销活动监听，而原活动记录库关闭仍在线程池排队或等待原生文件句柄释放
- **THEN** 同一Workspace关闭任务通过既有同步I/O原语执行原关闭入口，事件循环和独立挂载仍可推进。Backend观察到期或取消仅结束本次观察，保留原关闭任务、当前步骤、catalog及维护锁；原生关闭实际结算后才继续后续依赖，不因重入重复释放。原错误继续经原入口返回并允许重试未完成步骤，持久活动记录及Session locator保持；该等待不证明原生线程可终止或整个shutdown有硬期限

#### Scenario: 文件worker停止仍有准备或原生写入在途

- **WHEN** 工作区文件owner停止时，已有请求正在准备持久受理、等待受理锁，或原worker仍在线程中发布文件
- **THEN** 停止入口先关闭新准入，锁内重核尚未接纳的请求并明确拒绝；已接纳的准备仍由原调用完成，原worker句柄保留到实际结束。取消停止等待只结束本次等待，不取消原worker；准备或写入未完成时拒绝关闭SQLite，Backend观察预算到期仍保留原关闭步骤、catalog与维护锁。原任务结束后沿同入口收敛，不重发写入；已持久受理但尚未执行的意图在下次启动按原ID恢复。此场景不证明任意线程可强制终止或同步阻塞可抢占

#### Scenario: Child准入的同步核对和记录冻结尚未结算

- **WHEN** child创建在原准入gate内核对catalog、控制库绑定和main指针，或建立creation record和冻结artifact清单时遇到原生I/O、SQLite锁等待或线程池排队，且调用被取消或外层期限到达
- **THEN** 同一worker沿原顺序完成这次准入核对与冻结，不阻塞事件循环；原topology shared、Session exclusive、同key锁和创建holder保持至原调用结算，再传播取消或期限错误，不进入后续目录准备或发布。实际提交的原record和清单供同key恢复，既有冲突和失败原样暴露，不重复分配child、不新建事务或恢复链；不将worker结算视为原生线程可强制终止或完整shutdown有硬期限

#### Scenario: Child发布及失败收尾的原存储调用尚未结算

- **WHEN** child创建在原gate内读取catalog并提交发布CAS、冲突后重读记录，或在原失败收尾/返回前读取和终结记录时，原I/O或线程池排队尚未结算且调用被取消或外层期限到达
- **THEN** 直接存储调用由既有worker执行，持有相应原gate、key锁和创建holder至该调用真实结算，再传播取消或期限错误，不执行本阶段后续动作。实际已发布的child与原冻结身份保留，同key重试跳过CAS并补齐原确认和附件结算；未发布失败仍按原清理和中止合同处理，实际aborted不得改写为preparing。确认回调及异步阶段观察仍在原事件循环和原gate内，失败不能倒删已发布目标；不将worker结算当作强制终止或完整shutdown硬期限的证明

#### Scenario: Child目录准备或恢复的原生调用尚未结算

- **WHEN** 已冻结的child创建正在探测目录、准备staging、rename及同步目录，或核验原final/已发布目标，且调用被取消或其外层期限到达
- **THEN** 原调用及线程池排队不阻塞事件循环，同key锁与原创建holder保持至该调用实际结算，再传播原取消或期限错误且不继续下一步骤。目录准备不持Session/topology gate；业务发布仍沿原gate和控制库事务。重试保留原record、child身份、locator与清单，已发布目标不因复验取消被倒删；原生调用结算不构成可强制终止或完整shutdown硬期限的证明

#### Scenario: Session 删除排空超过期限

- **WHEN** Session 删除仍在等待未核实的卸载操作且达到关闭期限
- **THEN** 导航删除入口取得一次30秒协作式等待截止，Job调度锁、已接纳准备窗口与子树删除owner共用；直接进入子树删除owner时才由该入口取得默认截止。包含同key锁、mark/finish拓扑gate及全部Session的retention、creation、holder、Session gate与资源drain，阶段切换不重置。准备阶段到期明确报告Session与阶段，子树阶段同时报告工作区、根节点与operation；保留原进度、未核实操作和恢复所需locator。准备等待不持调度锁，到期或取消不为归还本调用的准入标记再次等待该锁，不清除其它删除调用的标记；原准备任务、Job队列与runtime build/unload继续由原owner持有。传入截止已过时不得创建journal或mark，不能报告已删除后让原操作继续修改已移除的数据。底层owner自己的TimeoutError和调用者取消保留原归属；同步阻塞及不合作取消的完整期限与终止核实仍须单独验收

#### Scenario: 导航删除在逻辑提交前后耗尽预算

- **WHEN** 导航worker执行正式删除operation，原子mark之前或之后耗尽子树删除总预算
- **THEN** mark前沿原队列写入带`delete_wait_timeout`的rejected回执，节点保持active且不补造删除journal；mark后保持committed和`repair_required`，原journal、冻结locator与尚未隔离的源目录保留，重启原worker沿同一operation定点完成settlement。两种情况均保留可诊断原因，worker继续处理后续operation，不将等待预算耗尽当作worker自身故障或已完成物理删除

#### Scenario: Browser 关闭遇到已接纳的准备或交互操作

- **WHEN** Browser Manager 关闭时，原交互正在准备唤醒、串行排队或并发执行，包括资源仍显示为冷回收的准备窗口
- **THEN** 每个运行资源先关闭操作准入，再通过原队列的完整已接纳集合等待原操作；单次排空预算不随阶段重置，成功后才冻结和保存最终检查点，空闲冷资源保留原检查点；Session 排空超时保留原操作、连接与锁，明确失败，不以在途计数为零或冷状态宣称原操作已经结束

#### Scenario: Browser Manager 排空超时后保留恢复依据

- **WHEN** 原 Session 的已接纳操作在 Manager 关闭排空预算到期后仍未结束
- **THEN** Manager 继续检查其它资源并汇总原排空错误，明确返回关闭失败；不将超时资源改为 lost、不删除其原检查点或关闭共享运行时，原操作与关闭准入保持，原操作结束后可通过同一关闭入口重新捕获最终检查点并完成关闭

#### Scenario: Browser Manager 的多个资源共享排空预算

- **WHEN** Manager 关闭时当前多个运行资源仍有已接纳的准备或交互操作
- **THEN** 在等待第一个资源前关闭本批所有资源的操作准入，本批共用默认五秒的单调排空截止；后续资源只使用剩余预算，空集合可即时确认；超时按原资源汇总且保留原操作、检查点和共享运行时，不能将排空预算称为整个检查点持久化或 shutdown 的截止

#### Scenario: Browser 生产信号关闭失败后重试

- **WHEN** Browser 后端收到关闭信号，原 Manager 的排空或核实收尾明确失败
- **THEN** 记录原资源与完整错误，保留原进程、HTTP 管理入口、原执行及恢复依据，并保持原 Manager 的关闭准入；在途关闭不因重复信号重复执行。核实原操作后，再次关闭信号沿同一 Manager 重试，只有原关闭成功才进入 HTTP 收尾并按该信号退出；不自动重发原业务操作。未捕获致命错误仍沿原退出规则处理；HTTP 阶段遵循下述期限，整个 shutdown 的总期限仍须单独核实

#### Scenario: Browser Manager关闭的检查点或收尾仍在等待

- **WHEN** Manager关闭的创建排空、资源检查点及收尾、共享运行时关闭或最终写盘仍在等待
- **THEN** 每次调用从入口共用一次默认30秒协作式观察预算，阶段不重置；到期明确报告当前阶段及仍在执行的Browser身份，不取消唯一原关闭任务或丢弃原context、检查点和记录。各资源独立推进原检查点/失败收尾链，检查点正文捕获仍沿原串行队列控制内存。重入等待同一任务，整批实际结算并失败后才允许重试；原错误按资源顺序汇总且迟到失败完整记录。成功关闭的共享运行时与最终关闭不重复执行，最后写盘失败只补未完成步骤。普通信号沿原保留进程/再次信号合同处理；观察到期不构成原生调用可强制终止、同步阻塞可抢占或生产进程已退出的证明

#### Scenario: 辅助服务 HTTP 收尾仍有未完成请求正文

- **WHEN** Terminal 或 Browser 已进入 HTTP 收尾，而原连接仍在等待未发送完的请求正文
- **THEN** 两类服务复用同一 HTTP 关闭实现，默认最多等待 5000 毫秒；到期关闭原连接并抛出 `http_server_drain_timeout`，宿主记录 transport 关闭失败后退出 1。正常 SIGTERM 关闭仍退出 143。普通 Manager 关闭未核实则保留原进程和管理重试，不进入此阶段；未捕获致命错误仍沿原退出 1 合同处理。传输关闭不构成外部资源停止证明，也不替代整个 shutdown、同步阻塞或不合作操作的终止核实

#### Scenario: Browser Manager 关闭遇到创建中的资源

- **WHEN** 关闭开始时浏览器仍在配额准入、首次导航或最终状态保存，新创建请求也可能排队
- **THEN** 先关闭创建准入，未接纳请求以绑定原身份与版本的正式未创建回执拒绝；原已接纳创建继续由唯一创建链持有，创建和交互排空共用本批默认五秒单调预算。超时明确失败且保留原资源、Promise与共享运行时；迟到创建完成后不再接纳新交互，同一Manager重试沿原检查点链关闭并可冷恢复，不重放创建或把等待超时当终止证明

#### Scenario: Browser 创建失败的收尾未核实

- **WHEN** 原启动失败，随后资源释放、检查点删除或终态保存再次失败
- **THEN** 启动失败复用原关闭链保留failed/unknown与原句柄、原始异常和完整因果关系，不签发正式失败回执；Manager不能凭创建Promise结束关闭共享池，原管理关闭核实后才可重试整体关闭

#### Scenario: Browser 检查点失败后的收尾再次失败

- **WHEN** Manager 关闭时一个资源的检查点采集失败，随后原 context 释放、检查点删除或状态保存再次失败
- **THEN** 按该资源聚合采集与收尾原错误并继续其它资源；原资源保持原非终态 status 与 unknown、保留尚未释放的句柄，不关闭共享池；同 Manager 重试仍处理原资源，只有原收尾全部完成才落为 lost，unknown 保存也失败时保留两份异常和因果关系，不能伪报检查点已恢复

#### Scenario: Browser 撤销版本时旧操作未能排空

- **WHEN** owner在普通恢复、关联或授权时同步新的传输版本，而原队列已接纳的旧版本操作仍在准备或执行
- **THEN** 先撤销旧连接和授权并持久化新版本，再以同一队列的默认5秒预算等待原集合；超时明确返回排空失败，保留原操作与运行时，不回退版本、不声明旧副作用已终止；迟到结果仍按旧版本拒绝，同版本重试复用原集合且不重放旧动作

#### Scenario: 管理停止的原脚本依赖 context 关闭

- **WHEN** 用户通过原 stop/delete 管理入口停止 Browser，而工具超时后的原脚本仍等待 context 关闭
- **THEN** Python与外部owner显式区分停止准备和普通版本同步：准备先撤销旧连接/授权、关闭新操作准入并持久化新版本，不在释放context前等待原脚本；随后复用原close链关闭context并排空同一原执行集合，只有当前版本的verified终态持久成功后才结清原lease。准备或关闭失败仍传播原异常且不发布停止成功，不遗忘原执行，也不建立第二停止链


#### Scenario: 整组关联释放在全量检查后独立收尾
