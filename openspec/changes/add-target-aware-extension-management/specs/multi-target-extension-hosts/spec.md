## Purpose

定义 Web 与 Electron 共用工作台中以 Gateway 为统一目标的扩展安装、Web 与 Node 入口分派，以及贡献和 API 的精确路由。目标 Gateway 托管常驻 Node 安装管理服务，复用原安装事实；下载、文件 I/O、外部监听与日志收集复用目标 Python 服务。browser 入口在当前浏览器执行，Node 入口在目标 Backend 的独立运行宿主执行。不同页面和客户端共享目标安装，不混用运行实例或资源归属。

## ADDED Requirements

### Requirement: 扩展管理必须在视图标题工具栏选定目标并由目标持有全部用户安装

系统 SHALL 在原 Extensions 视图容器的标题工具栏提供目标切换动作，复用原标题动作贡献及 Quick Input。初次打开 SHALL 默认当前页面入口的原生 Gateway，显示为“本地”；此名称不指浏览器所在电脑，直接访问 B 页面时即指 B。视图 SHALL 持有已选目标，列表、库存、搜索及新打开的详情使用该目标，原安装／更新／卸载按钮直接沿用；MUST NOT 在每个插件点击安装时重新询问目标或增加逐插件目标选择。MCP／设置需要切换目标时 SHALL 复用相同控件与交互规则，各自保留选择，不以一个随活动编辑器或会话变化的全局目标代替。

从既有明确目标的详情发起操作 SHALL 保留其目标；视图切换目标 SHALL 更新后续读取与新操作，取消或忽略旧查询的迟到结果，不重定向已有详情、未提交设置或在途操作，也不改变其它目标运行宿主的绑定。命令面板安装入口 SHALL 使用扩展管理视图当前目标，尚未选择时默认本地；VSIX 来源 URI 仅确定来源，不隐式决定安装目标。Backend 安装域由原 registry／上下文解析，无唯一结果时在视图选择目标阶段补选并沿用；目标级发现／库存 SHALL 不要求先挂接工作区，工作区仅在来源访问或配置启用确实需要时提供；MUST NOT 依赖已经启动的扩展宿主才能选择安装目标。

Web、Node 和纯声明式用户扩展 SHALL 经所选目标 Gateway 交目标原安装／profile／scanner owner 管理，共享该安装域的唯一版本、库存和更新／卸载事实。远端安装在远端执行，Relay 只转送；SSH 只是已有连接方式。浏览器缓存 MAY 保存已发布字节和展示镜像，MUST NOT 保留另一条可独立生效的 Web 安装写入链。内置扩展仍随发行提供，不要求重新安装。目标共享不表示自动跨 Gateway 复制或启用。

#### Scenario: 标题工具栏选一次目标后连续安装
- **WHEN** 用户从 A 页面初次打开扩展视图，在标题工具栏将默认本地 A 切为 B，再搜索并连续点击两个扩展的原安装按钮
- **THEN** 列表、目标能力判断和新详情使用 B，两次安装均直接交 B 的 Gateway 与原安装 owner，不再弹目标选择；只在业务需要时补选来源工作区，普通编辑器焦点变化不改投 A

#### Scenario: 切换管理目标不重定向已有对象或运行实例
- **WHEN** B 的安装已开始、B 的设置或扩展详情仍打开，用户将扩展视图标题工具栏切回 A；B 的旧列表查询随后返回
- **THEN** 扩展视图后续查询与新操作使用 A，不混入 B 的迟到列表；在途安装、既有详情动作、设置草稿及 B 的宿主继续保持 B，MCP／设置视图的当前目标不被联动修改

#### Scenario: 直接访问和中继访问共享 Web 安装
- **WHEN** 用户在 A 页面选择 B 安装一个 browser 扩展，随后直接打开 B 页面或由另一客户端访问 B
- **THEN** 两个入口读取 B 的同一安装版本和库存，并从 B 提供的资源在各自浏览器激活；A 没有建立另一安装记录，刷新或清理派生缓存不会丢失 B 的安装，关闭一个窗口不卸载制品或撤销另一窗口实例

### Requirement: 原生 Gateway 必须通过既有生命周期托管唯一常驻扩展管理服务

现有 Node 扩展管理组件 SHALL 直接提供受原本机认证保护的 loopback HTTP 服务，并由服务自身持有安装域独占锁；每个稳定安装域 SHALL 只有一个实例。目标原生 Gateway SHALL 复用管理 Backend／Browser／Terminal 的既有受管进程与跨代接管机制，启动时先核验已有实例的安装域、进程、运行实例、组件版本及日志归属并接管，确认没有实例才启动。Gateway 连接服务 MUST NOT 抢占安装域锁，不新增代理进程或将组件归属移到 Launcher。未配置组件 SHALL 明确报告能力不可用，已配置组件启动失败或异常退出 SHALL 沿原机制报错，不能假报就绪。普通管理请求 MUST NOT 隐式下载运行时、按请求启动 Node 或增加闲置启停状态机。

库存、VSIX 安装／更新／逻辑卸载及必要的 profile／scanner 语义 SHALL 由同一服务复用原安装 owner 及适用的具名管理通道处理。多个 Backend 和客户端 SHALL 经原受权通信机制共享该实例，安装域身份及 profile 成员沿原 owner 保持，不按 Backend 进程、workspace 或客户端新建一份。下载、配置文件 I/O、包资源字节读取和外部文件监听 SHALL 交目标侧原 Python 服务，不因复用安装器而全部转交 Node。全部消费者迁齐后 SHALL 移除 Backend 按请求启动、初始化、排空并退出管理 child 的链路，不增第二安装账本、broker、目标 registry 或进程管理器。

工作区切换、页面关闭及单个 Backend 停止／重启 SHALL 不关闭共享管理服务。新旧 Gateway 换代 SHALL 复用同一服务，旧版释放管理句柄后服务继续运行；候选 Gateway 启动失败 MUST NOT 关闭旧版仍在使用的实例。只有完整停机 SHALL 停止新准入、结清已接受的串行工作与包资源读取，并经原生命周期机制核实实际进程退出后结清日志归属。单次请求取消 SHALL 不被等同于终止共享服务，写入结果未知时 SHALL 按原记录查询，不因组件恢复重放安装。实际 Node 扩展运行宿主 SHALL 继续归 Backend，Web 入口继续在浏览器执行；MCP 安装、连接及业务配置仍交原 owner，Gateway 请求进程不执行插件或直接读写工作区业务数据。

#### Scenario: Gateway 换代和候选失败不打断共享服务
- **WHEN** 旧 Gateway 正在使用某安装域的管理服务，新候选 Gateway 核验并接管该实例，随后旧版交接退出，或候选初始化失败
- **THEN** 两代使用同一真实管理进程及安装事实，没有锁竞争或重复实例；正常交接只释放旧版句柄，候选失败只释放候选句柄，仍在使用的服务继续受原本机认证保护并提供串行操作

#### Scenario: 管理请求复用服务且 Backend 重启不关闭它
- **WHEN** Gateway 服务组已启动，一个安装域下多个 Backend 与页面连续查询库存并执行安装，随后切换工作区、关闭页面或重启其中一个 Backend
- **THEN** 安装管理请求复用同一个真实 Node 管理进程，没有逐请求启动记录；该服务不随上述操作退出，新 Backend 仍读取同一 profile，管理进程存活不被表述为扩展已激活

#### Scenario: 同安装域多 Backend 并发安装不创建竞争 owner
- **WHEN** 两个真实 Backend 对同一安装域并发提交不同扩展安装，并由另一客户端查询随后发布的库存
- **THEN** 请求进入同一个 Gateway 托管的原管理服务，原发布与变更通知语义保留两个安装成员，不丢 profile 更新，也不通过各自启动管理进程争用生命周期锁

#### Scenario: 远端管理服务由远端 Gateway 托管
- **WHEN** A 的页面经 Relay 管理 B，并与直接打开 B 的页面交替读取或安装
- **THEN** 两条入口均使用 B 的同一管理服务和安装域，A 不为 B 启动本地管理副本，B 的目标身份、授权和原 request_id 保持

#### Scenario: 服务组关闭和管理组件失败如实报告
- **WHEN** 目标 Gateway 服务组关闭，或已配置的管理组件启动失败、在写入回执前异常退出
- **THEN** 关闭由原进程管理机制核实实际子进程退出并保留安装数据；失败暴露具体原因，未确认写入按原结果未知规则查询，不自动重放或让 Backend 启动替代管理进程

### Requirement: 扩展管理 Node 必须限定职责并复用 Python 通用基础设施

Node 管理接口 SHALL 只开放原 VSIX 安装／更新／卸载、库存和必要的精确发布／profile 描述。Python MUST NOT 将其用作通用脚本执行、shell、文件读写、监听、日志或环境服务，也不得以通用 method 透传扩大接口。已准入的目标原生 VSIX 路径 MAY 作为安装参数，不因此成为通用文件访问能力。进程分离和具名受权接口不表示操作系统沙箱，本变更不要求另建沙箱。

VSIX 与安装依赖的下载 SHALL 复用目标 Python 既有 HTTP／下载能力，通过原安装服务的适用传输接口接入，保留上游市场与依赖规划语义，不重复维护另一安装状态机。配置文件和已授权包资源的字节 I/O SHALL 复用目标侧原 Python 文件基础设施；配置模型、scope、语言覆盖和 JSONC 编辑仍由原 Code OSS 服务承担。包版本和 profile 成员 SHALL 以原安装 owner 为准，沿原安装锁／引用保护避免资格核验、字节读取与回收之间的竞态，Python 不扫描或持久化另一份库存。

外部文件变化通知 SHALL 优先复用 `WorkspaceFileWatchService`／`ConfigFileWatcher` 的适用能力，在所属 Python 进程内异步运行；缺少通用能力 SHALL 在原 Python 服务补齐，不改向 Node 或新增监听守护进程。日志由各组件产生并沿原 Python 进程管理／日志体系收集。原安装器自身必需的内部 FileService、配置依赖和 watcher MAY 保留，但 MUST NOT 对外承担 Python 通用能力；不得将这些内部依赖等同于重复对外服务。消费者迁齐后 SHALL 删除 Node 对外配置文件、视图文件创建和包文件 stat／read／write 等旧链路，不保留双轨。

#### Scenario: 远端制品下载使用目标 Python
- **WHEN** 用户从 A 页面为 B 安装目录中的 VSIX，原安装计划还需要下载依赖
- **THEN** VSIX 和依赖传输使用 B 的 Python 下载能力，安装及 profile 更新仍交 B 的唯一原 Node 安装器；A 不代下载或执行，Python 不建立第二份安装清单

#### Scenario: 配置和包文件访问不借用 Node 通用接口
- **WHEN** 用户经实际 Gateway 读取或保存目标设置，或合法 Web 实例读取冻结版本的入口和相对包资源
- **THEN** 文件字节由目标 Python 文件服务处理，Node 只提供安装事实及必要描述，不收到配置／包文件 stat／read／write 命令；原配置语义、现行授权、精确版本和在用引用保护保持

#### Scenario: 文件变化复用 Python 异步监听
- **WHEN** 两个消费者订阅同一目标配置文件并由外部编辑器修改，随后分别释放订阅
- **THEN** 消费现有 Python watcher 的共享及释放语义，合法资源事件使原配置模型更新，不新增 Node 通用监听或独立监听进程；原安装器内部必需的 watcher 不受该禁止范围影响

#### Scenario: 通用 Node 请求不能扩大管理能力
- **WHEN** 内部调用方提交未登记 method、任意脚本、shell 或不属于安装管理的文件／监听操作
- **THEN** 原管理边界明确拒绝且不执行，合法安装参数和已有安装管理操作仍可用，不增加第二个命令执行通道

### Requirement: 扩展安装必须使用原版入口及明确兼容能力

系统 SHALL 复用原扩展视图、详情、搜索与 VSIX 安装交互，支持经验证的可配置目录和明确本地 VSIX 来源。安装前 SHALL 按 manifest 的 extensionKind、browser／main、engines、信任条件、版本、目标平台、依赖及实际宿主能力判断可用性；目录未配置／失败及能力不支持须可辨认，MUST NOT 承诺任意市场或扩展均兼容。安装、激活和实际功能可用 SHALL 分别报告；要求本机 UI Node 语义但当前运行面不具备时，不得冒充 workspace 扩展放到任意远端。

#### Scenario: 扩展需要目标不具备的 Node 或原生能力
- **WHEN** 用户在纯 Web 宿主选择仅有 Node 入口的 VSIX，且没有可用目标宿主
- **THEN** 明确说明所需能力和可选择的合法目标，不安装后伪报已可运行，也不在 Electron main 自动执行

#### Scenario: 目标侧 VSIX 安装与并发回执
- **WHEN** 用户通过已认证管理入口，以稳定目标及其挂接工作区的文件 URI 安装 VSIX，且另一安装先于本次 HTTP 回执完成
- **THEN** 原生目标按独立安装权限解析来源并交原安装器处理，本次回执中的安装版本与完整库存来自同一串行发布操作；其它目标不变，已有版本目录保留，安装不被表述为运行版本切换，断流不重放安装

#### Scenario: 无效 manifest 在原安装任务创建前拒绝
- **WHEN** 用户首次安装或升级目标侧 VSIX，其 manifest 产生官方校验器的 Error 诊断
- **THEN** 原安装服务在创建任务及发布候选前返回具体原因，保留原 profile 的存在状态、字节和已有制品，库存仍可读取且其它目标不变；仅有 Warning 的合法候选仍可安装，原 engines 前置拒绝及其诊断保持，不将安装成功解释为运行激活成功

#### Scenario: 目标 VSIX 复用同版本已有制品
- **WHEN** 目标安装服务收到相同官方 ExtensionKey 的 VSIX，已发布目录仍可由原扫描器验证，包括从新版切回保留的旧版
- **THEN** 沿原 `keepExisting` 复用已有目录，回执以 `reused` 明确说明本次正文未覆盖，工作台保留实际版本与重新加载提示；同版本另一份 VSIX 不隐式替换代码，也不新增包体 hash 比较。已有目录无法验证时明确拒绝并保留原件，不因扫描失败自动删除重建；未提供 `keepExisting` 的官方替换行为保持。此安装语义不代替活宿主引用保护或物理卸载验收

#### Scenario: 原 VSIX 入口冻结目标并如实报告批次结果
- **WHEN** 用户已在扩展视图标题工具栏选定 B，从原安装命令选择已挂接工作区的 VSIX，或经原资源命令提交一个或多个明确文件 URI，并在选择或安装期间切换标签或视图目标
- **THEN** 命令直接沿用已选 B，不再弹安装目标选择；原文件选择器只选择来源，安装进度使用发起时明确的 Backend 默认 profile 和有序工作区集合，不随焦点改投。来源和冻结目标在首个安装前完整核验，取消或非法后项不能触发前项安装。已核实安装回执合并显示真实版本并提供原重新加载入口；后项失败保留此前成功事实，不伪报回滚，不因 HTTP 错误断言没有发生安装，也不自动重放。用户身份失效不向后来身份发布原操作通知；浏览器或中继本机路径不能冒充目标来源，不支持的来源明确说明如何从目标工作区选择文件。

#### Scenario: VSIX 来源不隐式切换安装目标
- **WHEN** 扩展视图已选 B，资源菜单或拖放传入 A 的 VSIX URI，当前安装链尚未支持该跨目标来源
- **THEN** 命令明确拒绝该来源且零安装，不将目标改为 A，也不将 A 的路径在 B 解释；扩展视图仍选 B，用户可改选合法来源或主动切换目标

#### Scenario: 原文件选择器区分空目录和工作区读取失败
- **WHEN** 选择 VSIX 时初始目录或后续导航发生权限不足、目录读取 404、分页失败或目标离线
- **THEN** 原文件操作链将失败交原命令呈现，保留具体原因和请求归属，释放该次选择状态且零安装请求；成功的空目录与用户取消保持正常结果，原 stat 缺失的文件名候选与保存新文件语义不变。用户可以明确重开命令重试；取消的旧更新或关闭后的迟到结果不能覆盖新更新、结束新操作或改投其它目标

### Requirement: Web 与 Node 入口必须共享目标安装并按能力分派执行

browser 扩展 SHALL 从所选目标的安装记录在当前 Workbench 原 Web 宿主执行，需要 Node 的扩展 SHALL 在同一明确目标的后端宿主执行；browser／main SHALL 仅参与原 manifest 与能力的入口选择，MUST NOT 要求用户分别安装前端版和后端版。同一包有两类入口不代表两个入口必须同时执行。Node 宿主不得由 Gateway 请求进程、Python Agent 或 Electron main 执行。Web 与 Electron SHALL 共用 renderer 贡献及目标协议；桌面仅承担已约定的窗口、生命周期及 profile。

Web 的入口、静态贡献与相对资源 SHALL 从同一目标／已发布版本经原授权资源链加载，复用原扩展资源机制、Worker 和 CSP；Relay 不建立第二份安装事实，也不将目标原生 file 路径当作当前浏览器文件。运行注册和业务访问 SHALL 保留安装目标来源；同 ID 跨目标实例不能互相覆盖，纯窗口 UI 贡献仍遵守原窗口级冲突规则。共享制品不共享秘密，目标安装的 Web 入口同样遵守现有凭据归属和保护合同，不能借用另一目标的同名扩展凭据。

目标 Web／Node 扩展运行 SHALL 统一核原生 Gateway 的 `extension_host_manage`，覆盖运行准入、激活、状态、停止及各自适用的宿主生命周期／通道管理；`extension_installation_manage` 不代授运行。只读安装描述与包资源 SHALL 允许上述任一权限，供管理或运行读取，不能据此创建未获准的运行实例。资源访问还须满足明确目标及当前安装版本或合法实例冻结版本的资格，原生入口和 Relay 使用相同边界，不增加另一 Web 权限或资源账本。

#### Scenario: 仅 browser 的扩展安装在无 Node 宿主的目标
- **WHEN** B 的管理与 Web 资源能力可用，Node Extension Host 不可用，用户安装一个 manifest 合法且满足 Web 能力的扩展
- **THEN** 沿 B 的同一安装链发布并在当前浏览器运行，不为 Web 激活启动 Node 宿主，不要求另选 Web 安装域；Node-only 扩展仍按实际能力明确拒绝

#### Scenario: 零工作区根窗口运行入口目标的 Web 扩展
- **WHEN** 窗口尚未挂接工作区文件根，页面入口 Gateway 已发布合法 browser 用户扩展
- **THEN** 从入口 Gateway 的唯一实时安装域读取库存，以空工作区集合取得原 Web 运行资格并执行；不请求 Node 宿主，不借用当前活动工作区，管理视图改选其它 Gateway 不重绑运行目标；无合法入口的 Node 扩展明确诊断为不可运行

#### Scenario: 页面入口未配置可选管理组件
- **WHEN** 已授权主体查询入口 Gateway 的安装域，而原生 Gateway 明确未配置扩展管理组件
- **THEN** 实时目录返回空安装域，零根窗口明确诊断目标用户扩展不可用并继续加载原内置扩展；安装管理操作仍明确不可用，不吞没已配置组件故障、离线、权限拒绝或协议错误

#### Scenario: 同一 VSIX 包含 browser 与 main
- **WHEN** 一个已安装于 B 的 VSIX 同时提供 browser 和 main，多个客户端访问 B
- **THEN** 共享同一目标制品与版本，分别按 manifest 和实际宿主能力选择入口；不重复安装包，不把客户端实例、MCP 连接或凭据合并，目标资源和配置仍归 B

#### Scenario: 浏览器与 Electron 连接同一远端目标
- **WHEN** 两种客户端分别激活 B 上的 Node 扩展
- **THEN** 代码在 B 的目标侧执行，两者各有自己的客户端运行视图；客户端机器、Gateway 请求进程及 Electron main 没有另起该扩展的本地副本

### Requirement: 多目标宿主必须保持明确工作区视图和代际

一个 Node 宿主 SHALL 绑定一个客户端会话、一个稳定原生目标及明确挂接的同目标工作区集合，集合可使用原 multi-root 语义。其它目标的 workspace MUST NOT 隐式进入该宿主视图。全局活动工作区或单一 remoteAuthority 的切换不能替代多目标身份。工作区集合变化及宿主重启 SHALL 通过明确生命周期和 generation 更新，旧 generation 不得接受新调用或发布迟到结果。

认证握手 SHALL 返回目标平台、原 mount 中的有序根映射及目标原生 profile／日志初始化位置；根映射保留资源 URI 与目标 file URI 的不同职责，不成为第二份权威登记。原生位置只在目标机器解释。workspaceState 的稳定视图身份 SHALL 包含原生目标、明确 view 和有序工作区集合，不依赖客户端会话、generation 或临时路由。

#### Scenario: 同屏 A 与 B 的同名工作区
- **WHEN** 一个窗口同时打开 A1、A2、B1，而 A 宿主只挂接 A1/A2
- **THEN** A 扩展看到的 workspace view 只有 A1/A2，B 扩展仅见其挂接集合，切换编辑器焦点不会修改任一宿主身份或泄露另一目标文件

#### Scenario: 重连消费目标生成的初始化位置
- **WHEN** 客户端为同一明确目标和工作区视图重新建立认证通道
- **THEN** 新 generation 沿原协议使用目标生成的根与 profile 位置，同一视图的持久状态身份保持；根集合不同的视图不得借用该身份，Relay 和客户端不把目标 file URI 解释为自己的文件

### Requirement: 内部扩展身份必须支持同一公开 ID 的多目标实例

系统 SHALL 在原扩展服务内以公开 extension ID 与稳定安装目标区别内部实例，运行身份进一步带 view／generation，并迁齐 description registry、enablement、activation、running location、依赖和卸载消费者。公开 manifest／API ID MUST 保持不变；仅增加 Remote kind 字段、忽略重复 ID 或借另一目标同名依赖均不满足此要求。不同目标的版本可分别运行；窗口级声明冲突 SHALL 在启用前按原贡献语义诊断并要求选择可共存版本或不同窗口，不能静默覆盖。

extensions.all／getExtension／exports SHALL 解析该 host 的合法实例集，不能按公开 ID 返回其它目标运行对象。

#### Scenario: 同扩展不同版本跨目标独立激活
- **WHEN** A/B 的同 ID 扩展使用不同版本但具有可共存声明，各自依赖同目标组件，随后 A 更新或停用
- **THEN** 两实例曾真实独立激活，A 操作只撤销 A 的实例与依赖引用，B 的版本、贡献和运行保持不变

### Requirement: Node 宿主文档与编辑器同步必须按视图投影

初始模型、dirty buffer、textDocuments、visibleTextEditors、activeTextEditor、文档／编辑器／诊断／watcher 事件 SHALL 按 Node host 明确 workspace view 及资源归属发送，不能广播全窗口模型。焦点在其它 view 时该 host 的 active editor SHALL 为 undefined；版本、取消及 generation 须贯穿请求和结果。跨资源 WorkspaceEdit SHALL 在副作用前核验全部资源归属、映射与版本，拒绝错误目标，不声称新跨目标原子事务。此 API 视图约束不等于 Node 进程的文件系统沙箱。

直接 `workspace.applyEdit` SHALL 在恢复 DTO 与进入原 BulkEditService 前核验整批 `resource`、`oldResource` 和 `newResource`，合法首项不能先于非法后项生效。该入口错误 SHALL 保留原日志与 `false` 返回合同。宿主代际关闭 SHALL 取消原编辑 token；取消后尚未完成任何资源时返回未应用，已经完成的资源 SHALL 保留原结果，不能用外层关闭标志伪装撤销已发生的副作用。文件操作能力缺失时 SHALL 明确拒绝，不以目标 Node 原生文件访问旁路工作区文件 owner。

TabGroups SHALL 复用原编辑器组布局，仅投影属于当前宿主的完整 EditorInput；组内增量索引基于投影后的标签顺序，保留原 Tab／TabGroup 的运行态对象身份。其它目标的活动标签 SHALL 表现为该组无 activeTab，实际 activeTabGroup 与 viewColumn 仍由窗口布局决定。混合资源 Diff／Merge／MultiDiff 的所有实际文件端点均属该视图时才可见，不能只展示部分文件却允许操作完整输入。尚无目标归属的无文件标签不进入 Node 视图，Web 原窗口语义保持。关闭组 SHALL 仅关闭该宿主的标签，组中仍有其它目标文件时不得移除真实组；关闭、移动及迟到事件不得越过所属代际或改投其它资源。

文档语言 Provider SHALL 在原注册表的候选评分与独占排序前核对宿主视图；目标 Provider 的 scheme、绝对 glob 和 RelativePattern 按目标原生文件位置匹配，继续复用原 selector／glob 合同，不能仅在错发 RPC 后拒绝 URI。多文档操作的次要文档 SHALL 使用同一注册项的归属及评分，不另存 selector 绕过目标限制。Web 原窗口评分、Provider 对象及取消协议保持。

Code action Provider SHALL 在发布返回列表前核验其中全部 WorkspaceEdit 的端点归属；resolve SHALL 在修改原 action 的 edit／command 前完成同一检查。调用取消、注册撤销或宿主关闭后 SHALL 取消原在途请求，不发布迟到列表或修改旧 action。未发布或拒绝的列表 SHALL 释放其准确缓存；已发布列表继续沿原 dispose 释放，不重复结算，也不因另一代际同号缓存而混用。普通 command 正文与无 binding 的 Web 资源范围保持原合同。

Code action 的文本编辑 SHALL 沿原 WorkspaceEdit 转换及版本字段传递调用所基于的已同步文档版本。provide 与实际进入的 resolve 各自在调用扩展回调前冻结本宿主文档的数值版本，异步返回及后续应用不得把旧编辑改标为最新版本；已有初始 edit 的动作继续沿原流程直接应用，不为刷新版本另行 resolve。未知版本的资源及同批新建目标保持原转换语义，不合成版本或读取正文推断。此合同可能拒绝回调等待期间按新正文重新计算的编辑，用户可重新请求动作；它不承诺无版本资源的并发保护或已发生副作用回滚。

Rename 的 provide SHALL 复用同一原文档版本快照与 WorkspaceEdit 转换，在扩展回调前冻结本宿主已同步文本版本；MainThread SHALL 在结果发布前核验全部编辑端点，再沿原 DTO 恢复。provide 与 prepare 的在途请求 SHALL 同时响应调用取消、注册撤销及宿主关闭，拒绝迟到结果，不影响新注册或另一宿主。原 prepare 的 Range／placeholder、缺省位置、空结果及 rejectReason 语义保持；返回的窗口内结果 SHALL 保留其注册生命周期，原 BulkEditService 将其与调用方 token 合并并贯穿预览及实际应用；内部字段不得随公开命令结果进入 RPC。原 RenameController 与 inline rename 命令 SHALL 等待应用结算，前者使用该次操作的父 token，不能被自身文本变化取消后续编辑；退役的 inline 缓存结果不继续计数或应用。预览 SHALL 在打开原视图前满足其显示条件，取消后沿原 owner 释放输入与会话，停止迟到的预览模型创建及自引用申请，准确释放尚无引用的新模型和迟到引用；异步准备完成的旧点击不得打开已退役的预览，活跃预览的解析错误仍明确上报，未应用时不播报成功；已完成资源保留真实结果，不承诺回滚。本片不覆盖原 Chat response stream 分项移交后的应用生命周期，也不把内部字段扩展为跨 RPC 的持久引用。

#### Scenario: A 与 B 的未保存文档同时打开
- **WHEN** A/B 文件均有不同 dirty 内容，两个扩展枚举文档／可见编辑器并监听变化，用户在二者间切焦点
- **THEN** 每 host 只得到自己 view 的模型、内容和事件，非所属 view 焦点表现为无 active editor；错误目标编辑在产生副作用前被拒绝，迟到旧代际结果不发布

#### Scenario: 混合编辑器组的标签事件与关闭
- **WHEN** 同一真实编辑器组交错打开 A/B 文件，随后移动、切焦点或由 A 扩展关闭自己的 TabGroup
- **THEN** A/B 分别收到自己标签的连续索引和增量，未关闭标签的 API 对象身份保持；A 只能关闭自己的完整输入，B 文件及仍非空的真实编辑器组保留，宿主关闭后不再发送标签模型或继续处理后继关闭

#### Scenario: 直接编辑的整批准入与代际关闭
- **WHEN** A 的直接编辑先包含合法文本／文件项，后包含非所属资源；或编辑在预览等待及真实写入完成后的回执等待中遇到宿主关闭
- **THEN** 非所属批次在任何首项写入前拒绝；预览中关闭产生零写入并返回未应用，已经完成写入的回执保持真实结果，后续新编辑拒绝；原空批次、预览过滤与 Web 编辑范围保持

#### Scenario: 同语言 Provider 按目标原生位置匹配
- **WHEN** A/B 同时打开同语言文件，各自 Provider 使用语言、file scheme、绝对 glob 或 RelativePattern 注册，并交替请求结果或执行多文档高亮
- **THEN** 仅所属目标的 Provider 参与候选，模式匹配目标真实位置；外部目标的 exclusive Provider 不压制自身候选，多文档操作不向该 Provider 发送其它目标文档，切焦点不改变已发起目标

#### Scenario: Code action 列表、resolve 与缓存生命周期
- **WHEN** A 返回多个 action 且后项 edit 越出所属视图，或 resolve 返回非法编辑；在途 provide／resolve 遇到取消、注销或宿主关闭后仍返回结果
- **THEN** 列表整批拒绝并释放准确的新缓存；resolve 保持原 action 的 edit／command，迟到结果不发布或修改旧对象；已发布 list 的原缓存仍由该 list 收尾，新代际与 B 的同号缓存不受影响

#### Scenario: Code action 的异步返回和旧菜单保持原版本
- **WHEN** provide 或 resolve 等待期间待编辑文档变版，或动作发布后用户修改其中一个目标再点击旧菜单
- **THEN** 编辑仍携带相应回调调用前的文档版本，原整批版本校验在首个副作用前拒绝冲突，后继 command 不执行；原 UI 应用入口显示具体错误并结清进度，不触发全窗口启动失败，重新请求且版本匹配的动作可以正常应用，另一宿主不受影响

#### Scenario: Rename 的整批结果、版本与迟到请求
- **WHEN** A 的 Rename 返回双根编辑且后项越出所属视图，或 provide 等待期间另一待编辑文档变版；prepare／provide 在取消、注销或宿主关闭后仍返回
- **THEN** 非所属结果整批拒绝；已同步文本保留回调前版本，原编辑链在首个副作用前拒绝冲突；迟到位置或编辑不发布，原拒绝原因保持，新请求及 B 的状态不受影响

#### Scenario: 已返回的 Rename 在预览及 inline 应用前退役
- **WHEN** Rename 已返回编辑后注册撤销，或预览在打开、确认、输入创建及用户选择期间遇到注册／调用取消；用户随后重新注册并请求重命名
- **THEN** 已取消结果不开始新的文件或文本副作用，原预览输入和会话释放，未完成的预览准备不在退役后重新创建模型或打开旧视图，晚到引用释放且正常状态的解析错误不被吞掉；已有资源完成时保留真实结果并停止后继，原命令等待结算且零应用不播报成功，新注册和另一宿主仍可正常应用；窗口内部生命周期不出现在公开命令 RPC 回包中

#### Scenario: 工作区符号查询限定完整宿主视图
- **WHEN** A 的符号 Provider 绑定 A1/A2，B 绑定 B1，用户明确选择工作区范围或 A 扩展在 B 获得焦点时发起公开符号查询
- **THEN** 完整选择 A1/A2 才调用 A，单选 A1 时在调用前说明缺少完整视图，不查询 A2 后再过滤；A 扩展的查询只进入原 A 宿主，结果与解析保留同一 Provider、缓存身份和 typed URI，取消或注销不发布迟到结果；原无 scope 的窗口查询及 Web 窗口级能力保持

### Requirement: 扩展启用范围与版本激活必须区别于安装位置

VSIX 安装位置 SHALL 与原 profile／workspace view 的启用状态分别表达；同一 multi-root view 不得伪报每文件夹独立运行隔离，需要不同启用集的业务工作区须使用不同明确宿主视图。版本更新、停用与卸载 SHALL 沿原宿主 reload／重启及引用规则，保留未结算旧进程／操作所需制品；安装新版本不得伪报运行实例已切换，操作失败不得改变其它目标的配置或版本。

Web 实例 SHALL 在原运行 owner 准入时冻结安装目标、扩展及确切版本，其入口、动态 import、静态贡献和相对包资源均使用同一绑定。更新或逻辑卸载后，已运行实例 SHALL 继续读取该旧版本，直到实例关闭或运行授权撤销；不得混用当前新版。新实例 SHALL 仅取准入时当前安装版本，逻辑卸载后拒绝新建，不使用缓存或残留包恢复旧版。资源 owner SHALL 验证原实例绑定及当前运行授权，不能仅凭扩展 ID、版本 URL 或安装权限建立旧版本资格。

实例关闭或运行撤权后 SHALL 停止其后续资源准入及披露，并沿原生命周期撤销实例贡献、结清引用；其它合法实例保持。物理回收 SHALL 等实际运行及其它合法引用全部结清，不因移除安装记录提前删除旧包；复用原安装／运行引用 owner 与既有客户端租约，不另建资源租约或安装账本。已下载字节不得成为后续激活或资源访问的授权凭据。

#### Scenario: 共享安装但使用不同扩展启用集
- **WHEN** A1/A2 共享已安装版本但要求不同启用状态，且 A1 的旧宿主仍运行时安装新版
- **THEN** 用独立明确视图表达不同启用集，显示新版安装与 A1 待 reload 的区别，A2/B 的状态不被隐式修改；有引用旧制品不被删除

#### Scenario: Web 旧实例在更新及逻辑卸载后读取冻结版本
- **WHEN** B 的 Web v1 已运行，安装更新为 v2 后创建第二个实例，再逻辑卸载该扩展；两实例随后读取各自延迟加载模块和相对资源
- **THEN** 第一实例始终读取 v1，第二实例始终读取 v2，均保持合法运行授权且不混版；卸载后创建第三个实例被拒绝，原包仍受各自引用保护，另一目标的安装和实例不变

#### Scenario: 关闭一个实例不提前回收另一实例所需包
- **WHEN** 两个合法 Web 实例仍引用已被更新或逻辑卸载的同一版本，其中一个关闭并尝试继续使用旧资源地址，随后另一个也关闭
- **THEN** 关闭者的原实例绑定不再获准访问，另一实例仍可读取冻结版本；最后实际运行和其它合法引用结清后才可沿原 owner 物理回收，缓存或旧 URL 不允许创建新的旧版实例

### Requirement: 同一扩展贡献必须按发起目标分派

扩展 SHALL 继续使用原 manifest、命令 ID、菜单／快捷键及 activation 合同，内部注册须保留真实宿主及目标来源。同一扩展在多个目标注册同一命令时 SHALL 根据发起编辑器目标分派；全局入口存在多个合法目标时明确选择并冻结。资源 Provider SHALL 按资源稳定归属路由，不按最后注册覆盖或显示名匹配。

每个 UI command ID SHALL 由单个窗口分派入口持有按来源登记的合法实例；扩展内调用优先继承原 host／view，activation 不向所有目标广播同名事件。TreeView／WebviewView resolver、setContext 与菜单状态 SHALL 保留 host／view 归属及明确展示绑定；dispose 按来源和 generation 撤销，只有最后来源消失才移除共享入口。静态贡献只登记一次，不重复注册互相覆盖。

#### Scenario: 同一命令 ID 在 A 与 B 同时注册
- **WHEN** A/B 安装相同扩展，用户从 B1 编辑器执行命令后立即切到 A1
- **THEN** 只调用 B 宿主并读取 B1 资源，不因切焦点、注册顺序或同名文件改投 A；无发起目标的同一命令先选择目标

#### Scenario: 扩展内调用与其它目标撤销贡献
- **WHEN** 窗口焦点在 A，B 扩展调用同 ID 命令并提供同 ID TreeView／WebviewView，随后 A reload 并撤销其贡献
- **THEN** 命令只进入 B，视图与上下文按明确目标绑定；撤销 A 不删除 B handler、resolver 或状态，B 的菜单不被 A 的 setContext 覆盖

### Requirement: 扩展 API 必须使用实际目标服务并公布能力边界

系统 SHALL 为文档／语言、文件与 watcher、工作区与配置、终端／任务／调试、Webview／端口、依赖及存储公布实际支持能力。支持的 API SHALL 保留原扩展 API 语义并访问真实目标；缺少能力须明确拒绝，MUST NOT 使用空成功、本地 IndexedDB 同名文件、浏览器 localhost 或其它宿主替代。权限与能力读取不得触发 Agent 或隐式连接其它目标。

目标 Node 扩展取得的文件 URI／fsPath SHALL 可供该目标原生文件访问，跨宿主传递须沿唯一映射恢复原工作台稳定资源身份；不得向 Node 暴露只在浏览器 VFS 有意义的假路径或全局替换任意字符串。

嵌套根 SHALL 沿原 folder 最长匹配规则；同一本机路径对应多个业务身份时须由已有请求／文档上下文消歧，无唯一结果则明确拒绝，不能任选根或另建路径注册表。

#### Scenario: 远端扩展打开终端并读取配置
- **WHEN** B 扩展通过受支持 API 打开终端、读取 B1 配置及文件，随后请求一个未支持的调试能力
- **THEN** 前三者由 B 的真实服务处理，未支持能力明确失败；没有在 A、浏览器或 Electron main 创建替代终端或读取同名资源

#### Scenario: Node 扩展原生路径与编辑器资源往返
- **WHEN** B 的真实扩展分别使用 Node 文件 API 与扩展文件 API 读取 workspace 文件，再返回该文档位置
- **THEN** 两次均读取 B 的真实内容，位置映射回 B 的同一编辑器身份；A 同名路径及浏览器内部虚拟根不被读取

### Requirement: 宿主恢复与持久存储必须保持目标隔离

宿主 SHALL 惰性创建并按有界客户端租约回收；断开、崩溃、后端重启及权限失效须停止新准入、撤销旧代际贡献并报告实际原因，不自动重放未知副作用。安装记录及持久状态不随宿主关闭删除。扩展全局状态 SHALL 按 profile／原生目标／扩展隔离，工作区状态进一步按稳定工作区视图区分，不以临时客户端 ID／endpoint 作为持久身份；凭据留实际消费侧。

MainThreadStorage／ExtensionStorageService 等原存储 owner SHALL 迁齐上述身份、持久写入及变更通知，不能只改调用方 key。Node 的 globalStorageUri／storageUri／logUri／extensionUri SHALL 对应目标本机有效资源，包目录与可写状态分开；同身份客户端并发沿原存储写入／通知语义，不伪报逐字段事务合并或共享瞬时回调。

#### Scenario: 两个客户端使用同一安装后分别关闭
- **WHEN** 两个客户端在 B 激活同一版本扩展，关闭其中一个并重启另一个
- **THEN** 关闭者的回调／工作区视图按租约回收，不撤销另一客户端贡献；稳定持久状态可恢复，A 的状态和秘密不被读取

目标 Node 的跨设备 `setKeysForSync` 尚未支持时 SHALL 在原公开 API 明确拒绝；同 profile 客户端的存储变更通知及重启恢复不等同跨设备同步。Web 原同步能力保持，后续接入须迁齐原同步读写消费者，不得仅保存声明后报告成功。

目标侧秘密 owner 尚未接通时，Node 的 SecretStorage 四类操作 SHALL 在秘密进入浏览器 RPC 前明确拒绝；主线程也不得读取、修改或向该宿主广播 Web profile 的秘密。此限制不表示目标秘密支持已完成，后续实现必须在实际消费侧保存秘密，Web 原有 API 保持。

宿主初始化中的文件根 SHALL 复用原文件 owner 的规范 display 根，与 Workbench 文件模型使用同一身份；Gateway 归属由认证 binding 与 FileService URI 的 authority 承载，不得因重复编码 Gateway 而形成无法匹配的第二种根。

#### Scenario: 存储路径与同身份客户端同步
- **WHEN** 同 profile 的 A/B 扩展写各自 globalState 和真实 storageUri，B 的另一客户端读取并重启
- **THEN** 目标文件真实可写，A/B 不串值；B 的已确认持久结果按原通知和恢复语义可见，临时 host ID 变化不丢失状态

### Requirement: 扩展管理必须通过原生目标管理权限

远端安装、更新、卸载与 Web／Node 运行管理 SHALL 由原生目标校验相应能力，使用稳定登记和真实路由。失效目标、route 被其它目标复用、权限撤销与 API 版本不兼容须明确拒绝，不落到当前活动目标。实际安装／版本及引用 SHALL 由目标 Gateway 托管服务中的原安装 owner 持有，运行事实仍由相应运行 owner 提供，Relay 与前端不得形成第二事实源。

#### Scenario: 宿主地址被复用
- **WHEN** 已安装目标 B 的旧连接地址被另一个目标接管，用户从历史入口激活 B 扩展
- **THEN** 按稳定身份重新核验并拒绝不匹配连接，不向新目标发送扩展代码、凭据或命令

#### Scenario: 实时宿主发现不触发启动
- **WHEN** 客户端对明确目标及workspace集合读取宿主状态，目标缺少专用runtime、平台未支持或正在排空
- **THEN** 由原生Gateway按宿主管理权限读取Backend唯一owner，返回实际稳定身份与具名通道不可用原因，不启动Backend或宿主；离线和路由失效明确失败，不以登记镜像冒充实时状态，通道可用也不代表完整扩展API已可用

### Requirement: 发行产物必须独立提供工作台资源与可验证宿主链

Web 与 Electron 发行产物 SHALL 包含其所需静态资源与扩展资源定位，不依赖开发服务器或源码目录。目标侧 Node 宿主 SHALL 使用与固定上游及平台匹配的实际 runtime／组件，不借 Electron 内置 Node 假充远端能力。真实扩展激活及文件／命令操作、重启状态恢复必须分别通过产品入口验证，进程启动不能作为功能完成证明。

#### Scenario: 打包 Electron 在源码目录外启动
- **WHEN** 关闭开发服务器，将桌面产物移到独立目录后连接 B 并激活测试扩展
- **THEN** 原界面资源、Web 扩展及目标 Node 操作均按真实支持能力工作；重启恢复稳定配置及状态，没有读取源码路径或启用额外原生 IPC
