## Context

独立客户端已有原生 Thread 编辑器，但手写 DOM 的聊天和资源界面重复实现了既有 React 产品。独立边界应限定为工作台入口与外层布局：原版 Code OSS 管理导航、编辑器标签、预览/固定、拖拽、Grid、命令和设置；EditorPane 内直接复用既有 React 会话组件及业务链路。原工作台依旧固定官方上游，不修改子模块。

## Goals / Non-Goals

Goals：完成既有业务操作，维持精确工作区/会话/Thread 归属和原生工作台体验。
Non-Goals：重写后端调度、改变 Goal 续跑条件、接入微软发行版服务、在功能验收前切换旧生产入口。

## Decisions

- 自定义 EditorPane 挂载 React root，组合既有 ChatPanel、Composer、工具与附件展示、文件、更改和任务组件，不挂载旧 App 或旧工作台外壳。主题和业务样式仅在会话宿主内生效，不污染原版工作台。
- 每个标签显式传入 Gateway route、工作区业务 ID、Session ID 和 Thread ID。控制器、历史、SSE、排队/停止、草稿与资源操作均冻结这一归属，不读取其他标签的全局“当前会话”。同一 Thread 的后端事实仍只有一份；前端展示镜像不得成为第二个 writer。
- 将已有 React 组件需要的上下文改为会话实例作用域，保留原业务 hook 与状态归并实现。不能通过复制 Composer、消息协议或重连状态机来绕开全局依赖。
- 切换、隐藏、关闭和恢复标签由 EditorPane 驱动挂载及释放；取消请求不得写回其他 owner，关闭标签不得删除后端会话。草稿按用户、工作区、Session 和 Thread 隔离。
- 迁通后物理删除 workbench 下手写 DOM 的聊天、Goal、任务和资源管理实现及失去调用方的 API；全仓检查其直接/间接消费者和测试，复用既有 React 实现，不长期保留双轨。
- Goal 属于 Session main Thread。子 Thread 的资源内明确显示这一归属，不把它伪装成子 Thread 独立 Goal。暂停不打断当前 Agent 轮次；新建、重新开始和删除沿用原契约。
- 业务变更成功用完整响应替换镜像，失败重新读取并保留输入及错误。并发任务操作携带 expected_revision，工作区文件保存携带 expected_revision。
- 文件通过原版文件/文本服务接入后端资源 URI，原版负责文本模型、脏状态、撤销、保存与分组，避免另写文本编辑器和保存事实源。
- 会话资源保留在 Thread 内；工作区终端、输出、端口、自动化、MCP 使用原生底部面板贡献；Gateway 连接与工作区注册归控制面。
- 每个纵向批次做类型检查、相关构建和真实 Gateway 浏览器验收。已有真实回放隔离栈优先复用，不能靠假 UI 状态完成验收。
- 正式页面测试必须构建并加载 Workbench 静态产物，按编辑器组及 workspace/session/thread 定位开放 ShadowRoot 中的产品控件；不能将全局查询得到空集合当作业务通过。组件 harness 及 API、缓存、历史归并单测继续复用，业务断言不因界面迁移放宽。
- 先迁聊天及双 Thread 隔离，再迁文件、任务和工作区场景；通过后统一开发和发布入口。最后全仓检索并移除旧 App 外壳及其专属测试，保留新宿主仍依赖的 React 产品组件。

## Risks / Trade-offs

- 多组同时管理同一 Session → 操作后同步权威状态，避免过期 revision 静默覆盖。
- 后端脚本和 Goal 激活可能执行任务 → 浏览器验收使用隔离工作区及精确模型回放，Goal 控制测试先保持 main Thread 无运行任务。
- 原生 Web 缺少桌面进程宿主 → 连接现有工作区 Terminal/Browser 服务，不能用本地假实现替代。
- 全量迁移跨度大 → 分链路记录未完成验收；所有核心入口完成前不得宣称完整迁移或移除旧客户端。
