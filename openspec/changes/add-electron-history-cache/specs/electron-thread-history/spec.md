## Purpose

为完整桌面工作台提供真实 Electron 运行入口，复用现有会话历史镜像，在应用正常关闭、重启以及后端尚未完成同步时保留可识别、只读的历史预览，确保缓存与业务权威分离。

## ADDED Requirements

### Requirement: 统一桌面工作台

Electron SHALL 使用与 Web 相同的完整工作台和会话组件，通过 Gateway 访问业务；renderer MUST 隔离 Node 权限，不提供任意本地文件或 IPC 能力。

#### Scenario: 原生应用打开会话
- **WHEN** 用户启动 Electron 并打开会话
- **THEN** 原版工作台加载共享聊天和会话资源，页面无法访问 Node 或 Electron 全量 API

### Requirement: 重启恢复前端镜像

应用 SHALL 保持稳定的用户数据目录、持久化存储和页面来源，并在正常关闭前等待待提交历史镜像完成。缓存 SHALL 按 Gateway、工作区、Session、Thread 隔离；后端同步完成前 SHALL 只读展示并标记缓存状态。

#### Scenario: 重启后后端延迟
- **WHEN** 用户正常关闭已有历史的应用，再次打开且后端响应延迟
- **THEN** 页面先显示上次历史及同步提示，后端返回后替换镜像并恢复操作

#### Scenario: 独立用户目录
- **WHEN** 使用不同用户数据根目录启动应用
- **THEN** 不会读取另一用户目录的历史镜像

#### Scenario: 固定来源不可用
- **WHEN** 已保存的本地页面端口被占用或宿主运行态损坏
- **THEN** 应用明确报告启动失败，不自动换来源导致缓存看似丢失

### Requirement: 自包含桌面产物

系统 SHALL 从与 Web 相同的前端源码构建 Electron 客户端，桌面产物 MUST 包含 Electron 宿主、运行时和全部前端静态资源，移出源码目录后能连接显式指定的已有 Gateway。全部状态、网络和后端 URI／VS Code 虚拟文件系统 SHALL 复用 Web 链路；宿主 SHALL 只负责窗口、生命周期、固定存储与共享静态服务，不新增原生文件系统 IPC、原生扩展或其他系统能力。

#### Scenario: 迁移后启动便携产物
- **WHEN** 将便携包解压到独立目录，在无源码与开发服务器依赖的条件下启动并指定 Gateway
- **THEN** 完整工作台初始化，用户可以打开和操作会话、预览文件，并通过同一后端 URI 在原版编辑器打开虚拟文件

#### Scenario: 产物重启恢复
- **WHEN** 用户固定会话 Tab 并正常退出，然后重新启动相同便携产物
- **THEN** 复用原版工作台视图持久化，恢复会话 Tab；后端延迟时显示已存历史镜像，同步后恢复交互
