## Purpose

统一产品各执行边界的失败事实交付，使用户和下游能取得真实原因、来源及可用诊断关联；各领域继续持有自己的状态和存储，不依赖穷尽异常类型、逐字段手写文案或新增全局错误系统。

## ADDED Requirements

### Requirement: 未登记异常也必须保留可展示的真实原因

系统 SHALL 从已有异常或协议错误提取可展示原因及可取得的类型、分类和失败操作上下文。普通未知异常 MUST NOT 仅因未登记就被固定文字替代；无消息时 SHALL 明确表示未提供文本。系统 MUST NOT 要求每个字段或每种异常提供专用提示才能正确交付错误。

#### Scenario: 新增异常类型没有专用文案
- **WHEN** 已有执行边界收到从未登记但带消息的异常
- **THEN** 默认摘要沿原原因派生并显示实际操作，用户可按需读取经敏感信息处理的有界原原因与诊断，无需新增 UI 异常分支，也不要求把完整诊断直接上屏

#### Scenario: 工具选项校验失败
- **WHEN** 校验器报告必填字段缺失和额外字段
- **THEN** 结果保留校验器实际字段路径及问题，不要求手写字段检查，不包含原输入值或 validator 上下文中的凭据

### Requirement: 公共错误字段采用固定的最小合同

本项目构造的公共错误 SHALL 复用 `Error(code, message, details)`，保留已有领域 code；新异常没有分类时使用 `unknown_error`，但不得为只有文字的旧历史补造分类。可选 details SHALL 使用固定键：`error_type`／`stage` 为非空字符串；`source` 为错误产生位置的对象，提供时保留原 component 及实际已知身份，`target` 仅保留原边界已知目标 ID，不要求 component，也不表示目标已执行或已故障；各对象只携带实际已知 `gateway_id`／`backend_id`／`workspace_id`／`instance_id`，原领域其它关联仍沿宿主；`issues` 为 `{path: (string|integer)[], code: string, message: string, path_exact?: boolean}[]`，path_exact 仅说明原校验路径是否完整保留；`status_code`／`exit_code` 为整数，`signal` 为字符串；`cause` 和 `errors` 分别为同形公共 Error 和其数组；`truncated` 仅截断时为 true。缺失可选值 SHALL 省略，不填 null、空对象或当前激活身份。校验 path SHALL 保留安全字段段，不按点号拆字段名，且不带 input／context。

request_id 及身份 SHALL 优先使用原宿主位置，details 仅补充实际存在且宿主未携带的关联，不保存第二套可变副本。标准协议 SHALL 在原 adapter 中映射一次，保留其原字段与控制语义；消费者 MUST NOT 遍历候选键猜测类型、阶段或原因。原 adapter SHALL 只比较同一角色及作用域中确应相同的稳定身份，不因 source、操作 owner 和 target 不同而报告冲突。真正冲突时保留原错误及关联、交付协议／归属诊断，不静默择一、不覆盖业务事实或据冲突元数据跨目标导航。

#### Scenario: 标准协议已有不同字段名
- **WHEN** 原协议以自己的字段交付阶段、原因和请求关联
- **THEN** 原 adapter 按固定合同映射必要信息，协议消费者仍可使用原信封，前端不增加多键兜底或第二份 request_id

#### Scenario: 后台失败没有请求关联
- **WHEN** 失败仅有原实例和任务身份，没有 HTTP 请求或已知目标
- **THEN** 仅传递实际身份，缺失的 request_id 和 target 被省略，不填当前激活工作区或虚假默认值

#### Scenario: 客户端故障来源与远端操作目标不同
- **WHEN** DAP adapter 已知 source=workbench，而操作目标属于远端 Gateway／工作区／Thread；或 HTTP target 只包含已知 Gateway／工作区 ID
- **THEN** 角色差异不报身份冲突，不强补 target.component，不把连接失败写成远端业务失败；日志仍按实际日志来源和已有绑定打开，不能根据 component 猜通道

#### Scenario: 同一操作目标身份真正冲突
- **WHEN** 原领域 adapter 按本协议核验到同一目标角色下的稳定工作区 ID 与已确认操作目标不同
- **THEN** 原业务错误与关联仍保留，另交付归属诊断，不静默替换目标、不触发错误工作区的日志或恢复动作

### Requirement: 各模块按职责接入统一错误链路

业务 owner SHALL 决定原结果、code、恢复资格及已知来源；SDK SHALL 只负责本语言通用异常的安全有界提取；HTTP／realtime／DAP 等原 adapter SHALL 各自解析本协议、保留控制分类并核验相应身份。原 UI 操作入口 SHALL 根据已持有领域结果决定提示位置和动作，共享纯展示只派生文本，不再解析 wire 或推断业务状态。Workbench 原桥负责通知／日志／输出副作用，Gateway 原 diagnostics owner 负责日志能力及记录核验，workspaceOutput 只消费这些能力；Error.source 与日志 descriptor.source 不作同义字段处理。

实现 SHALL 复用原原因、少量共享通用提示及原领域已有状态；操作名称沿原入口标签，不按插件／工具／模型／字段或未知异常类型建立专用文案分支。场景用于验证合同，不要求逐场景新增类、helper、状态或测试文件；校验路径与文档时效仅由需要字段定位的链路处理，普通错误不强制携带相关字段。

上述职责 SHALL 沿已有模块落实，不新建对应的一组服务／注册表。SDK 不依赖产品代码；客户端 shared/core 不导入 Web API、React、DOM 或 Workbench；React 沿既有回调使用原工作台能力，不要求所有组件直接调用 OutputService。客户端已报告标记 SHALL 仅在原本地操作链使用，不写入业务状态、wire 或持久历史。MUST NOT 为满足统一入口复制错误解析器、在纯 helper 中增加网络／通知副作用，或改变重试／终态／资源释放策略。

#### Scenario: 新的业务错误接入已有展示
- **WHEN** 原 API adapter 已交付类型化失败及操作上下文，React 和 Workbench 都消费它
- **THEN** 原 owner 提供结果与动作资格，共享纯投影消费已解析事实，原工作台桥执行通知或日志导航，不要求 SDK 理解业务、不让每个组件重解协议，也不由已报告标记清除原失败状态

### Requirement: 各领域沿原边界交付错误并保留业务语义

HTTP 请求、后台执行、插件安装／运行、MCP、配置、主题、运行资源、维护和关闭 SHALL 在所属边界交付失败。各领域 SHALL 保留原状态、原控制分类、授权、重试、取消及释放语义；统一错误显示 MUST NOT 新增自动重试、审批、进程重启或资源释放。各领域 MUST NOT 为错误展示而另建统一业务数据库或要求所有普通函数捕获异常。

#### Scenario: MCP 工具正常返回调用错误
- **WHEN** MCP 连接正常而工具返回 `isError` 或协议业务错误
- **THEN** 对应调用保留原原因，连接不被改写为已断开，不触发新增重连或调用重放

#### Scenario: 配置保存后应用失败
- **WHEN** 候选已保存但未成为 active
- **THEN** 默认摘要明确表达已保存及未生效／应用失败，再提供短原因；原候选、active、pending 及草稿事实不变，不显示全部生效或未保存，不以压缩摘要改变原操作状态

#### Scenario: 用户取消与未知结果
- **WHEN** 用户显式取消，或传输中断后原 owner 无法判定业务结果
- **THEN** 界面保留取消或结果未知语义，不统一改成业务失败，也不伪报成功

#### Scenario: 写入回执丢失而重读看见资源
- **WHEN** 写入回执未取得，后续原重读返回当前资源／revision，但没有原 owner 对该提交的确认
- **THEN** 默认摘要仍保留写入结果未知，不凭当前资源存在推断原写入成功／失败，不清草稿、不重放请求，确认仍交原 operation／幂等入口

### Requirement: Gateway 及跨进程传输不得重新猜测下游错误

已取得下游错误时，传输层 SHALL 保留原状态／错误 code、可展示原因和真实来源；Gateway 自身产生的路由或传输失败 SHALL 明确标明其发生层及已知目标。原协议的错误 envelope SHALL 保持可消费，MUST NOT 仅为统一展示替换标准协议或丢弃协议必要字段。

HTTP／MCP／DAP 原始错误载荷 SHALL 沿原协议的鉴权、脱敏、内容类型和大小规则传输。16 KiB 公共错误预算 SHALL 只约束项目构造的 Error 和原 adapter／客户端提取的公开载荷，不是默认 UI 摘要的视觉长度；Gateway MUST NOT 因该预算新增下游正文缓冲、解析、截断或重编码，亦不替 owner 净化整个响应。公开提取 SHALL 使用已知协议的有界必要字段，不写回原对象；非 JSON 正文不猜字段或全量读取另造信封。Gateway 自产错误 SHALL 遵守公共预算，原传输超限仍保持原 transport 语义。

#### Scenario: 远端工作区返回业务拒绝
- **WHEN** 请求经过入口 Gateway 和远端 Gateway，工作区后端返回有原因的拒绝
- **THEN** 客户端保留原业务状态及原因，不改写成 Gateway 无法连接；原请求链透传同一 request_id

#### Scenario: Gateway 尚未收到上游响应
- **WHEN** Gateway 连接目标失败
- **THEN** 返回 Gateway 传输失败及实际可取得的原因，不声称后端或插件已执行并失败

#### Scenario: 原协议错误载荷大于公开错误预算
- **WHEN** 合法下游 HTTP／MCP／DAP 错误载荷超过 16 KiB，但符合原协议传输限制
- **THEN** 代理保留原响应体、状态／协议 code 及 request_id，不新增正文解析；原消费入口仅生成有界脱敏摘要并标记省略，原 data 和工具正文不被改写

#### Scenario: 下游返回非 JSON 错误正文
- **WHEN** 下游按其既有合同返回非 JSON 错误响应
- **THEN** Gateway 保留内容类型和原响应，不因通用 Error 格式化而猜测 JSON 字段、全量缓冲或更换为本层错误

### Requirement: 失败查询与事件必须保留同一 owner 的原因和身份

领域已有持久结果时，其查询与事件 SHALL 消费同一已提交失败事实。运行期状态继续由其原 owner 持有；没有持久历史需求的周期维护或客户端错误 MUST NOT 为满足本要求新增错误账本。作用域和诊断关联 SHALL 使用真实已有标识，不从当前激活工作区推导来源，不伪造 request_id。

#### Scenario: 插件启动失败后重新打开详情
- **WHEN** supervisor 观察到插件启动异常或非预期退出，用户重新打开其详情
- **THEN** 显示原实例、退出信息及有界原始原因，不变成其它实例的错误，不因详情重新打开而重新启动插件

#### Scenario: 无请求上下文的维护失败
- **WHEN** 定时维护任务失败且没有 HTTP 请求
- **THEN** 原日志保留真实任务及所属实例／工作区、异常原因和堆栈，不生成虚假 request_id 或每周期新建业务记录

### Requirement: 共享实时通道须保留故障层次及结构化关联

统一 realtime 的原捕获／error 帧／消费出口 SHALL 保留有界安全原因和实际已有的订阅／请求关联，原日志复用脱敏报告，不只发异常类名或额外记录 raw traceback。客户端 SHALL 沿原字段保留 request_id／subscription_id 和发起的订阅 path，不把标识拼入 message 后反解析；无 HTTP 状态／请求 ID 时不补造 500 或握手关联。已开始交付的 HTTP 响应 MUST NOT 被改写为第二个错误响应。

单订阅失败 SHALL 仅沿原协议结束相应订阅，不升级为共享连接故障或影响其它订阅；连接级失败沿原统一管理入口处理，不由各业务再建连接／重试。多个消费者收到同一 Error／cause 时 MUST NOT 变异共享对象以写入各自 Thread、插件或目标身份，而使用原订阅上下文展示。订阅 ID 不作跨连接／持久身份；传输故障不写成领域业务失败终态，各订阅镜像不各弹通知。

#### Scenario: 单订阅在响应开始后失败
- **WHEN** 一个订阅已交付响应头，随后原流读取抛错，其它订阅正常
- **THEN** 原 error 帧和客户端保留安全原因及该订阅真实关联，仅结束该订阅，不补造 HTTP 500、不破坏其它订阅或重写已开始的响应

#### Scenario: 多订阅收到同一个连接错误对象
- **WHEN** 一个共享连接故障被分发给不同 Thread／插件的 pending 订阅
- **THEN** 共享异常不被各消费者覆写业务身份，各镜像使用各自原上下文且不分别弹通知，原统一入口处理连接状态，不把传输失败落成多个业务终态

### Requirement: 主要失败与后续清理失败均须透明

操作失败后发生的释放、关闭或诊断写入错误 SHALL 保留原主要失败及次生故障，不能相互覆盖或伪报成功。原资源 owner SHALL 继续持有真实未释放／待核实状态。报告失败 MUST NOT 递归触发同一报告器、添加无限重试或阻断其它按原规则独立的维护任务。

#### Scenario: 调用失败后释放也失败
- **WHEN** 业务操作抛错，随后资源释放抛出另一异常
- **THEN** 诊断可定位两项故障，业务原因不被替换，资源未释放事实仍可见

### Requirement: 公开错误必须有界并遵守凭据保护

公开错误 SHALL 保留真实原因，并在现有出口对认证头、Cookie、凭据字段、敏感 URL 部分及当次已知凭据值进行统一处理。本链路产品生成的诊断 SHALL 在原报告出口将不含 locals 的有界 traceback／stack 及 cause 脱敏后交原 logger，MUST NOT 再传原始 exc_info／Error 生成第二份未处理堆栈。秘密值 SHALL 仅由既有凭据使用边界以当次短期参数提供，不放入异常属性、ContextVar、日志 extra 或全局注册表，不查询完整密钥库或环境。不持有值的边界仍处理结构敏感字段及认证语法，不承诺识别任意未知编码秘密。本要求不扫描重写历史日志或拦截第三方自行输出。

上述预算对象为本项目构造／持久化的公共 Error 和消费侧提取的公开载荷，不替换原协议传输规则或默认 UI 的视觉约束。沿原更严格预算；否则整个上述错误 JSON UTF-8 SHALL 至多 16 KiB（包含 details／issues／cause／errors），其中 message 至多 8 KiB，issues 至多 32 项，cause／errors 合计至多 8 个后代、嵌套至多 4 层。预算 SHALL 使用公共常量而非新增用户配置。提取 SHALL 有界遍历并累计预算，不先复制或序列化整个异常／上游 data 后才截断；优先保留原 code／类型、宿主关联及截断标记，再保留主原因及次要详情。秘密识别和处理 SHALL 先于文本裁剪，防止泄露凭据残片。超限 SHALL 标记 `details.truncated`，不触发完整日志补读或改变状态。错误文本 MUST NOT 作为 HTML、命令或任意可信跳转执行。

#### Scenario: 错误同时含原因与凭据
- **WHEN** Provider／校验器／stderr 错误包含测试凭据及拒绝原因
- **THEN** API、事件及公开界面不包含凭据，仍能识别拒绝原因；原报告出口记录的 message、堆栈和 cause 也不含该已知凭据，logger 不输出第二份原始异常

#### Scenario: 子进程产生大段 stderr
- **WHEN** 失败输出超过错误结果大小预算
- **THEN** 返回原退出状态及有界脱敏摘要，明确截断，沿原日志入口查看，不读取全文件构造 API

#### Scenario: 深层子错误和校验详情共同超限
- **WHEN** 异常含深层 cause、大量 ExceptionGroup 成员及长路径校验问题
- **THEN** 构造时停止超预算遍历，最终错误整体及各项数量均符合上限，保留主原因、原关联和截断标记，不因单个 details 或子错误绕过总预算

### Requirement: 诊断日志须在格式化过程中限制开销

本链路新生成的单条诊断正文 SHALL 沿原更严格预算；否则 UTF-8 至多 64 KiB，包含 message、stack／cause 和省略标记，所有选定异常的堆栈帧合计至多 64 帧，原因后代／深度复用 8 个／4 层上限。实现 SHALL 在有界选择原因节点及堆栈帧后复用标准格式化原语，脱敏并累计正文预算，优先保留主原因、真实关联及靠近抛错点的帧，超限停止并明确省略。MUST NOT 先递归构造完整 traceback／ExceptionGroup、渲染巨大校验正文或拼接完整 stack 再截断；日志轮转不能替代构造预算。不要求新建通用格式化框架、报告线程／沙箱或完整诊断旁路存储。

#### Scenario: 日志格式化遇到大异常链
- **WHEN** 原报告入口收到长 cause 链、大量子错误及超长消息
- **THEN** 诊断在遍历和格式化阶段受预算限制，不先生成整份文本，最终保留主原因、有效关联和省略标记；日志不含已知凭据，公开错误预算仍独立满足

### Requirement: 前端应展示错误事实而非自行归因

客户端 SHALL 沿原 adapter 消费已解析事实，共享纯展示入口派生摘要，原领域及 Workbench 入口负责提示与动作；迁齐消费者后删除混合诊断后缀和局部 formatter，不正则反解析或仅靠 CSS 掩盖旧格式。具体职责如下：

- 默认摘要 SHALL 使用入口已有操作名和安全 message／issues，紧凑提示单行、独立空态至多两行；无原因如实说明，不把 path／status／来源解析错误当业务原因。必要业务名称可保留，来源、阶段、堆栈、关联只入按需诊断，不塞长 title。原公开原因预算不变，视觉省略 MUST NOT 写回协议、历史、缓存／状态的 failure 或另存摘要；字段诊断、主动展开结果及日志不套紧凑行限。
- 原 HTTP adapter SHALL 保留 status／detail／path／requestId 和安全来源；来源头缺失与损坏分开，安全解析诊断不含原头／解析原文、不覆盖业务原因。非 2xx 正文故障保留已取得响应，不能由外层超时抹掉或充当业务原因；要求 JSON 的 2xx 解包失败保留响应关联、短解包原因，已有正文片段只入有界脱敏诊断，不推断业务结果。无响应、主动取消、允许空／非 JSON 正文、令牌刷新及重试保持原合同，不为展示新增重读／clone、parser、wire 或持久状态。
- 原校验 adapter SHALL 沿 issue.path_exact 说明路径保真，失真／未声明精确仅作诊断，不根据占位字符串或整体 truncated 猜定位。原编辑器使用字段段和原映射解释前缀／语法／分支，并在返回及点击时核对发起资源与模型版本／草稿；不可映射或草稿已变则停用标记／精确跳转，仍保留原因。不能反解析点号路径、猜相似控件、覆盖草稿、自动重验或另存原路径／文档版本；问题总数只用 owner 已知事实，截断不冒充全部。
- 正常响应中的类型化失败 SHALL 由原 adapter 提供原因，与异常共用纯显示，不 String 为对象文本、强行 throw、改状态或删工具正文。聚合／批量结果保留实际成功、失败、取消／未执行及逐项关联，不把部分失败说成全部失败、不任取根因、补造总数或重放成功项；混合已报告成员由原聚合出口交必要汇总，不重复通知或新增账本。
- 同一操作 SHALL 在原可见区域或原生通知交付一次主要提示，复用 ReportedError 且保持失败返回；字段诊断保留修正信息，搜索保留成功分支与范围，后台默认日志。仍有效且需要反馈但无可见区域时才通知，仅日志／隐藏状态不算已报告；关闭已显示区域不补发通知，多视图可保留镜像但不各弹通知，不强制各组件新建错误槽／去重状态。
- 原操作入口 SHALL 捕获已有 owner／目标／资源快照供回调、日志及复制使用；旧响应沿原生命周期废弃，不覆盖新目标／操作或抢焦点。用户取消与期限／网络故障按原上下文区分，不仅凭 AbortError 名称。恢复或同类新操作成功沿原生命周期替换对应展示；关闭提示、查看日志、无关成功或网络恢复不清除权威业务失败。
- 领域 owner SHALL 决定结果与恢复资格；已保存未生效、写入结果未知及传输故障不得被通用失败抹平，也不靠当前资源／revision 推断原提交成功。动作只复用原资格，不默认添加重试或调用重放。查看／复制须键盘可达、保持可访问名称，不只靠 hover、不自动抢焦点或高频播报。

#### Scenario: 公共原因同时被协议和 UI 消费
- **WHEN** 同一长安全原因通过插件命令错误帧交付，并在紧凑 UI 中显示
- **THEN** 原错误帧及诊断仍保留原预算内的原因，UI 只派生短摘要并提供按需诊断；不能通过缩短公共 failureMessage 让所有消费者只拿到视觉省略文本

#### Scenario: 原冲突原因存在但来源响应头损坏
- **WHEN** HTTP 返回原 409、冲突原因和 request_id，但错误来源头无法解析
- **THEN** 摘要仍显示原冲突原因，诊断／复制保留来源元数据损坏及原关联，不泄露原头、不以当前目标补来源、不改抛解析异常；头未提供时不误报损坏

#### Scenario: 错误正文没有可读原因
- **WHEN** 原 HTTP 错误正文只有 code 或没有可用 message／issues
- **THEN** 摘要保留原已知操作结果并说明未提供原因，原 path／status／code 保留于诊断，不把接口路径当成原因，也不猜测为权限、配置或连接问题

#### Scenario: 错误响应头已收到但正文读取超时
- **WHEN** 原入口已收到非 2xx 状态及 request_id，随后正文读取中断或耗尽原期限
- **THEN** 原 HTTP 失败及响应关联仍可诊断，说明原因正文未取得并单独保留读取故障，不退化成丢失状态和关联的普通超时，不把客户端读取失败说成服务端业务原因，不重试请求

#### Scenario: JSON 入口收到带关联的 2xx HTML
- **WHEN** 要求 JSON 的请求收到 2xx、原 request_id 及 HTML 或损坏的 JSON，无法按原合同解包
- **THEN** 默认显示短解包失败，实际状态、路径及 request_id 沿原错误承载保留，已有安全正文片段只入诊断；不把 HTML 直接上屏、不宣称写入失败或成功、不重读响应，允许空正文／非 JSON 的端点保持原行为

#### Scenario: 历史读取失败含长诊断
- **WHEN** 历史请求返回含校验原因、长路径、来源及 request_id 的错误，页面同时有历史区和 Composer
- **THEN** 历史区仅显示一条紧凑摘要及实际可用动作，Composer 和通知不复制它；窄编辑器不被诊断撑高，原原因与关联可按需读取

#### Scenario: 设置存在多个字段问题
- **WHEN** 校验器返回多个可定位的问题，或 JSONC 存在具体行列错误
- **THEN** 原字段或编辑器诊断保留修正原因及定位，默认提示不拼接请求路径／request_id，也不将所有问题替换为通用“参数错误”

#### Scenario: 校验结果已截断且字段名包含分隔符
- **WHEN** 原 owner 未提供总数，issues 已截断，且字段段含点号、斜杠或数组下标
- **THEN** 只披露已返回数量和省略，沿原字段段定位；无法映射的原问题仍可查看，不把有限问题当全部或标到另一字段

#### Scenario: 安全展示路径已经不能精确定位
- **WHEN** 原字段路径因脱敏、预算裁剪或额外字段占位变成不完整路径，或完整校验路径含领域 owner 无法映射的分支标签
- **THEN** 提取方准确交付 path_exact，原领域编辑器只在路径保真且映射成立时提供精确定位；其它情况保留安全问题，不将占位符当真实字段、不按字符串猜完整性，不读取秘密或查询后台重建路径

#### Scenario: 同一配置资源的草稿已发生变化
- **WHEN** 校验针对草稿 A 发起，用户继续编辑或重排数组成为 B，旧结果返回或用户再点击 A 的字段定位
- **THEN** 原编辑器沿现有模型版本／草稿状态停用旧标记和精确跳转，保留 A 的失败事实及安全原因，不标错 B 的字段、不覆盖 B、不重发校验；稳定版本下的原定位仍可用

#### Scenario: 模型探测正常返回业务失败
- **WHEN** 原 HTTP 请求成功交付，但其已声明结果状态为失败并携带结构化 error
- **THEN** 所属测试结果显示原短原因及可用诊断，不出现 `[object Object]`，不改成 HTTP 失败、不强行抛错或重复弹通知

#### Scenario: 批量操作部分成功
- **WHEN** 原批量附件处理或模型测试有成功项和失败项
- **THEN** 保留成功项及逐项已知结果，以原数量汇总部分失败，不清空成功项、逐项重复通知或重新提交成功操作

#### Scenario: 配置操作与状态重读均失败
- **WHEN** 原配置操作失败，沿原流程重读状态也失败并产生 AggregateError
- **THEN** 诊断分别保留操作和重读错误及各自关联，不用后一个失败覆盖前一个、只留外层标题或猜未核实状态，也不因此重放写入

#### Scenario: 聚合同时包含已报告与未报告成员
- **WHEN** 原聚合出口收到一个已交付成员和一个尚未交付的真实失败
- **THEN** 未报告失败仍有必要的汇总和诊断，已报告成员不被再次逐项通知，也不因为其中一项已报告就吞掉整体

#### Scenario: 插件操作已有行内结果
- **WHEN** 插件操作或日志读取失败已由所属区域显示结果，异常继续传给调用方
- **THEN** 调用仍保持失败语义，上层不再弹同一错误；另一次独立操作的失败不会被全局去重机制吞掉

#### Scenario: 联邦搜索仅部分分支失败
- **WHEN** 用户所选范围内一个查询分支失败，其它分支已有结果
- **THEN** 原失败分支显示范围、短原因和不完整状态，保留其它结果，技术诊断按需查看，不新增全局通知或跨范围查询

#### Scenario: 请求参数未修正
- **WHEN** 原 owner 已确认参数契约不成立，原流程没有可用的原样重试资格
- **THEN** UI 保留原因和诊断入口，不把重复发送相同请求作为恢复动作，不仅凭 422 状态码决定重试或改写实际原因

#### Scenario: 操作失败时没有可见结果区域
- **WHEN** 仍有效且需要反馈的普通用户操作失败，所属区域已关闭且原错误尚未向用户展示
- **THEN** 原 UI 边界使用原生通知交付一次摘要，不能仅因日志已写或隐藏状态已更新而标记为已报告，也不新建常驻错误槽

#### Scenario: 多个编辑器观察同一失败
- **WHEN** 用户操作失败并被多个 Thread／插件状态订阅者观察到
- **THEN** 原发起入口只交付一次交互提示，各视图保留各自所属状态镜像，不各弹一次通知，也不新增跨窗口去重状态

#### Scenario: 中止异常并非用户取消
- **WHEN** 请求因期限或网络中断失败，其异常名为 AbortError，但原调用上下文未认定用户取消或过期
- **THEN** 原故障保持可见且原因可诊断，不按名称静默吞掉；真正的主动取消仍沿原取消语义处理

#### Scenario: 主题加载请求失败
- **WHEN** 用户切换主题失败
- **THEN** 原入口显示实际加载错误和真实生效主题，不静默当作切换成功，不出现多层重复通知

#### Scenario: 原生主题恢复或预览取消
- **WHEN** 已选主题被移除、启动时缺失，或用户取消主题预览
- **THEN** 原 Workbench 默认主题恢复及预览还原规则保持，界面显示实际生效主题，不把正常恢复禁用或误报为本次切换成功，不新增重复通知

#### Scenario: 旧目标错误晚于新目标结果返回
- **WHEN** 用户切换目标后旧请求失败才返回
- **THEN** 新目标当前结果不被旧错误替换，旧错误仍按原操作归属处理

#### Scenario: 编辑器复用后旧回调记录诊断
- **WHEN** 操作由 Thread／模型 A 发起，失败回调执行前编辑器已复用为 B
- **THEN** 原诊断和复制仍使用 A 的发起快照，不能用 B 的名称或身份标注；过期 UI 更新沿原规则废弃，不额外注册请求身份

### Requirement: 错误详情须沿原输出入口定位真实来源

“查看日志” SHALL 复用现有输出命令、窗口日志桥、日志查询／记录引用和 OutputService。动作 SHALL 绑定原失败实际已知的目标、工作区、通道及记录／请求／操作或实例关联，不用当前激活目标或同名新实例补齐未知身份，不伪造 request_id。仅用户点击后按需读取：已有记录引用沿原有界读取；只有关联时先定位已加载通道，未找到才复用既有有界查询。默认错误展示 MUST NOT 等待日志读取，不新增索引、全文件扫描、跨目标兜底、后台预取、轮询、连接、数据库或错误订阅。

导航 SHALL 区分已定位记录与仅打开通道；只能打开通道时应明确命名为“打开输出”。轮转、截断、来源失效和未找到 SHALL 诚实显示，不把最近 300 行加载成功当作原错误定位成功。现有可复制公开诊断 SHALL 保留；展开／复制不隐式查询，不以搬入日志为由绕过脱敏。原 owner 记录原诊断，上层不重复堆栈；客户端本地异常使用窗口日志。诊断读取失败 SHALL 作为本次输出操作的简短结果，不递归调用同一导航或层层弹通知。

日志查询 SHALL 复用原单行字面量及 `complete／limited_reason／cursor` 合同，一次点击执行一次有界查询；未完成时只报告本次限制和所查范围，后续翻页由用户显式发起，不自动追续点。零命中且未完成 MUST NOT 宣称没有日志。命中 SHALL 核对实际来源和原 log_id／实例身份，多条候选保留来源及用户选择，不能按首条／最近记录或 request_id 子串命中推断根因。诊断读取请求的 request_id SHALL 与原业务请求关联分别表达，不能替换原业务 ID；记录引用沿原版本核验，失效不跳到新文件同一偏移。

日志坐标 SHALL 沿原 diagnostics 合同：line_start／line_end 为文件物理行的 UTF-8 字节半开区间，不是行号；start_codepoint／end_codepoint 为原 locate.text 去行尾、UTF-8 替换解码后的 Unicode 码点半开区间。原日志 owner SHALL 明确 schema／说明中的单位而不改引用名称或重编码。Workbench 输出定位 adapter SHALL 在本次已核验文本中转换到 Monaco 的 UTF-16 行列／模型偏移，保持真实命中，不能将码点直接用作模型 offset、将字节当行号或将 preview 当原行；无法映射不宣称定位成功。MUST NOT 为适配编辑器另存一套后端坐标、添加通用定位服务或读取完整日志。

既有设置页日志记录查看的调用方、读取及定位 SHALL 迁齐到原输出动作，删除旧专用 viewer／展示路由及悬空消费者，不保留两套读取渲染；原 query／locate 后端 API 继续复用，诊断配置仍留原设置入口。旧查看入口的有效归属、版本及请求生命周期断言 SHALL 迁移保留，不因删除组件取消验证。定位记录 MUST NOT 被实时尾部刷新立即覆盖或拼入实时尾部冒充新日志。关闭／切换通道或后续导航 SHALL 沿原生命周期取消或废弃旧定位结果，不覆盖新范围。日志停用、无 sink／精确关联或远端不可用时，用户仍可经原菜单复制已持有的安全诊断；无可用来源不展示虚假日志动作，不为此建立备用错误文件、开启日志或预取数据。

插件编辑器及管理视图的实例日志查看 SHALL 同样通过原输出动作打开点击时的真实目标、工作区绑定及 log_id，删除各自 pre／读取和重复错误提示链路，保留插件原状态及短原因。迁齐所有调用后 SHALL 删除旧 `readPluginInstanceLog` UI 导出，输出使用已有 Gateway API，不反向依赖插件编辑器、不新增读取 facade；旧目标核验、取消、实例替换与日志状态断言保持。设置页原输出按钮、诊断配置和进程状态概览不在删除范围。

输出操作 SHALL 如实区分打开、读取与定位，不能以 showChannel 或 void 触发读取宣称加载成功；发现／读取失败由原操作边界交付一次，不由内部 catch 和外部命令重复报告。同一来源刷新失败可保留最后成功正文，但须在原动作／视图反馈中表达未刷新；首次读取失败不表示空日志，切换来源不得把旧正文当新结果。空／不可用／截断及读取错误 SHALL 由原 DTO 元数据和视图反馈承载，不写作本地日志镜像中的原日志行、不参与日志正文复制或命中定位。MUST NOT 为此增加持久状态、日志记录、轮询、重试或成功回执协议。

query／locate SHALL 沿用 diagnostics 尾读的同名可选 `gateway_connection_id` 查询参数，由原传输及注册表验证其与稳定 Gateway 的归属；未指定时只允许原唯一连接规则。明确连接失效或不匹配 SHALL 拒绝，不默选其它连接或凭据；连接 ID 不存入日志记录引用，联邦入站不增加再次转接权限。日志 source／范围 SHALL 使用原 descriptor 披露的日志归属，不能仅凭插件的工作区 binding 推导；仅支持尾读的来源只提供真实打开输出能力，不伪造精确定位或另建插件日志 API。客户端窗口日志 SHALL 保持本地来源。

复制诊断 SHALL 只选择本次已持有的公开错误和安全关联，不序列化整个 Error／Response／请求选项或配置对象，不自动附加原始日志尾部。本变更不宣称第三方原日志已经净化，不重写原日志或扩大其访问边界。

诊断复制 SHALL 复用当前运行面的既有剪贴板入口，由该入口处理临时节点清理、失败传播和必要的焦点／选区还原；错误组件只交付文本及动作结果，不另建 clipboard 或焦点服务。失败时也须清理临时节点，不改变 Composer／配置草稿，不把焦点遗留在隐藏输入或在用户切换后抢回原编辑器。成功提示 SHALL 在实际复制完成后交付；失败沿原动作短反馈，原业务故障不被替换，不自动重试、循环申请权限或弹新详情窗。

#### Scenario: 失败后切换目标再查看日志
- **WHEN** 操作在目标 A 的工作区失败，用户切到目标 B 后点击原错误的查看日志
- **THEN** 输出导航仍绑定 A 的原工作区和真实来源，并定位可得的原关联，不用 B 的日志解释 A 的失败，也不激活 A 的导航工作区

#### Scenario: 日志记录已轮转或只有通道身份
- **WHEN** 原记录不在现有保留范围，或错误仅携带可打开的通道而没有精确关联
- **THEN** 分别说明未找到记录或仅打开输出，保留已持有的安全诊断，不扫描全部历史、不假称已定位、不递归触发诊断查询

#### Scenario: 一页查询零命中但未完成
- **WHEN** 诊断查询返回空 items、complete=false 及扫描／字节／期限等限制原因
- **THEN** 只说明本次查询范围及限制，保留可用续点供用户显式继续，不自动扫描后续页或断言原日志不存在

#### Scenario: 同一请求命中多个进程的日志
- **WHEN** 字面量查询匹配同一请求的多层日志或关联 ID 子串，并产生本次诊断请求的新 request_id
- **THEN** 按真实来源及可核验关联呈现候选，不任取一条作为根因，不把诊断请求 ID 覆盖到原失败，不给不匹配的实例标记已定位

#### Scenario: 旧定位请求晚到或实时尾部更新
- **WHEN** 用户在定位返回前关闭／切换输出，或定位展示后原尾部通道刷新
- **THEN** 旧请求不能覆盖新范围、重开通道或抢焦点；有效定位记录不被尾部刷新立即替换，也不被作为新日志插入原尾部

#### Scenario: 普通错误没有可用日志来源
- **WHEN** 业务失败已有安全错误载荷，但目标断开、日志关闭或没有可打开的日志来源
- **THEN** 原摘要及经键盘可用的复制诊断仍可用，不显示虚假查看日志动作、不要求先恢复日志或新增备用账本

#### Scenario: 同一远端 Gateway 登记多个连接
- **WHEN** 原失败已带明确连接，日志 query／locate 面对该 Gateway 的多条管理连接
- **THEN** 原参数沿原路由传递并核实归属；指定连接失效时明确失败，不任取第一条或换凭据，原业务 ID 和稳定日志引用不变

#### Scenario: 工作区插件使用 Gateway 日志源
- **WHEN** 插件绑定工作区，但原日志 descriptor 标记 source=gateway
- **THEN** 沿原 Gateway 日志源和真实实例通道打开，不改查该工作区后端日志，也不因为处于其它工作区而替换插件来源

#### Scenario: 从插件详情或管理视图查看实例日志
- **WHEN** 用户从任一插件入口点击查看当前实例日志，随后实例被替换或读取失败
- **THEN** 原输出动作沿原 log_id 和目标处理，失效时明确说明，不转向同名新实例、不再展开局部日志 pre，也不同时由内部读取和命令调用方弹出失败通知

#### Scenario: 尾读刷新失败或日志为空／截断
- **WHEN** 同一日志最后成功内容仍可见但刷新失败，或日志 owner 返回 empty／truncated
- **THEN** 原视图反馈区分未刷新与真实空／截断；原正文及其复制不混入状态文案，首次读取失败不被当作空日志，切换来源不显示上一来源内容充当新结果

#### Scenario: 日志命中前含非 BMP 字符且原文件使用 CRLF
- **WHEN** 用户将带 emoji／非 BMP 字符、同一行重复命中的已核验日志记录定位到原输出模型，原物理行使用 CRLF
- **THEN** Workbench 转换原码点范围后高亮指定命中，原字节引用和 Gateway 坐标不变，不受 preview 截取或模型追加行尾影响；不能高亮另一处同名文本，不通过读取全文件重算位置

#### Scenario: 复制诊断时原对象还含私密请求信息
- **WHEN** 客户端原异常或关联对象还引用认证头、配置或未经本链路处理的原始日志
- **THEN** 复制仅包含本次有界安全公开错误和关联，不展开引用对象或自动读取／附加原日志，原诊断信息仍可用

#### Scenario: 诊断复制使用兼容路径或被浏览器拒绝
- **WHEN** 用户经已有剪贴板入口复制诊断，兼容复制临时转移焦点并成功或失败，或等待期间已切换编辑器
- **THEN** 原入口清理临时节点并只还原本次仍有效的焦点／选区，草稿不变；仅成功后提示已复制，失败保留原业务原因且不重试、不抢回旧编辑器焦点

### Requirement: 客户端渲染故障须保留可用的诊断出口

客户端局部错误边界 SHALL 保留原隔离粒度，显示短摘要并沿现有窗口日志记录诊断。整个工作台不可用且无法打开输出时，故障页 SHALL 提供本地展开／复制已持有安全诊断及原有重载动作，不依赖后端或成功写入日志。该故障页职责 MUST NOT 扩大为每个业务组件各建详情系统；日志出口失效不得覆盖原故障或伪报成功。

#### Scenario: 整个工作台渲染失败
- **WHEN** 顶层渲染边界捕获异常且原输出 UI 不可用
- **THEN** 默认显示短故障说明，用户仍可本地展开／复制有界脱敏原因并重载，页面不直接铺开长异常，也不显示不可用的查看日志动作

### Requirement: 错误交付不能增加普通交互的全量检查与等待

错误提取 SHALL 仅使用当次有界载荷、异常及已持有上下文，不要求全库审计、扫描历史、读取完整密钥库或新增常驻连接。普通请求 SHALL 沿用既有完整链路预算：≤512 KiB 暖读 p95≤500ms、单次≤1500ms，三步导航总 p95≤1000ms、单次≤2000ms，可操作 Composer／文件可见≤2000ms，首次未缓存业务读取≤3000ms；原历史更严格预算优先。快速本地失败 SHALL 计时至完整错误结果或真实错误 UI 可见，不以占位或进程 timeout 代替。

#### Scenario: 大历史中的一个失败 Turn
- **WHEN** 用户打开含一条失败 Turn 的大历史小页
- **THEN** 只沿原有界投影读取失败信息，满足原历史页预算，不全量读 Trace 或运行日志补错误
