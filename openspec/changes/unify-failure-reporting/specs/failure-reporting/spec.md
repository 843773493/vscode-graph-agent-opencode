## Purpose

统一产品各执行边界的失败事实交付，使用户和下游能取得真实原因、来源及可用诊断关联；各领域继续持有自己的状态和存储，不依赖穷尽异常类型、逐字段手写文案或新增全局错误系统。

## ADDED Requirements

### Requirement: 未登记异常也必须保留可展示的真实原因

系统 SHALL 从已有异常或协议错误提取可展示原因及可取得的类型、分类和失败操作上下文。普通未知异常 MUST NOT 仅因未登记就被固定文字替代；无消息时 SHALL 明确表示未提供文本。系统 MUST NOT 要求每个字段或每种异常提供专用提示才能正确交付错误。

#### Scenario: 新增异常类型没有专用文案
- **WHEN** 已有执行边界收到从未登记但带消息的异常
- **THEN** 用户能看到经敏感信息处理的原原因及实际操作，有界诊断可沿已有来源定位，无需新增 UI 异常分支

#### Scenario: 工具选项校验失败
- **WHEN** 校验器报告必填字段缺失和额外字段
- **THEN** 结果保留校验器实际字段路径及问题，不要求手写字段检查，不包含原输入值或 validator 上下文中的凭据

### Requirement: 公共错误字段采用固定的最小合同

本项目构造的公共错误 SHALL 复用 `Error(code, message, details)`，保留已有领域 code；新异常没有分类时使用 `unknown_error`，但不得为只有文字的旧历史补造分类。可选 details SHALL 使用固定键：`error_type`／`stage` 为非空字符串；`source`／`target` 为包含 `component` 和实际已知 `gateway_id`／`backend_id`／`workspace_id`／`instance_id` 的对象；`issues` 为 `{path: (string|integer)[], code: string, message: string}[]`；`status_code`／`exit_code` 为整数，`signal` 为字符串；`cause` 和 `errors` 分别为同形公共 Error 和其数组；`truncated` 仅截断时为 true。缺失可选值 SHALL 省略，不填 null、空对象或当前激活身份。校验 path SHALL 保留原字段段，不按点号拆字段名，且不带 input／context。

request_id 及身份 SHALL 优先使用原宿主位置，details 仅补充实际存在且宿主未携带的关联，不保存第二套可变副本。标准协议 SHALL 在原 adapter 中映射一次，保留其原字段与控制语义；消费者 MUST NOT 遍历候选键猜测类型、阶段或原因。上下文与原宿主身份冲突时 SHALL 明确报告协议／归属错误，不静默择一。

#### Scenario: 标准协议已有不同字段名
- **WHEN** 原协议以自己的字段交付阶段、原因和请求关联
- **THEN** 原 adapter 按固定合同映射必要信息，协议消费者仍可使用原信封，前端不增加多键兜底或第二份 request_id

#### Scenario: 后台失败没有请求关联
- **WHEN** 失败仅有原实例和任务身份，没有 HTTP 请求或已知目标
- **THEN** 仅传递实际身份，缺失的 request_id 和 target 被省略，不填当前激活工作区或虚假默认值

### Requirement: 各领域沿原边界交付错误并保留业务语义

HTTP 请求、后台执行、插件安装／运行、MCP、配置、主题、运行资源、维护和关闭 SHALL 在所属边界交付失败。各领域 SHALL 保留原状态、原控制分类、授权、重试、取消及释放语义；统一错误显示 MUST NOT 新增自动重试、审批、进程重启或资源释放。各领域 MUST NOT 为错误展示而另建统一业务数据库或要求所有普通函数捕获异常。

#### Scenario: MCP 工具正常返回调用错误
- **WHEN** MCP 连接正常而工具返回 `isError` 或协议业务错误
- **THEN** 对应调用保留原原因，连接不被改写为已断开，不触发新增重连或调用重放

#### Scenario: 配置保存后应用失败
- **WHEN** 候选已保存但未成为 active
- **THEN** 设置结果保留候选和实际失败原因，原 active 事实不变，不显示配置已全部生效

#### Scenario: 用户取消与未知结果
- **WHEN** 用户显式取消，或传输中断后原 owner 无法判定业务结果
- **THEN** 界面保留取消或结果未知语义，不统一改成业务失败，也不伪报成功

### Requirement: Gateway 及跨进程传输不得重新猜测下游错误

已取得下游错误时，传输层 SHALL 保留原状态／错误 code、可展示原因和真实来源；Gateway 自身产生的路由或传输失败 SHALL 明确标明其发生层及已知目标。原协议的错误 envelope SHALL 保持可消费，MUST NOT 仅为统一展示替换标准协议或丢弃协议必要字段。

HTTP／MCP／DAP 原始错误载荷 SHALL 沿原协议的鉴权、脱敏、内容类型和大小规则传输。16 KiB 公共错误预算 SHALL 只约束项目构造的 Error 和原 adapter／客户端提取的展示摘要；Gateway MUST NOT 因摘要预算新增下游正文缓冲、解析、截断或重编码，亦不替 owner 净化整个响应。消费摘要 SHALL 使用已知协议的有界必要字段，不写回原对象；非 JSON 正文不猜字段或全量读取另造信封。Gateway 自产错误 SHALL 遵守公共预算，原传输超限仍保持原 transport 语义。

#### Scenario: 远端工作区返回业务拒绝
- **WHEN** 请求经过入口 Gateway 和远端 Gateway，工作区后端返回有原因的拒绝
- **THEN** 客户端保留原业务状态及原因，不改写成 Gateway 无法连接；原请求链透传同一 request_id

#### Scenario: Gateway 尚未收到上游响应
- **WHEN** Gateway 连接目标失败
- **THEN** 返回 Gateway 传输失败及实际可取得的原因，不声称后端或插件已执行并失败

#### Scenario: 原协议错误载荷大于展示摘要预算
- **WHEN** 合法下游 HTTP／MCP／DAP 错误载荷超过 16 KiB，但符合原协议传输限制
- **THEN** 代理保留原响应体、状态／协议 code 及 request_id，不新增正文解析；原消费入口仅生成有界脱敏摘要并标记省略，原 data 和工具正文不被改写

#### Scenario: 下游返回非 JSON 错误正文
- **WHEN** 下游按其既有合同返回非 JSON 错误响应
- **THEN** Gateway 保留内容类型和原响应，不因通用 Error 格式化而猜测 JSON 字段、全量缓冲或更换为本层错误

### Requirement: 失败查询与事件必须保留同一 owner 的原因和身份

领域已有持久结果时，其查询与事件 SHALL 消费同一已提交失败事实。运行期状态继续由其原 owner 持有；没有持久历史需求的周期维护或客户端错误 MUST NOT 为满足本要求新增错误账本。作用域和诊断关联 SHALL 使用真实已有标识，不从当前激活工作区推导来源，不伪造 request_id。

#### Scenario: 插件启动失败后重新打开详情
- **WHEN** supervisor 观察到插件启动异常或非预期退出，用户重新打开其详情
- **THEN** 显示原实例、退出信息及有界原始原因，不变成其它实例的错误，不因详情重新打开而重新启动插件

#### Scenario: 无请求上下文的维护失败
- **WHEN** 定时维护任务失败且没有 HTTP 请求
- **THEN** 原日志保留真实任务及所属实例／工作区、异常原因和堆栈，不生成虚假 request_id 或每周期新建业务记录

### Requirement: 主要失败与后续清理失败均须透明

操作失败后发生的释放、关闭或诊断写入错误 SHALL 保留原主要失败及次生故障，不能相互覆盖或伪报成功。原资源 owner SHALL 继续持有真实未释放／待核实状态。报告失败 MUST NOT 递归触发同一报告器、添加无限重试或阻断其它按原规则独立的维护任务。

#### Scenario: 调用失败后释放也失败
- **WHEN** 业务操作抛错，随后资源释放抛出另一异常
- **THEN** 诊断可定位两项故障，业务原因不被替换，资源未释放事实仍可见

### Requirement: 公开错误必须有界并遵守凭据保护

公开错误 SHALL 保留真实原因，并在现有出口对认证头、Cookie、凭据字段、敏感 URL 部分及当次已知凭据值进行统一处理。本链路产品生成的诊断 SHALL 在原报告出口将不含 locals 的有界 traceback／stack 及 cause 脱敏后交原 logger，MUST NOT 再传原始 exc_info／Error 生成第二份未处理堆栈。秘密值 SHALL 仅由既有凭据使用边界以当次短期参数提供，不放入异常属性、ContextVar、日志 extra 或全局注册表，不查询完整密钥库或环境。不持有值的边界仍处理结构敏感字段及认证语法，不承诺识别任意未知编码秘密。本要求不扫描重写历史日志或拦截第三方自行输出。

上述预算对象为本项目构造／持久化的公共 Error 和消费侧展示摘要，不替换原协议传输规则。沿原更严格预算；否则整个上述错误 JSON UTF-8 SHALL 至多 16 KiB（包含 details／issues／cause／errors），其中 message 至多 8 KiB，issues 至多 32 项，cause／errors 合计至多 8 个后代、嵌套至多 4 层。预算 SHALL 使用公共常量而非新增用户配置。提取 SHALL 有界遍历并累计预算，不先复制或序列化整个异常／上游 data 后才截断；优先保留原 code／类型、宿主关联及截断标记，再保留主原因及次要详情。秘密识别和处理 SHALL 先于文本裁剪，防止泄露凭据残片。超限 SHALL 标记 `details.truncated`，不触发完整日志补读或改变状态。错误文本 MUST NOT 作为 HTML、命令或任意可信跳转执行。

#### Scenario: 错误同时含原因与凭据
- **WHEN** Provider／校验器／stderr 错误包含测试凭据及拒绝原因
- **THEN** API、事件及公开界面不包含凭据，仍能识别拒绝原因；原报告出口记录的 message、堆栈和 cause 也不含该已知凭据，logger 不输出第二份原始异常

#### Scenario: 子进程产生大段 stderr
- **WHEN** 失败输出超过错误结果大小预算
- **THEN** 返回原退出状态及有界脱敏摘要，明确截断，沿原日志入口查看，不读取全文件构造 API

#### Scenario: 深层子错误和校验详情共同超限
- **WHEN** 异常含深层 cause、大量 ExceptionGroup 成员及长路径校验问题
- **THEN** 构造时停止超预算遍历，最终错误整体及各项数量均符合上限，保留主原因、原关联和截断标记，不因单个 details 或子错误绕过总预算

### Requirement: 诊断日志须在格式化过程中限制开销

本链路新生成的单条诊断正文 SHALL 沿原更严格预算；否则 UTF-8 至多 64 KiB，包含 message、stack／cause 和省略标记，所有选定异常的堆栈帧合计至多 64 帧，原因后代／深度复用 8 个／4 层上限。实现 SHALL 在有界选择原因节点及堆栈帧后复用标准格式化原语，脱敏并累计正文预算，优先保留主原因、真实关联及靠近抛错点的帧，超限停止并明确省略。MUST NOT 先递归构造完整 traceback／ExceptionGroup、渲染巨大校验正文或拼接完整 stack 再截断；日志轮转不能替代构造预算。不要求新建通用格式化框架、报告线程／沙箱或完整诊断旁路存储。

#### Scenario: 日志格式化遇到大异常链
- **WHEN** 原报告入口收到长 cause 链、大量子错误及超长消息
- **THEN** 诊断在遍历和格式化阶段受预算限制，不先生成整份文本，最终保留主原因、有效关联和省略标记；日志不含已知凭据，公开错误预算仍独立满足

### Requirement: 前端应展示错误事实而非自行归因

前端 SHALL 使用原失败原因和上下文，通过所属组件、设置诊断或原 Workbench 通知／日志入口展示。同一操作 MUST NOT 因每层捕获重复弹出相同错误；后台维护默认使用原日志。业务失败、恢复状态和传输失败 SHALL 分别表达，过期错误响应不得覆盖新操作或其它目标状态。没有原因时 SHALL 只表示缺失，不推断后端未提供、权限不足、需要审批或连接断开。

#### Scenario: 主题加载请求失败
- **WHEN** 用户切换主题失败
- **THEN** 原入口显示实际加载错误和真实生效主题，不静默当作切换成功，不出现多层重复通知

#### Scenario: 原生主题恢复或预览取消
- **WHEN** 已选主题被移除、启动时缺失，或用户取消主题预览
- **THEN** 原 Workbench 默认主题恢复及预览还原规则保持，界面显示实际生效主题，不把正常恢复禁用或误报为本次切换成功，不新增重复通知

#### Scenario: 旧目标错误晚于新目标结果返回
- **WHEN** 用户切换目标后旧请求失败才返回
- **THEN** 新目标当前结果不被旧错误替换，旧错误仍按原操作归属处理

### Requirement: 错误交付不能增加普通交互的全量检查与等待

错误提取 SHALL 仅使用当次有界载荷、异常及已持有上下文，不要求全库审计、扫描历史、读取完整密钥库或新增常驻连接。普通请求 SHALL 沿用既有完整链路预算：≤512 KiB 暖读 p95≤500ms、单次≤1500ms，三步导航总 p95≤1000ms、单次≤2000ms，可操作 Composer／文件可见≤2000ms，首次未缓存业务读取≤3000ms；原历史更严格预算优先。快速本地失败 SHALL 计时至完整错误结果或真实错误 UI 可见，不以占位或进程 timeout 代替。

#### Scenario: 大历史中的一个失败 Turn
- **WHEN** 用户打开含一条失败 Turn 的大历史小页
- **THEN** 只沿原有界投影读取失败信息，满足原历史页预算，不全量读 Trace 或运行日志补错误
