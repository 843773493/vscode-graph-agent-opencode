## Goals / Non-Goals

**Goals:**

- 同一次工作台启动只有一个显示语言，默认简体中文，内置英文；相同源码同时覆盖 Web 与 Electron。
- 完成实际交付界面的文案提取及语言加载，复用原命令、菜单、设置、内置功能与编辑器，保持业务合同。
- 语言切换通过原显示语言入口保存并重载，沿原存储保护恢复工作状态。

**Non-Goals:**

- 无刷新热切换、全工作台可观察翻译注册表、重建命令／编辑器以更新文案。
- 在线翻译、语言包市场、VSIX／用户 Extension Host、开放自有插件 UI／语言包贡献协议。
- 自动翻译用户与模型内容、Skill／系统提示词、服务原始输出；重做后端错误体系或改变模型回答语言。
- 为移动端及尚未实现的客户端预写 adapter，或把语言同步到 Gateway／工作区配置。

## Decisions

### D1. 客户端语言 owner 与默认值

显示语言属于当前客户端存储域，不属于 Gateway、workspace、Thread 或业务配置。复用原 Web Locale 服务的偏好入口及 `vscode.nls.locale`；bootstrap 与设置动作读写同一键，不另加 IndexedDB、React 状态或 Electron 配置副本。

正式支持值为 `zh-cn` 与 `en`，无偏好固定 `zh-cn`；清除偏好也回到此默认值。入口统一大小写规范化，HTML／Intl 使用等价的 `zh-CN`／`en`。不增加跟随系统／浏览器或 URL 覆盖模式。已存不支持值明确显示可恢复启动错误，提供清除偏好回到中文的具名操作，不静默写回或查询市场。其他窗口不被强制刷新，沿各自下次加载读取同一存储域偏好，不新建跨窗口同步系统。

选择此方案是因为启动前无法依赖完整 Workbench 配置服务，原 Web Locale 偏好已经适合 bootstrap。保留原语言键比另建持久化层简单；不支持值仅需明确处理，不为开发数据追加迁移框架。

### D2. 单一 bootstrap 先于业务模块求值

入口依次完成：读取本地偏好 → 加载同发行版本的当前语言资源 → 设置 NLS、产品翻译入口与 document.lang → 动态导入原 main／工作台入口。静态 import 的传递依赖不得先执行贡献注册；不能仅在 startWorkbench() 中设置全局语言。

加载提示、可恢复启动错误及重试／重置动作使用随入口内置的最小中英文文本，由同一文案源生成；不等待 Gateway，不先显示另一语言的占位后再纠正。错误详情保持原文。选定语言资源缺失、损坏或版本错配时明确失败，不伪装为英文成功。bootstrap 只处理真实资源加载边界，不审计用户数据库或全包 hash。

有用户可见文本的 Worker／Webview 必须在其自身模块求值前取得当前 renderer 的已选语言和对应本地资源；晚创建的实例也保持一致。没有文案的纯计算 Worker 不为“覆盖”增加通信层。Electron 和浏览器 parity 入口同样先经过 bootstrap，禁止旁路静态导入 main。

### D3. 沿上游 NLS 使用翻译数据，不安装翻译插件

上游资源沿 `module_id + nls_key` 匹配中文数据，复用固定版本的调用分析、NLS 表和消息格式化行为。构建记录固定上游源码提交、翻译数据来源提交／版本及摘要；翻译资源作为项目可复现输入保存于有归属的静态资源目录，保留来源与许可，不从 reference_repo 或用户已装 VSIX 读取。正常构建和启动不临时联网下载中文包，更新数据是显式开发操作，不运行包入口。

对源码转换后的有效模块提取文案，包含项目注入的 localize 调用；被项目改变语义的上游 key 改为项目专用 key，不能继续误用旧中文翻译。保留 localize2 的 original 英文以维持原命令面板检索和说明行为；不得翻译稳定 command_id、context key、设置键或资源身份。

项目自有可见文案要求中英文完整且占位符一致；缺项或冲突在构建校验时拒绝。上游新增但翻译数据尚缺的条目沿原 NLS 回退英文，并在构建结果明确列出；核心验收界面中的缺项由项目补译后才能验收，不能借 fallback 宣称“整个页面已中文”。补译和产品术语覆写限定模块／key 归属，不建运行期翻译覆盖规则引擎。

这保留上游的成熟机制，避免复制全部 Workbench 为中文分支，也不恢复已经移除的市场／宿主／扩展安装链。

### D4. 产品文案采用薄共享入口，语言在启动内固定

纯翻译、占位符及格式化入口落在 `src/clients/shared/core/i18n/`，只接已加载的语言和资源，不读取 window、localStorage、VS Code 或 Electron。初始化由 bootstrap 负责；React、状态展示和普通工具函数都消费同一入口。没有热切换需求，因此不添加语言订阅、跨 React 根 Provider、更新广播或新的设置状态机。

项目原文采用英文和稳定语义 key，中文作为翻译；英文 catalog 由唯一原文提取，不再手工维护同内容的第三份词典。产品目录按会话／输入／资源／任务／设置等实际功能分文件，构建统一校验；同一 key 不以英文句子或文件位置的偶然变化充当新身份。复用上游占位格式的必要子集，不新增 ICU 框架；确有单复数差异使用明确的完整句子和 Intl 格式化，避免片段拼接。

Workbench 定制继续使用原 localize/localize2，React 使用纯共享入口；两者共享启动语言和产品文案源，产出各自需要的资源投影，不相互导入应用入口、不维护第二份手写翻译。同一产品文案只在一个语义 owner 定义，不因入口不同重复维护。

### D5. 翻译覆盖按实际交付面盘点

| 展示面 | 必须迁齐的文案 |
|---|---|
| Workbench 外层及项目贡献 | 活动栏／视图名、导航、Tab 标题、命令面板、菜单／快捷键说明、设置名与枚举说明、空态、Tooltip、ARIA／读屏文字 |
| React 会话及资源 | 消息操作／输入栏、模型与工具控件、会话文件／更改、Trace／请求详情、任务／Goal、源码与 Agent 调试、对话框／通知／连接状态 |
| 工作区及 Gateway 管理 | 工作区、连接、插件包管理、终端／浏览器入口和输出面板的产品控件；原服务输出不翻译 |
| 内置编辑功能 | Text／Diff／设置／搜索／Debug 等原 UI 的 NLS；实际保留内置扩展的 package.nls 及运行期 l10n；Markdown／媒体等已交付 Webview 的控件 |
| 格式化及启动 | 日期、数字、时长、相对时间、计数／分页提示、启动失败摘要；界面语言变化不改变时区或底层数值 |

盘点以真实入口和构建依赖为准，不以“中文字符串零命中”验收：测试 fixture、协议、日志、示例、用户内容和 Skill 可以包含中文。删除或替换旧硬编码调用方，不保留旁路中文 UI。英文验收同时检查过去写死中文的所有产品面；英文合法术语、Gateway、Thread 等不通过机械字符规则判错，术语在语言资源中保持一致。

用户消息、模型回复、用户命名、文件、提示词／Skill、命令输出及日志永不因切语言被改写。既有机器错误码有对应产品提示时按码显示本地化摘要，原始详情可查看；未知异常仍显示原始详细错误。不分析中文消息字符串决定类型，不强制后端所有错误先改协议。过去存入展示缓存的派生状态标签改为读取时翻译，业务历史仍按原内容恢复，不清缓存或重写会话数据。

### D6. 内置扩展和资源使用本地供应

在原 LanguagePack 服务接缝只公布中文与 English，原 Quick Pick 不枚举 Gallery 或进入 VSIX 详情。内置扩展清单与运行期 l10n 是独立资源消费面：构建保留原文和相应翻译，在语言明确后由原 scanner／内置资源 loader 读取当前语言，不能只翻译 package.nls 就报告内置扩展全部完成。只覆盖现有内置功能，当前自有插件未开放 UI／编辑器 Provider，本变更不借 i18n 开放这些能力。

Worker／Webview 保留原隔离、资源 URL、安全边界和生命周期，只装配其实际需要的本地翻译；不加入访问外部翻译 CDN 或读取本机路径的能力。原语言发现和内置翻译读取的市场旁路迁齐后删除；与自有插件改造共享的源码转换文件实施前协调，不为汉化引回旧体系。

### D7. 显示语言动作与重载保护

保留原“配置显示语言”命令及原 ID、Quick Pick、当前项标识、取消和重载提示，选项固定为“简体中文”与“English”。选择当前已生效语言无写入／重载；只有选中另一语言才持久化并提示。写入失败保留当前界面、显示错误且不重载。选择后拒绝立即重载时当前语言保持，新偏好在下一次正常加载时生效；不新增 pending 语言账本。清除动作移除偏好并提示返回中文，不再提示跟随浏览器。

确认重载时走原 host 重载／脏工作副本保护，并结清已有会话历史镜像、Composer 草稿、视图状态等待提交展示存储；复用既有提交函数与原 owner，不另建“语言切换快照”。提交失败或用户取消脏文件处理时保留页面和内容，不强制刷新。重载恢复仍遵守原预览／固定 Tab、Grid、编辑器备份及后端同步合同，不新增一份布局或业务状态。

Web 重载当前页面，Electron 重载原 BrowserWindow renderer，不关闭应用或重启 main、Gateway、Backend、MCP／终端／浏览器插件。网络连接按原重载逻辑重新附加，后台业务继续；不承诺恢复已经失效的资源或旧执行句柄。原生宿主向页面呈现的产品错误摘要沿 renderer 当前语言输出，技术详情保留，不建立 Electron 独立 locale 配置或新原生 IPC。系统自身原生错误不属产品翻译范围。

### D8. 开发、构建与缓存一致性

在 build.mjs／sourceTransform 及 Vite transform／预构建链复用同一模块／key 提取与翻译匹配规则，包含实际依赖的 React 产品源码；不能只给生产 bundle 设置语言。若使用数字索引，主包、共享块及相关 Worker 必须使用同批映射，禁止各构建独立编号后混用。生成索引是单次构建产物，不作为跨版本持久合同；已有产物资源身份继续由原静态资产机制管理。

Vite optimizer 的失效输入纳入翻译资源与提取／转换规则版本，语言资源变化触发相应重载，不能要求用户清浏览器数据。源代码修改沿原 HMR；不为保持文案热更新而实现产品无重载换语言。语言资源不固化成 optimizer 构建机器的显示语言。

Web 和 Electron 打包包含两种语言以及内置功能资源；语言加载来自本次产物本地路径，不依赖源码／reference_repo／开发服务器／Gallery／公网。按已有内容地址／构建版本发布 JS 与语言资源，避免旧消息索引对应新翻译；不新建全包完整性或缓存系统。每次启动只加载当前语言及实际使用子功能资源，普通交互为内存查表，不逐条请求翻译、不访问后端、hash 或扫描词典。

### D9. 规范与实施边界、验收成本

用一个新 capability 约束新增语言行为；已有 native-web-workbench／electron-thread-history 继续约束布局、宿主和缓存。本规划不修改其他正在实施的 OpenSpec，不把新的文案提取与热重载要求提前计作已实现；实际代码接线按纵向子链完成后验收。

复用现有正式测试装具，定向合同检查默认／不支持值、占位符、localize2 原文、索引一致性、保存失败和取消；产品场景合并执行中文启动→英文选择／重载→中文恢复，并覆盖多 Thread、草稿、脏文件和内置功能。使用真实 Gateway／Workspace，至少实际请求同源 health／workspaces／workspace；有模型替身的会话操作如实标为 integration，真实 Electron 不由 electron-web 替代。

普通语言选择器从点击到双语选项可操作、已加载页面中的会话和设置等操作从真实入口到完整结果计时，沿现有更严格交互预算；首次冷加载／重载另记完整可操作时点，不能把重载耗时混入普通暖操作或以占位／首个文本作成功。记录规模、样本、p95／max、请求适用的 request_id 和未验范围；无请求的本地选择器标记不适用，不伪造 ID。不新增生产监控、逐调用验证或重复长跑。

## Risks / Trade-offs

- [中文数据与固定上游并非完全对应] → 锁定实际输入并按模块／key 匹配，原文变化重新核翻译；核心可见缺项补译，其他缺项明确披露，不无条件拉取最新语言包。
- [模块静态导入提前求值] → bootstrap 必须成为真正入口；使用首次注册的菜单／设置／命令文本作为反例，不只测翻译 helper。
- [只翻译 React 或扩展清单留下混用] → 按 D5／D6 盘点运行期控件、内置清单、Webview、Tooltip 和 ARIA，双语言验收。
- [重载丢失草稿或影响后台运行] → 复用原存储／脏文件保护，在真实页面核保留内容、目标归属和后端运行身份；失败保持页面，不新增恢复状态机。
- [上游缺项默认英文] → 原 NLS fallback 仅用于真实未翻译条目，项目自有文案双语齐全；资源加载失败不使用 fallback 掩盖。
- [构建抽取与开发预构建规则分裂] → 共用匹配逻辑与资源输入，验证相同 key 在 Vite／Web／Electron 同一解释；不维护第二编译器。

## Migration Plan

1. 在实现前核对当前源码与共享文件写入方，锁定翻译输入，完成原入口、语言旁路和实际可见面盘点。
2. 先闭合启动／NLS／原显示语言选择／重载这一条链，再迁齐产品文案及内置资源；中间切片保持验收范围明确，不保留两套语言选择实现。
3. 实现完成后集中执行定向静态／真实类型、前端构建及最小真实产品验证，发行场景使用按仓库约定递增版本的干净提交；规划阶段不改用户 Home。
4. 本变更不需要业务数据库迁移；已合法保存的 zh-cn／en 使用同一原偏好，未支持值按 D1 明确恢复。代码回退只沿既有发行流程，不自动删除用户存储、改写会话或增加旧格式运行时兼容。
