# 目录用途

存放终端输出的UTF-8字节边界、增量重放与逐连接流控；不管理PTY进程或终端生命周期。

```text
output/
├── terminalUtf8Output.js              尾部缓冲和事件切块的字节边界
├── terminalUtf8Output.test.js         字符完整性、字节上限及有界处理
├── terminalOutputMultiplexer.js       输出重放、ACK窗口和控制消息顺序
├── terminalOutputMultiplexer.test.js  游标、缺口resync、背压和释放
└── terminalOutputMultiplexerEncoding.test.js 多连接编码复用与socket拒收
```

Session决定何时记录PTY正文并产生唯一输出sequence；本目录决定保留哪些字节、各消费者从哪里继续读取及何时可以发送。按数据流中的职责组织，不按模型与UI分两套输出实现。

文本字节边界归 `terminalUtf8Output.js`，输出顺序、游标和背压归 Multiplexer；缓冲截断只能从完整字符开始，保留正文不得因解码替换字符而再次超过上限。无需切块的输出直接形成一个事件。

尾部只保留256KiB，不应编码已经确定会丢弃的整段输入。UTF-8每个UTF-16单元至少占1字节，因此只需编码最后256Ki个单元，再按字节边界对齐；扫描与编码范围由保留上限约束。未超限字符串保持原值，超限时沿用UTF-8编码对孤立代理项的替换语义。

超出64KiB的单次输出按码点宽度累计UTF-8字节，确定边界后从原字符串切片；不逐字符调用编码函数或拼接块正文。码点决定字符宽度，UTF-16偏移决定切片位置，孤立代理项按3字节计费且保留原值，不能把这两种单位混作同一偏移。

输出sequence只有Session逐一递增产生，重放环只从头部淘汰，因此Multiplexer可用序号差加逻辑头偏移定位增量起点，无需从头扫描或维护第二份位置索引。淘汰立即释放正文引用，空前缀达到数组一半后集中压缩，避免大量小输出逐项shift搬移。字节窗口、ACK、控制事件顺序及缺口resync仍由同一Multiplexer处理。

模型增量读取从已定位的后缀直接拼接正文，不为读取再复制事件数组或提取一份正文数组；不缓存拼接结果，不修改重放记录。字节保留上限、游标校验和缺口快照仍归同一读取入口。

客户端未确认队列只记录sequence和字节数，ACK累计确认到指定序号；逻辑头游标推进后同样集中压缩。窗口计费只包含未确认后缀；resync替换整份待确认快照时必须同时归零头游标，防止旧游标跳过新快照的确认。该队列与模型读取的重放缓冲各管自己的消费状态。

Multiplexer的`clientFlowStates`按attach连接保存`TerminalClientFlowState`，不表示终端业务状态。`attachedMessageSent`只确认attached已交给连接，`blockedOn`明确区分ACK窗口与socket拒收；`socketRetryTimer`只重试socket发送。已发送/已确认输出序号、模型读取游标和屏幕实际绘制是不同事实，不能互相替代。

多个连接接收同一输出事件时，Multiplexer只在本次同步广播内复用现有协议owner生成的封包；广播返回即释放这个局部映射，重放记录不额外保留编码正文。后续ACK续传、socket重试和重连仍按各自游标重新编码；没有连接时不编码输出，不另建持久传输缓存或第二套序列化合同。

控制通知只服务当前attach连接；没有连接时直接结束广播，不序列化通知或计算队列字节。它们不进入输出重放缓冲，后续attach读取当时的完整状态；有连接时仍按原输出屏障排序并核控制队列上限，不把这项省计算变成积存旧通知或放宽配额。

## 可修改内容

- 终端正文的字节截断、事件切块、保留缓冲与增量重放。
- 逐连接确认窗口、socket背压、控制消息排序及对应单测。

## 不可修改内容

- 不管理PTY、worker、进程退出或Terminal生命周期。
- 不解释命令标记；命令协议语义由`../../shared/commandText.js`独占。
- 不复制协议编码；统一引用`../../protocol/messages.js`。
- 不写磁盘或维护第二份持久输出、输出序号或业务状态。

## 规范

- 使用ESM，相对导入指向实际owner；移动后物理移除旧模块，不保留转发路径。
- 字节边界与传输窗口各有唯一实现；不把模型消费游标当作UI确认。
- 现有单测由辅助服务runner递归发现，不为新目录复制测试或改变正式产物规则。
