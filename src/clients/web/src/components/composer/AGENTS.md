# 目录用途

`components/composer/` 存放消息输入框及其附件、视图、Agent、工具选择和发送控制组件。

## 支撑树

```text
composer/
├── Composer.tsx              输入、附件、发送与会话动作编排
└── composerTestFixtures.ts   Composer hook 测试共享的浏览器全局环境
```

Composer 专属的 API fake、数据装配和行为断言留在相邻测试文件；共享 fixture 显式加载 fake-indexeddb，为进程内浏览器存储提供真实事务仿真，不依赖其他测试文件的导入顺序。全局 window、存储、浮层构造器、BroadcastChannel 和可控轮询计时器由共享 fixture 安装并按描述符还原。

# 可修改内容

- 可以调整输入框局部交互、工具栏控件、附件展示和工具选择浮层。
- 可以继续拆分只服务于 Composer 的展示组件。

# 不可修改内容

- 不在组件中实现后端工具测试规则或持久化业务。
- 不在这里放置会话历史、文件预览或工作区侧栏组件。

# 规范

- 后端状态通过 `api.ts` 或上层 App 状态访问，失败必须显示给用户。
- Composer 上方的折叠入口承载持续任务（含 Goal 等应用）、排队消息和主 Agent 留言；留言默认折叠，展开才分页加载 Markdown，只能逐条删除，回复经原 Composer 普通消息；行内操作默认使用图标、悬停说明及可访问名称，次要操作收入菜单。任务复用原会话订阅与任务命令，管理入口展开所属会话的任务资源。停止进度反映在原停止按钮；错误不得增加入口、卡片、提示行或自动展开详情。撤回和策略操作在原行标记失败；排序采用乐观展示、后台同步完整快照，冲突或超时重读权威顺序，不显示错误行或 Toast、不盲恢复旧顺序；原始原因经 ComposerDiagnosticsContext 进入工作台已有窗口输出通道。本地提交恢复与后端队列复用各自 owner，合并展示不新增提交存储或 writer。停止回执须核发起作用域，不写入已切换的 Thread。
- 对外附加仅发布原草稿 hook 的临时句柄；引用与正文仍是文本草稿，不经过附件上传、不自动发送，句柄不构成另一份草稿权威状态。
- 浮层需支持键盘关闭、视口边界约束和窄屏操作。
- 产品控件文案复用 `shared/core/i18n` 的稳定 key；Agent、模型、工具名称、用户正文及后端原始详情保留原文。语言由工作台 bootstrap 在模块求值前确定，组件不保存或热切换语言。
