# 目录用途

`src/clients/web/src/tests/` 存放跨越多个 Web 源码子目录的契约守卫测试，例如校验跨客户端共享选择器与真实 DOM 属性保持一致。

## 支撑文件

```text
tests/
├── testGlobals.ts  跨测试目录复用的全局描述符还原与最小 window 计时器桩
└── fixtures/
    └── session/    被多个源目录共同使用的会话测试装具，按依赖拆成独立模块
```

领域专属的 API、组件和 hook 装配仍留在各自源码子目录的测试 fixture 中；被多个源码子目录共同使用的装具按领域放入 `fixtures/`，各用例直接导入所需模块。

# 可修改内容

- 可以新增和维护需要同时读取多个 `src/clients/web/src/` 子目录或仓库级测试资产的一致性测试。
- 可以添加小型文本解析 helper，但应保持用例聚焦。
- 可以放置跨多个测试目录共享的测试支撑 helper（例如浏览器全局桩的还原入口 `testGlobals.ts`），但不得放单个组件的局部断言或流程编排。
- 可以按领域拆分被多个源码子目录共同消费的测试装具。

# 不可修改内容

- 不在这里放单个组件或单个纯函数的局部行为测试，那些测试应与被测源码同目录。
- 不在这里放产品运行时代码。

# 规范

- 一个测试文件只守一条跨目录契约，断言要能指出漂移发生在哪个文件。
- 读取源码或测试资产时使用 `import.meta.url` 相对定位，保持不变更当前工作目录也能运行。
- 保留“模板示例；在整理 `AGENTS.md` 时请保留此行。”这一行。
