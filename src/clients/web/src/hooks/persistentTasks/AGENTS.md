# 目录用途

管理当前工作区及会话关联任务的后端镜像、状态订阅、运行记录与管理动作；Goal 与其他任务共用任务快照及 SSE，目标、预算和原操作回执复用 Goal 专用控制接口。

# 可修改内容

- 工作区切换时撤销请求、SSE 生命周期、revision 管理与失败回读。

# 不可修改内容

- 不新增任务账本、调度器或客户端业务状态权威，不推导执行成功。

# 规范

- 复用现有 Gateway 请求与 SSE 解码；成功使用完整对象，失败保留原错误并读取后端。
- 工作区切换和卸载后丢弃旧响应；旧闭包不能向新目标提交操作。
- 会话动作的观察基线归属精确工作区；按输出首次出现与终态变化触发 UI 策略，不能仅比较运行状态字符串。初次读取历史只建立基线。

运行历史按稳定 task_id 加载有界摘要页，精确运行通知直接替换该条；无关任务更新不得清空或重读历史。会话动作观察直接消费同一 SSE，初始及 gap 只用在途摘要建立基线，隐藏停止消费并在恢复时重新建立基线。

Goal 的会话投影和任务详情共用 `useTaskGoal`；已取得父任务完整 Goal 的详情不另开读取或订阅。会话范围快照必须包含空槽位及清空版本，成功控制消费完整回执，失败回读任务；不增加 Goal 固定轮询，也不从 Trace 第二次写入 Goal 镜像。

空 Goal 详情同样复用父列表的 `session_goal`，包括删除后的版本；不得把空槽位当成缺少快照而新增 SSE。
任务逻辑观察者通过现有 Workspace Observation 聚合传输，不能让各任务入口单独占用物理 SSE，挤占普通 HTTP 请求的连接名额。

Composer 的持续任务列表消费同一会话快照及 changed 事件的完整任务镜像；不得为此再开订阅、轮询或持久化。Goal 仍使用其专有控制接口，普通任务动作交给原任务命令。
