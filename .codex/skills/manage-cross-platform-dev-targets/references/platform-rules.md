# 平台规则

只读取与当前目标或改动相关的章节。目录内更具体的 `AGENTS.md` 仍是实时权威。

## 公共编排

- 维护目标配置 schema、无真实凭据的示例、ESM 编排模块和测试辅助代码。
- 从运行时工作目录或显式项目根目录解析路径。
- 快速失败并输出目标、平台和失败阶段。
- 始终验证 SSH host key。
- 不在跨平台目标工具中实现 Gateway 或工作区后端业务逻辑。
- 整理任何相关 `AGENTS.md` 时保留“模板示例；在整理 `AGENTS.md` 时请保留此行。”

## Linux SSH 目标

- 使用 `set -eu`；把所有路径作为独立参数传入并加引号。
- 支持仓库初始化、快照激活、运行时初始化、服务生命周期和产物收集。
- 不依赖 Docker 专属命令或宿主机仓库挂载。
- 不接受测试代码拼接的任意 shell 程序作为管理动作。
- 删除或覆盖前验证目标是配置声明的精确专用绝对路径。

## Windows OpenSSH 目标

- 使用 PowerShell 严格错误模式和结构化动作参数分派。
- 使用 Windows 路径、`.venv\\Scripts\\python.exe`、ACL 和进程管理方式。
- 不调用 `sh`、`nohup`、`kill` 等 POSIX 命令。
- 不假设 VMware 地址、Windows 用户名或盘符。
- 未经真实 Windows VMware 验证的路径转义、ACL、后台进程和原生模块兼容代码必须带明确 TODO。

## Docker Linux 目标

- 仅让容器提供目标系统与 SSH；统一经 SSH 执行源码同步和服务管理。
- 不挂载当前项目根目录作为容器仓库。
- 不把真实 `.env`、SSH 私钥或 Gateway 凭据写入镜像。
- 为仓库、Home、缓存、SSH 状态和产物使用明确且彼此独立的持久目录。
- 修改镜像、Compose 或入口脚本后，验证已有持久目录不会被隐式覆盖或删除。
