# GPT 分层团队协作

主模型由用户选择。主线程负责用户沟通、范围和必要裁决；协调层负责日常调度与交付。此方案替代 GPT 团队的主线程直管作者和审查者方式，不改变产品验收标准。仅创建或修改技能不授权继续实施历史任务。

## 团队与唯一负责人

| 层级 | 模型与数量 | 职责 |
| --- | --- | --- |
| 主线程 | 用户选择的模型 | 接收新指令、确定范围、裁决真正阻塞；收到可交付摘要后回应用户 |
| 交付协调 child | gpt-6-luna / max，1 名 | 管理唯一核心作者、消费者前置、小修、运行窗口、固定候选及串行集成 |
| 独审协调 child | gpt-6-luna / max，按需 1 名 | 安排独立审查，核调用链和验收证据，将确定 finding 直接交交付协调者 |
| 辅助协调 child | gpt-6-luna / max，按需 1 名 | 管理明确隔离的外围任务、命名核查和小修，避免与核心共享写面 |
| 核心 grandchild | gpt-6.1-sol / max，全队唯一 | 贯穿完整核心场景，迁齐声明、写入、查询、恢复、DTO、调用方和必要测试 |
| 辅助 grandchildren | gpt-6-luna / max | 前移核查核心消费者与测试前提、独审、命名核查、隔离小修及其验证 |

主线程最多直接管理 3 个 child；不直接向 grandchildren 派单、接收日常报告或补写业务实现。全部后代最多 15 个；长期实施时至少保持 3 个有明确授权工作的 Luna，包含协调者。不为凑人数扩展任务；收尾和仅整理技能时按实际需要留人。

只有交付协调者可以创建或续派核心 Sol。其它协调者把核心 finding 直接交它，不另外创建作者。Luna 不承担大型核心改动；隔离小修自行完成相关验证，不移交 Sol 补救。各 child 只能创建 grandchildren，孙层不得继续派生。

切换旧团队前先结束旧写租约和在途运行。代理不能直接改父节点；旧直系 Sol 停写交接后，才由交付 child 创建新的核心 grandchild，不能同时保留两名活跃核心作者。

## 创建、恢复与派单

创建每一级代理时使用当前工具的创建接口，显式传入：

~~~javascript
start_delegated_task({
  task_name,
  model: "gpt-6-luna", // 仅唯一核心 grandchild 改为 "gpt-6.1-sol"
  reasoning_effort: "max",
  fork_turns: "none",
  message,
});
~~~

模型 ID 不带 provider 前缀，不省略、不静默替换。候选列表不能单独证明目标不可用；实际调用失败保留原错误并报告受影响任务。创建记录保留实际 agent ID、父级、角色、模型、effort、状态和写租约；后续派单不能改变原模型。

completed 成员用当前工具的 continue/followup 接口唤醒；send/deliver 仅补充运行中任务。收到 429 直接给原成员续发“继续”，不额外查状态、进程或模型，不重发长派单，不创建替代者。恢复任务只找台账的唯一活跃 agent ID，不唤醒同名旧核心或已撤权成员。

派单只传本任务必需信息：目标与完成标准、真实根目录、固定基线/必要需求入口、完整业务闭包和写租约、运行 profile 与产物路径、验证要求和报告接收者。使用空历史创建；不复制主线程对话、整份状态历史或所有旧审查报告。协调者可直接协调已授权范围内的依赖和返工，只有范围、产品语义或权限确需裁决时上报主线程。

## 协调层怎样减少返工

交付协调者维护当前租约、依赖、验收与下一动作；其它 child 只提交本角色结果，不并发改同一台账。接续本项目时由它按需读取[既有台账](../team-collaboration-gpt/memory/2026/10/10/team-collaboration-state.md)的当前段和准确收据，主线程只接精简摘要。核心公共合同由唯一 owner 决定，消费者随同批完整迁齐；不要让多个作者同时改同一合同。

Sol 持续实现完整场景时，Luna 提前沿实际入口核消费者、SQL 列与 loader、恢复和测试 setup，直接给 Sol 可行动事实。先闭合整批必要改动，再集中静态检查、少量真实核心入口和受影响边界；保留已约定的完整验收。不逐字段交接，也不靠放松身份、顺序、冲突或错误归属断言通过测试。

每轮只有一个重测试和集成负责人。停写窗口按实际源码依赖划定，不能让无依赖的小修等待全部核心工作。作者整批 STOP 后，交付协调者从固定 Git 树导出完整补丁并严格重建，独审针对该固定候选及完整调用链。疑点先追入口、caller 和已有拒绝边界，再要求作者修复；局部 patch 推断不能直接触发回滚。已通过项按真实源码依赖复用，只审新增差异。

Git 权只交给本轮唯一集成者。每个 Git 子进程显式使用绝对私有 GIT_INDEX_FILE 和 GIT_OPTIONAL_LOCKS=0，保留共享暂存；禁 Git 的作者和审查者不建索引。用户已授权的普通提交与 push 可由交付协调者执行，完成后核提交树及远端 SHA；不 force、不改写共享历史。未授权的外部动作仍由主线程处理。

## 路径、运行与证据

默认共用当前真实工作树，不复制整仓或新建临时工作树。确有已有授权的隔离需求时，代码 worktree 只放 `out/worktrees/YYYY/MM/DD/<run_id>/<task>/`。日期按北京时间冻结。

临时运行控制、日志和原件只放 `out/tests/temp/YYYY/MM/DD/<run_id>/<role>/`；隔离业务工作区使用其 `workspace/`，产物使用 `artifacts/`。正式测试沿用 `out/tests/<与 tests 同名路径>/`，不改正式产品入口。禁止 `/tmp` 乱放、项目根目录测试数据、重用历史临时业务工作区；不搬运与开发无关的目录。

协调者分配并准备 profile、产物根及所需运行目录，复用现有 [run_task.py](../team-collaboration-gpt/scripts/run_task.py)：

~~~bash
<ROOT>/.venv/bin/python <ROOT>/.codex/skills/team-collaboration-gpt/scripts/run_task.py \
  --profile <绝对profile> --attempt <唯一名> --seconds <预算> -- <原命令及参数>
~~~

测试和执行性诊断必须带进程外超时、内存保护，原始退出码及输出不可覆盖；有界源码读取不逐次建 attempt。profile 变更另建版本，不切在途输入。协调者用 [verify_run.py](../team-collaboration-gpt/scripts/verify_run.py) 核准确原件，用 [verify_delivery.py](../team-collaboration-gpt/scripts/verify_delivery.py) 核固定交付；机械成功不等于业务通过。详细参数只在实际运行前按需查看脚本帮助或共同流程的运行章节，不默认载入旧 GPT 长技能及完整历史。

## 主线程收到什么，何时等待

孙代理向直属 child 交付，child 之间直接协调 finding、依赖和返工；不要抄送主线程逐条原始报告。主线程只收：

- 已完成的业务里程碑或可提交结果；
- 协调层无法自行消除的阻塞、需要用户裁决的事项；
- 用户询问或约定观察期限到达时的一次精简状态。

单次汇总不超过 8 行：范围/候选，已证行为，必要检查的实际结果，重要未闭项，下一动作，准确原件路径。正文不粘贴日志、长 diff 或完整流水；主按具体疑点再查原件，不重复全部核验。失败与未验证范围必须保留，不能只报绿色结论。

派单后主线程使用等待工具让出执行；新用户指令到达后经对应 child 转交，通常不直接唤醒孙代理。不要用短周期状态轮询、无变化询问或主动展开旧报告制造上下文。阶段确实超出约定观察期限时，先向负责人问一次当前阻塞和下一动作，不能因安静就重派作者。

结束本轮时，交付协调者交提交/远端 SHA、证据入口和未闭事项；主线程给用户简短结果。用户只授权准备技能时，到此结束，不创建下一轮实施团队。

## 用实践调整

协调层只记录会改变下一步的失败原因和修正效果，主线程维护本入口的稳定规则。候选已通过的审查和检查按依赖复用，不为补统计重跑。

“协调层降低主上下文成本”是本次目标，尚未证明总体 token、速度或质量收益。后续以真实返工次数、可用场景交付、主线程展开报告量和可取得的 token 记录比较；无同口径数据不报模型效率倍率。无效流程删除，用户建议先实践，不直接写成更多禁令。
