# GPT 团队协作

主模型由用户选择 GPT 系列；技能不能切换正在运行的主模型。

执行前读取 [共同调度流程](memory/2026/10/04/team-collaboration-workflow.md)。队伍人数、派单、目录、提交和验收只在共同流程维护；模型配置只在本入口维护，不写回 `AGENTS.md`。继续实施或处理报错时，再读取 [实时状态与实测改进](memory/2026/10/04/team-collaboration-state.md)。

创建 subagent 时显式传入：

```javascript
start_delegated_task({
  task_name,
  model: "gpt-6-luna",
  reasoning_effort: "max",
  fork_turns: "none",
  message,
});
```

`task_name` 与 `message` 按共同流程分配，实际工具名以当次 schema 为准。模型 ID **不带 provider 前缀**，不能省略模型，也不能擅自添加 `newapi-local/`。

上述参数已通过只读探针，创建、回复和 `turn_context` 均确认成功，见 [模型探针记录](../../../out/tests/temp/2026/10/03/154301-gpt-model-probe/coordinator/artifacts/model-probe.json)。工具说明中的候选列表不能单独证明某个 ID 不可用；实际创建失败时明确报告原始错误并记录受影响任务，不自动换模型。

复用与中断恢复按共同流程核验；用户变更模型选择时直接修订本入口的唯一配置，运行状态更新共同台账。

## 按实践减少返工

主代理继续负责调用链、依赖、独审与串行集成。分工按实际返工、入口缺陷和合并成本选择：独立纵向业务可由一个实现者贯穿；公共合同由唯一提供者先固定，消费者按依赖顺序跟进。先减少返工，再比较效果，不把某种分工设为所有任务的模板。

当前严重拖慢交付的实测原因与调整（详细证据在实时台账）：

- **交付遗漏。** E02手筛hunk畸形，V02漏Web调用与删除，E01的60c又漏实际生产修改。用[交付校验脚本](scripts/verify_delivery.py)从固定base/target导出标准补丁，严格重建、核blob/hash，并在完成报告前逐路径说明候选外源码和未跟踪文件。补全的c04可重建；D02已发现并修复后缀漏判，新增语言仍核工具扫描边界。机械绿灯不证明业务正确。U03漏异常、组件与SQL ordinal，WVL又沿旧清单漏DTO/helper/tool，造成import阻断与HTTP 422；冻结前从候选实际import、签名及真实入口核完整闭包，包含既有测试调用迁移，不能只比白名单内blob。
- **前置与公共合同失配。** 多树并改、缺模块/签名、错误三方基线让消费者失败，也迫使主代理重建。中央E04旧组合缺已主集成M01/M02，恢复真实前置后才严格通过；旧全union仍会回退新owner。唯一提供者先交完整合同和必要调用闭包，按真实共同祖先及当前主前置合流；共享文件按符号保双方语义，不能选一侧整文件。 合流路径数由当前base/target实际差异重算，已在当前树的同blob改动登记为已包含；不能用旧摘要的数量要求制造no-op或延长调查。U03原25path增量还依赖其基线已有的DTO/mixed-UI字段，按白名单漏出后造成重复等待；从消费者实际使用的合同核完整依赖，必要后端先固定，独立Web收尾不阻塞它。
- **测试入口不真实。** R27直接INSERT关系掩盖生产writer未接线；R31作者live有装配而固定包没有；R46真实HTTP绿但UI仍绕旧writer。验收从用户动作到权威存储核固定组合的真实调用、装配和身份来源。分页覆盖空、前、中、后及续读；删除/fixture迁移核保留CLI、模板和完整caller，不删断言求绿。
- **身份与版本混用。** R45 synthetic Job替source事实、R46把queue事务generation当catalog revision、O03把backend UUID兼作Gateway路由。先确定字段的唯一owner和读写用途，按真实identity/hash/lineage及事务边界验收。E01A的Turn、Job、admission key独立，queued恢复复用；internal不造Turn，不另建平行账本。
- **生命周期入口漏项。** R34/R41漏真实启动与合理拒绝后的journal收敛，R44漏drain后新mutation，R47漏GET恢复claim/对账副作用且copy同时持多gate，R49又漏新异常到HTTP映射。沿实际副作用、冻结锁合同和提交/await边界审查，核请求拒绝、崩溃重启和并发新增；HTTP动词、稳定排序或直接helper测试都不能代替入口证据。原作者补小forward、另一作者只审新增差异。
- **路径和运行归属错误。** 默认cwd、陈旧index、相对编辑误投主树、worktree/out产物错根已重复发生；L02还从其它源码树启动Python。派单给字面绝对workdir/index/artifact/report，shell全程固定独立index，编辑逐文件绝对目标；实际核Git根/分支、子进程cwd/代码来源、业务工作区和生命周期handle。先保独有源再纠正，不重新复制整树：R53、O03和WVL又生成约217–231MB可复现源码副本，已保固定改动与报告后删除；对象审查用Git tree，构建用现有完整代码worktree。`git -C`进入普通artifact子目录仍会发现祖先仓库，不能在那里把`git apply`当作隔离重建。WVL作者误将自产限制当用户指示而停工；暂停或缩范围前核消息来源，摘要和自我推断不能撤销已有授权。独立index只隔离暂存，固定检索显式tree或`--cached`，首次shell也固定index环境。
- **审查与修补本身增加成本。** A29误判合法thread解析，A31为lint改await引入取消窗口；T05按重复断言文字修错相邻测试，静态绿但原失败仍红。先核规范、实际输入和具名入口；小修限定函数上下文并核postimage，定向复验原失败与受影响场景，不能全局替换重复断言。无契约依据的收紧不采纳；减少代码不能删必要功能。

比较分工时，在现有台账记录每条切片的首次交付可重建性、入口缺陷、返工轮次、等待公共合同和主代理合并修补量。用户建议是待验证选项；按相近范围的实际结果选择、替换分工，没有可比证据时继续局部试验，不宣布某种分工最优。原作者负责该纵向切片的必要消费者与 fixture；同一闭包中新显露的 caller、参数和回归测试沿已有授权推进，除真实跨 owner 冲突外不逐次等待范围确认。agent 名称不决定代码归属，主代理核真实写入范围后一次授权闭包，避免例行参数迁移反复转交和等待。交付工具只检查完整性，不能证明业务合同正确；deferred 只声明真实候选外源码差异，缺少消费者依赖另列精确路径与符号，不能造差异满足工具，也不能用目录前缀吞掉遗漏。

E01A 真实消息入口缺独立 admission key，checkpoint 从 message 派生会违反合同；在现有 Job 派发 producer 分配并显式传递，queued 恢复复用，不为补 key 增设平行账本或未经要求的 active Job 恢复。提供者的已完成独立合同先固定，其余消费者迁移另交，避免新发现持续拖住整包。此调整尚待真实入口验证。

已通过的检查按候选 tree、路径与依赖保留；后续只审新增差异和受影响入口。依赖变化才重验受影响项，不为补日志复跑绿灯。原始验证按候选与尝试分别保存，重试不能覆盖失败 stdout/stderr/exit；O02a/O02b及R47已重复覆盖首跑日志，缺失项如实标记；attempt目录在运行前确定，禁止重跑复用原输出名。具体证据、调整效果和下一轮边界维护在日期目录的实时台账；未实测的机械化步骤不能记作成功。
