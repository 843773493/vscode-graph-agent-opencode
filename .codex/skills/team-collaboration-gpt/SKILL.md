# GPT 团队协作

主模型由用户选择 GPT 系列；技能不能切换正在运行的主模型。

执行前读取 [共同调度流程](memory/2026/10/04/team-collaboration-workflow.md)。队伍人数、派单、目录、提交和验收只在共同流程维护；模型配置只在本入口维护，不写回 `AGENTS.md`。继续实施或处理报错时，再读取 [实时状态与实测改进](memory/2026/10/04/team-collaboration-state.md)。

创建 subagent 时显式传入：

```javascript
start_delegated_task({
  task_name,
  model: "gpt-6-luna",
  reasoning_effort: "max",
  fork_turns: "none",
  message,
});
```

`task_name` 与 `message` 按共同流程分配，实际工具名以当次 schema 为准。模型 ID **不带 provider 前缀**，不能省略模型，也不能擅自添加 `newapi-local/`。

上述参数已通过只读探针，创建、回复和 `turn_context` 均确认成功，见 [模型探针记录](../../../out/tests/temp/2026/10/03/154301-gpt-model-probe/coordinator/artifacts/model-probe.json)。工具说明中的候选列表不能单独证明某个 ID 不可用；实际创建失败时明确报告原始错误并记录受影响任务，不自动换模型。

复用与中断恢复按共同流程核验；用户变更模型选择时直接修订本入口的唯一配置，运行状态更新共同台账。

## 按实践减少返工

主代理继续负责调用链、依赖、独审与串行集成。分工按实际返工、入口缺陷和合并成本选择：独立纵向业务可由一个实现者贯穿；公共合同由唯一提供者先固定，消费者按依赖顺序跟进。先减少返工，再比较效果，不把某种分工设为所有任务的模板。

当前严重拖慢交付的实测原因与调整：

- E02 手筛 patch hunk，补丁畸形且漏核心签名；V02 固定包漏 Web caller 和删除。用 [交付校验脚本](scripts/verify_delivery.py) 从固定 Git base/target tree 导出、严格重建、核对 blob/hash，并列出候选外源码与未跟踪文件；通过后才交消费者。D02 独审实测发现后缀表漏 `.proto/.ps1/.cjs`，已修并定向验证；新增语言需核扫描边界，不能只看工具绿灯。
- 公共 owner 合同多树并改，消费树缺生产模块或使用错误三方基线，造成 collection 失败与接口回退。L02b 又因准入只验 import、漏 registry DTO/runtime 签名产生 19 项失败。派单登记完整依赖树和提供者；同步用真实共同祖先，准入核消费者实际使用的签名与入口。提供者先交完整调用闭包，历史台账清扫不阻塞它，不要求主代理反复人工重建残包。R36 又揭 full-copy 的 staging override 拒绝 thread 参数、clone 元数据写错 owner pair；签名/AST 绿灯之外，需走真实高层入口及不同源/目标 owner 验收；必填 owner 迁移集中核 DDL 对应的生产 INSERT/UPDATE 与调用点，避免逐条漏列才返工。
- R27 测试直接写 execution/membership 关系，绿灯掩盖生产 writer 未接线；R31 又发现作者运行态已装配 mixin，但固定增量的依赖树没有该 wiring。验收先核固定组合的装配与实际代码来源，再提供真实生产写入到读取/DTO 的证据；reader 算法测试不能代替入口闭包。U03c 新增 around 测试仍漏“internal 全在 Turn 窗口前”的分布，独审真实读取揭两 lane 上界混用；分页取空、前、中、后分布与续读证据，不能只验一个有交集窗口。
- R33 的 E04b 固定包完整、137 项通过，仍漏五个测试对已删除静态会话的消费及两处在用导入；R42 又发现保留的真实 Provider fixture CLI 依赖已删除的静态 Session。删除后的核查包含模板、准备入口和保留的运行命令，从空目录核真实消费者；零引用与主要测试绿灯不能证明调用闭包。R32 又定位真实 thread 的 ToolSet intent 被旧 `main` gate 拒绝；身份迁移同时核 producer、consumer 和持久键，不保别名映射。
- R34/R35 在完整队列交付后发现：生产 lifespan 未主动恢复队列、删除逻辑提交晚于不可逆标记、IDB insert 与失败回滚交错留下孤儿。验收沿真实启动、事务提交和异步等待边界设计故障点；直接调用恢复 helper 或单事务测试不能代替这些入口。R37 forward 又漏共享 flush 的命令结果归因及 reload 与跨标签页新增交错；异步共享任务的结果必须归到真实命令，磁盘合并还需覆盖本地新增与远端广播。原作者修增量、另一作者交叉审查；通过前不把这一分工记为成功。 R41 再揭 pre-mark 拒绝留下 preparing journal，重启恢复与 rejected operation 冲突；故障注入还要核请求合理拒绝后的持久状态能否让下一次真实启动完成，不能只测已提交与成功路径。
- R28 Terminal helper 使用 UUID 通过测试，真实 Gateway launcher 却仍传控制面 `gw_*`，导致托管启动失败。L02b 真实启动进一步发现 health 漏 UUID、继承 Python 配置指向另一源码树。身份迁移核实际创建、启动、接管和请求链，并核子进程 cwd、代码来源与真实健康字段；控制面注册 ID 与业务 UUID 分属不同 owner，不以放宽校验或另读业务存储消解冲突。 O03b 接真实 UI 时提前发现 outbox 用同一 workspace ID 兼任 backend 分区身份与 Gateway 路由，已分原 driver 作者修必填路由参数；消费者准入需核身份来源与实际传输用途，不能以端口拼造稳定身份。
- E02 Git 多句命令漏索引变量，恢复默认 cwd 又误读别树；E05 恢复误读主树/旧任务树，声称15文件未应用，中央核正确共享树全部匹配，避免了一次重复合并。产物名和 agent 名混淆重复建根，主代理也曾给错 E04 短名。O03b 的 shell cwd 正确，相对编辑补丁仍写到主树；命令 cwd 不控制编辑工具的默认根。派单核 Git 路径和分支，编辑逐文件使用绝对 worktree 目标，编辑后用任务索引核实际差异；shell 整次环境固定独立索引和产物根。失败先保全、按真实归属纠正，不重新复制源码。
- A29 把可选 thread 输入误判为双轨，规范复核后撤回；R30 才证实 main 按钮别名与 child 调试进程排空遗漏。审查先核原规范及真实入口，区分高层唯一解析与底层第二 writer，避免无依据收紧合法 API。
- A31 发现主代理为消除 lint 把测试 `Popen` 改成 `to_thread`，引入取消后未登记进程的窗口；已恢复同步创建和登记。静态修复涉及 await、异常或资源获取时，按行为差异复核，不能仅记为格式整理。

比较分工时，在现有台账记录每条切片的首次交付可重建性、入口缺陷、返工轮次、等待公共合同和主代理合并修补量。用户建议是待验证选项；按相近范围的实际结果选择、替换分工，没有可比证据时继续局部试验，不宣布某种分工最优。交付工具只检查完整性，不能证明业务合同正确；deferred 只声明真实候选外源码差异，缺少消费者依赖另列精确路径与符号，不能造差异满足工具，也不能用目录前缀吞掉遗漏。

E01A 真实消息入口缺独立 admission key，checkpoint 从 message 派生会违反合同；在现有 Job 派发 producer 分配并显式传递，queued 恢复复用，不为补 key 增设平行账本或未经要求的 active Job 恢复。提供者的已完成独立合同先固定，其余消费者迁移另交，避免新发现持续拖住整包。此调整尚待真实入口验证。

已通过的检查按候选 tree、路径与依赖保留；后续只审新增差异和受影响入口。依赖变化才重验受影响项，不为补日志复跑绿灯。原始验证按候选与尝试分别保存，重试不能覆盖失败 stdout/stderr/exit；O02a/O02b 已发生覆盖，缺失项如实标记。具体证据、调整效果和下一轮边界维护在日期目录的实时台账；未实测的机械化步骤不能记作成功。
