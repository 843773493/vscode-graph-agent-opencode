# 目录用途

存放生产组件之间的协作、协议与故障边界测试；依赖可以是真实服务，也可以是明确的外部替身。

## 可修改内容

- 真实工作区后端、Gateway、客户端与本地协议桩之间的集成测试。
- 集成测试专用 fixture、断言和服务替身。

## 不可修改内容

- 单模块、进程内测试；这类测试放在 `tests/unit/`。
- 新增的、由用户明确说明的完整业务流程验收；这类测试放在 `tests/e2e/`。现有归属不明确的测试先保留，不批量迁移。
- 生产代码和 `asset/` 模板。

## 规范

- 测试必须至少跨越两个真实生产模块，或通过真实 HTTP 进程验证一个生产边界。
- 替身只能替换明确的外部服务边界，不得伪造被测生产模块本身。
- 目录由验证目标决定，不由模型真假决定；完整业务流程 E2E 也可使用上游重放或手工 SSE，不为切换参数复制测试。
- Integration 与 E2E 复用 `tests/harness/`、`tests/support/` 中的 fixture、transport 和驱动。明确记录外部替身及真实运行面，不把模拟宿主或 Web parity 当成原生平台证据。
- 正式产物写入 `out/tests/integration/`，路径镜像本目录下的测试文件。
- 每个测试文件使用独立工作区、端口和服务生命周期。
