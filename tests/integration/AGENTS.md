# 目录用途

存放跨越多个真实生产模块、但使用受控外部服务替身的集成测试。

## 可修改内容

- 真实工作区后端、Gateway、客户端与本地协议桩之间的集成测试。
- 集成测试专用 fixture、断言和服务替身。

## 不可修改内容

- 单模块、进程内测试；这类测试放在 `tests/unit/`。
- 没有服务替身的完整产品链路；这类测试放在 `tests/e2e/`。
- 生产代码和 `asset/` 模板。

## 规范

- 测试必须至少跨越两个真实生产模块，或通过真实 HTTP 进程验证一个生产边界。
- 替身只能替换明确的外部服务边界，不得伪造被测生产模块本身。
- 只要关键链路使用 stub、fake、mock、固定响应、替代服务、`page.route().fulfill()`、模拟宿主或替代运行面，测试必须归入本目录。
- 正式产物写入 `out/tests/integration/`，路径镜像本目录下的测试文件。
- 每个测试文件使用独立工作区、端口和服务生命周期。
