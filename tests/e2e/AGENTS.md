# 目录用途

本目录承载用户主动说明的完整业务流程验收，包括客户端、工作区系统和辅助服务流程。新增用例写明公开入口、业务步骤和最终结果；现有归属不明确的测试暂留原位。

## 可修改内容

- 端到端测试用例
- 各分面的 E2E 测试用例
- 与 E2E 测试直接相关的根级 fixture、标记与配置

## 不可修改内容

- 生产代码实现
- 其他测试目录的公共约定，除非明确需要同步调整
- 与 e2e 无关的脚本化调试代码
- 不得伪造被验收产品的状态或结果；模型边界允许显式选择真实调用、上游录制重放或手工 SSE。

## 规范

- 优先使用 pytest 风格组织测试
- 模型模式不改变文件归属及 E2E 标记；真实调用可录制，重放或手工 SSE 复用仓库已有 HTTP transport 回放入口，不另起服务或复制测试主体。产物保留实际模式、响应资产来源及被替换边界，回放结果不代表真实 Provider 可用。
- E2E 不允许静默切换已选择的依赖模式；缺少当前模式的模型凭据、回放资产、客户端或服务时，必须失败、跳过或明确报告 `UNMET_PREREQUISITE`。
- 当前唯一实现的客户端 E2E 是 `clients/web/`；Electron、VS Code 和 React Native 客户端测试仍为 TODO
- 与 Integration 共用 `tests/harness/` 和 `tests/support/` 的工作区、进程、模型流、等待及清理设施；只保留场景必需的局部 fixture，避免两层各造一套。
- 测试命名应清晰表达场景与预期结果
- e2e 测试重构目标：每个测试文件内部测试默认串行执行，不同 e2e 测试文件允许并发执行
- e2e 测试文件应优先使用文件级 pytest fixture 生成独立的服务、工作区参数、配置与 client，避免共享可变状态
- e2e 测试中的共享状态应尽量限制在文件内；不要依赖跨文件共享的全局单例状态来完成测试编排
- fixture 作用域应优先采用 file/module/function 级别按需隔离，避免 session 级共享可变状态污染并发测试
- e2e 测试目标：每个 e2e 测试文件独立启动一个后端进程，客户端通过真实 HTTP 端口访问该进程，不再依赖进程内 ASGITransport 直连 app
- 通用模块级后端的 model-stream 录制位于该测试文件 `runs/<run-id>/artifacts/model-stream/`，由本次模块运行共享，不归首个用例或参数变体独占；独立用例自行持有的 transport 仍使用其节点产物目录。
- e2e 后端端口应使用一段固定且连续的端口范围进行分配，优先选择不常用的本地测试端口段，避免与常见开发端口冲突
- 后端启动前先检查端口；只能通过本用例持有的进程句柄回收旧进程，未知监听者占用端口时明确失败。退出时释放所有已持有进程，不按端口杀进程。
- 真实模型调用使用实际配置的 API key；上游重放和手工 SSE 不要求真实模型密钥。产品自身的 Gateway／Workspace 鉴权仍按实际链路验证，不得随模型模式省略。
- 测试统一使用 pytest fixture 进行依赖注入；应用代码统一使用 FastAPI Depends 进行依赖注入
- 每个测试必须隔离 `BOXTEAM_HOME`、Gateway 状态目录和工作区目录。
- 正式 E2E 测试的输出目录必须镜像测试文件路径：`tests/e2e/<path>/test_name.py` 写入 `out/tests/e2e/<path>/test_name/`，工作区放在其 `workspace/` 子目录，可复查证据放在 `artifacts/` 子目录。
- `out/tests/temp/YYYY/MM/DD/<task_name>/` 只用于 Codex/Agent 在正式测试脚本之外创建的一次性诊断和临时操作，不得作为正式 E2E fixture 的输出目录。
- 需要工作区配置时，先复制测试工作区，再创建 `.boxteam/`，最后把测试配置及 schema 复制进去；不得修改 `asset/` 模板或把项目根目录注册为工作区。
- Gateway 持久化测试必须覆盖进程重启后的恢复；验证注册表重连时，应移除仅用于首次声明目标的配置，避免测试实际上依赖启动配置重新创建目标。
- 会话存储断言必须通过 session manifest 或正式路径解析 API 找到物理会话节点，禁止继续假设 `.boxteam/sessions/{session_id}/` 固定路径。
- 会话目录 E2E 必须覆盖稳定 ID、SQLite-only folder、嵌套导航、移动、显示名更新、删除和物理 Session 被手工挪走后的访问拒绝；导航改动不得移动 Session 目录或改写不可变 manifest。只对仍有生产 owner 的显式迁移验证对应输入，不保留已下线的物理 folder 布局迁移测试。
