# 目录用途

`app/services/infrastructure/node_debug/breakpoint/` 承载 Node Debug 断点领域的基础设施实现：断点源摘要与锚定、断点条件/logpoint 表达式、断点增删改 mutation 以及断点源码一致性核对。

# 可修改内容

- 可以维护断点 DTO 与运行态之间的映射、条件表达式编译、logpoint 输出解析和源码漂移核对。
- 可以维护本子包内模块之间的导入路径和实现细节。

# 不可修改内容

- 不得实现 API 路由、Agent 编排或会话/进程生命周期决策。
- 不得保留旧顶层模块路径、re-export wrapper 或兼容导入别名。
- 不得静默吞掉源码读取、表达式编译或一致性核对错误，也不得返回虚假的断点默认值。

# 规范

- 文件按单一断点职责命名，只依赖断点领域自身模块与上层 schema。
- 需要跨子包能力（运行态、会话状态）时通过明确的绝对模块路径导入，不反向依赖 `service.py`。
- 失败必须直接抛出详细错误；修改本目录后运行 `uv run ruff check` 和对应 Node Debug 专项测试。
- 代码注释使用中文，公开行为变更必须同步更新调用方和测试，不得建立双轨实现。
