# 前端状态管理：后端权威与本地投影

后端是业务事实的唯一权威来源。工作区后端管理会话、消息和 Job，Gateway 管理连接与工作区导航；前端保存权威状态的镜像、待确认意图的展示投影和本地展示态。浏览器通过同源 `/api` 访问 Gateway，由 Gateway 路由工作区业务请求。

本文落实 `add-itemized-rollout-context` 的 Requirement「集合型 mutation 遵循统一的乐观收敛判据」；业务约束及验收场景以[该 requirement](../../openspec/changes/add-itemized-rollout-context/specs/itemized-rollout-context/spec.md#requirement-集合型-mutation-遵循统一的乐观收敛判据)为唯一规范，不在此另立协议或重复状态、阈值取值。四类判据来自[design 9.2.1](../../openspec/changes/add-itemized-rollout-context/design.md#921-操作性质决定收敛策略判据)。

## 对象级替换与集合级重取

先判断操作影响的状态，再选择收敛方式。重命名若只改对象字段，按对象替换；若同时改变集合的排序或成员位置，按集合变化处理。

| 操作性质 | 收敛方式 | 例子 |
| --- | --- | --- |
| 改对象字段 | 用后端返回的完整对象替换对应镜像对象，其余成员和顺序保持 | 切换 Agent、修改 provider |
| 改集合成员且破坏性 | 本地收敛投影、异步确认及权威校验兜底 | 删除会话、删除文件夹 |
| 改集合成员且可逆 | 本地收敛投影及异步确认 | 新建、移动、改变集合位置的重命名 |
| 只读观察 | 按目标精确读取 | 打开列表、展开目录 |

对象字段更新成功时直接消费完整返回值，不因更新一个对象重拉整个集合。集合成员变化成功时按对应操作收敛投影，不全量重取会话列表或整棵目录树。基线 revision 冲突、跨端并发写入或本地投影不可信时，才显式重读权威状态；校验和错误必须可见。

## 权威镜像与待确认意图

权威镜像只接受已提交的后端结果。本地投影由已提交快照和有序意图重放计算，不能直接修改权威镜像，也不能作为已提交业务事实写入模型上下文、历史或持久化业务链路。

请求受理与实际完成按 Requirement「会话目录编辑必须支持乐观投影、持久入队和失败回退」区分。稳定操作身份、依赖顺序、幂等、查询、事件及失败收敛均引用[该规范](../../openspec/changes/add-itemized-rollout-context/specs/itemized-rollout-context/spec.md)，不新增另一套同步写通道。收到受理回执后仍展示待完成；只有权威终态才能展示完成。

网络超时或响应丢失不能证明操作未执行。先查询原操作并与权威状态对账，不能直接回滚或以新身份重复提交。业务失败后重新读取受影响的权威状态，重放仍独立的意图，按既有依赖合同终结受影响的后续意图；不得用默认空状态隐藏异常。

## 不同资源的归属

- 主窗口的左侧侧边栏承载 Gateway 连接与工作区导航；其权威 owner 是 Gateway 控制面。
- 主窗口的底部面板承载当前工作区的终端、输出、端口和自动化，随工作区切换。
- 主窗口的右侧侧边栏承载当前会话的文件、更改和资源，不能混入 Gateway 全局状态。
- 文件树只替换受影响目录并精确失效子树，外部变更经权威事件增量收敛；是否引入异步受理由既有量化前置决定。详见 Requirement「文件树必须精确失效与权威收敛，Gateway 导航必须接入同一意图协议」，不得为了形式统一增加另一套机制。

## 展示态

面板展开、输入草稿、焦点和请求等待状态可由前端管理。后端业务状态的本地展示不能伪造成功，事件、迟到响应或旧分页结果也不能覆盖更新的权威基线。数据与错误处理始终绑定原目标工作区及资源，切换工作区后不得把在途结果应用到新目标。
